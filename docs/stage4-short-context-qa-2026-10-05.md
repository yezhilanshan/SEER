# 短上下文QA固定预算与L1匹配对照

用户明确批准上一条方案的下一轮范围：有限拟合/开发失败分析、单事件与2/4事件QA适配层500次追加更新、匹配L1压缩评价。训练对象仍仅为独立QA适配层；原前端、EventFormer、P、LLM/LoRA和压缩器全冻结。不会在本轮自动训练压缩器、加预算或启动在线回放。

复用295个已核验TRAINsubject02/sensor14xx事件，set000/001拟合，set002开发。单事件任务沿用前轮相同配对和问题。2/4事件组在同一录制内按时间构造互不重叠完整组，余数明确记录，不跨录制、不跨cohort、不读提问时点后的事件。问答只描述输入事件组：first/last、同题正反存在性，4事件另有完整顺序。正例问询组内实际动作，负组在同cohort/同长度内优先含混淆动作且不含问询动作；一组一个配对，选取动作位置按组索引轮转。活动标签仅生成监督答案，不进入实际记忆token；固定14类候选名称对所有识别问题相同。

先用旧500步适配层评价全部单事件拟合任务和全部开发任务，记录逐类拟合/开发差异；不据开发结果改训练配置。继续旧权重但重置AdamW，lr0.0003、weight_decay0.01、clip1、AMPscale256、seed42。严格250单事件、125双事件、125四事件更新（1/2/1/4循环）；各桶独立类别和任务计数器防止奇偶遗漏。每步同题Yes/No各一条，第三条单事件identify、双事件first/last交替、四事件first/last/sequence轮转；三个答案CE平均。总500实际AdamW更新，适配层累计1000训练步。100/250/500保存，仅报告最后500，无开发集checkpoint择优。

前后原token开发QA、无记忆对照、配对交换证据分别保存真实greedy生成。生成单答案24token、四事件完整顺序64token，不靠teacher-forcedCE宣布成功。结束后同一24个开发四事件组、同一问题、同一QA适配层/LLM，比较32原token与4个冻结L1摘要token。摘要只由相同四事件及时间生成，使用前轮固定压缩器，记录源组SHA/预测/摘要源键余弦和配对正确变化。该差异同时可能包含压缩信息损失与适配层对摘要分布不适应，不能直接归因于信息消失。

开发推进目标：2事件、4事件各自presence balanced≥80%、pair both≥70%、first和last各≥80%；单事件macro recall比同任务训练前降幅≤0.03。四事件完整sequence准确率单独报告，不修改目标答案以合并/去重。未达到时停止配置，不增加训练。缓存、旧适配层和压缩器SHA保护，上游完整权重/原token/key不变；检查点实际步数和推理导出读回。原始预测与日志全部保留，单受试者且共享事件组的TRAIN开发任务不视为独立样本或正式Go。
