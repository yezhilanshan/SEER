# v2.6 方案与现有代码对照及改造建议

日期：2026-10-14。依据：`计划/方案书v2.6.md`、本机源码、历史实验报告，以及本轮服务器只读检查。本报告是改造建议；本轮没有修改模型代码、执行训练或重跑历史指标。

## 结论

建议新增 `src/continuous_mmwave/v26/`，复用已训练的因果雷达编码器、EventFormer、语义投影和记忆接口，重写事件决策和训练主循环。保持旧在线链与 `v25/` 原样，用于对照和回退。

v2.6 的关键是：每次更新比较 Keep/Birth 的因果预测似然，选择继续或重置；重置改变后续事件状态，后续运动预测损失经过该选择训练 Reset Policy。仅在旧 Verify 后添加预测头，或仅用预测误差生成边界标签，都没有实现这个核心机制。

第一阶段应交付连续数据/时间审计与预测价值对照。Event State 对预测没有额外收益时，先查表示与任务，不启动大规模 Reset 或语言记忆联合训练。

## 4. 需要先解决的三个数据问题

### 4.1 类别标签不是实例边界

当前 NPZ/读取契约提供 labels/timestamps，没有独立的实例序列字段。`clean_runs` 和 `recording_intervals` 会合并连续相同标签；`visible_pair_label` 直接把同类别记为负例。因此旧语义候选标签不能直接变成新 Reset 监督。

建议新增事件 sidecar，保留 `recording_id, instance_id, start, end, class_id(optional), caption(optional), boundary_source, boundary_valid, caption_valid`。同类动作重复必须有不同实例 ID。未知区间应有 annotation mask，不能默认为“没有边界”。

如果当前只有命令日志，先用它做明确标注为命令边界代理的 pilot，并人工核查代表性转折、同类重复、渐变片段。没有真实实例 GT 时，不能验收方案要求的语义实例分割或重复实例能力。

### 4.2 更新开始、数据到达与确认时间是三个时刻

已有 v25 调用使用 `timestamps[i,0]` 标记 update 开始，这是可复用部分；但 F_t 含两帧数据，只有收齐后才能计算。建议保存半开区间 `[update_start, update_end)` 与 `available_at`，Reset 的边界候选记在 start，在线输出延迟按实际到达/确认时间计算。

禁止在更新起点声称已使用这批所有帧得出决策。当前 0.09 s 时间基来自数据转换；实际采样时钟仍需审计，不靠重新标记成 0.2 s 消除问题。

### 4.3 数据划分与旧权重的训练暴露必须一起审计

`v25/data.py` 的旧 fit/dev/session/subject 角色与 `configs/parrad-expanded-split-20261011-v1.json` 的新 9/3/3 划分不同，不能拼接使用。例如 subject12 在旧 v25 可作 subject holdout，在新划分中是 validation。

建议为 v2.6 固定独立 recording manifest 与训练/标定/评估角色，核对前端 checkpoint 的训练受试者。已有 17/18 在 RD 实验中被评估过，06 更是历史已观察测试；可沿用冻结测试协议作新方法比较，但应声明历史暴露，不称完全未接触数据。按 session/subject 分组，并避免两个同步雷达或重叠窗口跨角色。

## 5. 建议新增的最小代码结构

```text
src/continuous_mmwave/v26/
  data.py          连续 recording、实例标签、缺失/未知 mask
  targets.py       冻结目标、未来 horizon、时间与来源元数据
  models.py        Event pooling、Keep Dynamics、Birth Prior、Hazard
  state.py         E、prev_motion、历史、age、watermark、事件版本
  losses.py        prediction、cover/dup/off、count、semantic preserve
  rollout.py       oracle/scheduled/closed-loop + ST + TBPTT
  controller.py    KEEP/DEFER/RESET 与 Presence/Idle
  boundary.py      q 轨迹精修；后续扩展因果解释成本
  runtime.py       编码一次、每 update 推断、到达时间
  pipeline.py      Commit/Memory 适配与回放修正
  evaluate.py      预测、事件、重复实例、延迟与退化诊断
  checkpoint.py    v26 权重、目标/数据/代码/config SHA
  runner.py        各阶段独立入口
```

这是职责建议，不要求第一步创建全部文件。首先实现 data/targets/models 与只读预测评估，随后增加 rollout/controller，最后接 pipeline。

训练与推理共享预测和状态更新函数，训练不调用带 `inference_mode` 的在线控制器。Presence 没有可靠标签时，区分“传感器数据无效”与“确认无人”；不能用低信噪或静止直接推断无人。

| P1B（可选） | 单独解冻 Event Update Gate/Cross-Attention/少量 LoRA，加语义保持 | 对照仅解冻这一变量，保护旧检索/Reader | 恢复冻结表示 |
| P2 / Stage2 | 事件内训练 Keep，开始帧训练 Birth；Hazard 与事件级 cover/dup/off 初始化；scheduled sampling | 等 age/等输入的似然标定；自主闭环边界与重复实例检查 | 修监督/概率尺度 |
| P3 / Stage3 | 冻结 Predictor 参数，硬前向 ST，真实连续 3–8 s TBPTT；pred+count+weak-bnd+sem | Reset 改变后续状态与 loss；梯度测试；事件 F1/FP/min；预测梯度切断消融 | 不宣称核心机制成立 |
| P4 | 单状态在线先行；固定 max_defer，必要时 K≤2；边界精修与 atomic swap | 模拟延迟到达/缺失/缓存不足/旧任务过期；实测 P95 与队列增长 | 降级并标记修正失败 |
| P5 / Stage4–5 | 冻结事件机制，接 Commit Teacher、Caption、L0/L1/L2、LLM | 先单事件雷达读出，再顺序/时间问答，再固定 token budget 压缩 | 保留 L0，暂停压缩 |

参数冻结不等于切断计算图：P3 Predictor 和 EventFormer 可以 `requires_grad_(False)`，但对 E 和 Reset 的前向必须保留 autograd。只允许在 TBPTT 块边界 detach E；未来 target、Teacher 与纯缓存可以 detach。若整个 Predictor 放进 `no_grad()`，Reset 就收不到预测梯度。

训练需要同时计算 Keep/Reset 更新或等价可微选择；确定性推理只执行选中一次 EventFormer 前向。两者计算成本不同，不能拿单状态推理显存估计双路径 TBPTT 训练预算。

## 7. 因果顺序和必要验证

单 update 的顺序应固定为：

1. 在 F_t 到达前，用 E_(t-1)、m_(t-1)、过去历史准备 Keep/Birth 分布。
2. 收齐当前 update，计算冻结 m_t，在同一观测上评分两个分布。
3. Hazard 使用真实事件 age 和历史；按可靠度/mask 控制是否允许 Reset。
4. 决定继续/重置，再用 F_t 更新 E_t。Birth 不能先读取 F_t 再重构 F_t 作为自己的高似然。
5. E_t 预测未来 m_(t+h)；训练的未来数据只在 loss target 中出现。

建议验证：改变未来帧不改变此前预测/决策；未来 target 无梯度；TBPTT 内 pred→Reset 非零梯度，切断臂只有该路径被禁用；硬前向始终只代表一个事件；跨同类实例正确保留边界；未知/丢帧不反复重置；超时 DEFER 可终止；回放从基础事件状态开始并恢复完整预测状态，而非只换 E；过期异步任务不能覆盖新事件。

更换/精修 E 后，要同时校正 age、prev_motion、预测上下文与版本/水位。旧 Reconciliation 主要重建 EventFormer/prototype，新方案还涉及 Predictor 的历史；仅 atomic swap E 可能留下内部状态不一致。

注意确认回溯时的语义：若 DEFER 后判定早前 update 开始了新事件，当前 provisional 时间线、旧事件 Commit 输入和新 Active 回放区间必须同步修正。缓存不足时保留 correction_failed/provisional，禁止作为 final event 静默入库。

## 8. 公平实验与最小核心消融

建议首轮先运行预测价值四臂；之后才加入 TCN+Boundary Head、锁定旧在线链、可运行且明确权重状态的 v2.5、v2.6 Full，以及“相同结构/监督但切断预测→Reset 梯度”臂。

预测对照保持 target、输入历史、horizon、训练更新数和合理的容量预算一致。事件对照以双方共有的 **final-event FP/min** 标定；旧 proposal FP/min 只作为候选计算量指标另报。

边界 F1 按明确秒数容差报告，另报区间级一对一事件匹配、Boundary MAE、重复同类实例召回、过/欠分割、确认与修正延迟。历史 Boundary F1 不可与逐帧分类 F1 相减。

Split BiRNN 最近报告的最终修正 Weighted F1 80.06% 使用未来窗口，平均最终等待 37.17 s；它不能当作严格因果 0.18/0.2 s 更新的基线成绩。离线 Radar-to-Text 也包含双向 GRU、居中的 MD patch 和全窗口归一化，整体不能直接接入在线主路径。若后续迁移其空间 CNN，需单独改因果预处理与时序层并重新训练/对齐。

核心消融采用完全相同模型、数据和边界监督，只改变未来预测梯度是否流回 Reset Policy。事件指标没有稳定变差时，只能说预测正则/新控制器有效，不能说已证明“预测后果驱动自主事件形成”有优势。

## 9. 我建议的第一步

先实施 P0 + P1A：锁定已训练 causal MD-GRU + 0.5B EventFormer；保留原时间粒度、维度与 gate；建立连续未来目标缓存、实例/时间审计和 Event-conditioned vs event-free 预测对照。先回答“事件状态能否提供短运动历史之外的预测收益”。

并行概念上的数据工作是审计真实实例标签，不需要训练才能推进。若要立即做 pilot，可先采用命令边界代理，明确它只能验证训练机制，不能完成真实语义事件验收。

P0/P1 通过后，再实施 Keep/Birth 和 Reset 闭环。MDL、完整大模型联合训练、复杂 Beam Search 和长时 QA 暂列后续阶段。
