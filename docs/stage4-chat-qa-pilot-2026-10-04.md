# Stage4 chat与事件问答训练

前一轮已经贯通流程，但模板CE降低未带来正确自由生成。这轮直接修正训练任务和推理接口：共用Qwen chat前缀，输入L2 top1、L1 top2与全部L0，监督活动顺序、首/末活动及14类活动存在性问答。活动标签只用于答案，不通过文本提示注入模型输入。

从上一轮100步共享压缩器继续训练500步，使用新AdamW状态。前端、原检索投影P、FullLM和LoRA全部冻结。结构不变；损失为回答CE+2倍逐摘要语义保留。初始FP16缩放256，seed42，lr1e-4，clip1。100/250/500保存检查点，最终500步作为报告对象。

为了公平比较前后回答，以初始100步压缩器的真实语义检索生成固定选中证据清单。每条训练/开发任务从自己的录制前缀生成，答案只由选中的记忆所覆盖事件产生。只用已核验的subject02/sensor14xx TRAIN缓存：set000/001拟合，set002开发。固定证据用于前后QA对照；最终在线雷达回放仍使用新压缩器产生的键进行实时检索，二者分别报告。

共享同一压缩器，训练时对选中的L1/L2源组递归重新生成有梯度摘要，保持时间/位置/层级一致。L0原事件tokens完整保留。没有压缩摘要的L0-only场景暂不作为压缩器训练样本。

活动顺序、first、last、Yes、No五类训练任务轮转，避免用总准确率掩盖Yes/No偏置。评估直接保存greedy生成，按规范答案评分，并报告同问题正反证据均正确的比例、无记忆对照和逐摘要语义余弦。格式不合格、重复乱码、截断均不能计为正确。自由生成与teacher-forcedCE分开，开发集择优不用于选checkpoint。

完整入口：

```bash
OMP_NUM_THREADS=1 PYTHONPATH=src python -u -m continuous_mmwave.parrad_stage4_qa \
  --config configs/parrad-stage4-chat-qa-pilot-v1.yaml
```

在新的输出目录运行，拒绝重复启动；已有旧权重、缓存和失败记录保留。服务器仍通过本对话授权的SSH访问，不在文件中记录认证信息。

本轮不更改Stage3阈值，也不通过GT边界替代自然在线分段。线上finalization仍为同步工程入口，TRAIN开发结果不构成未见受试者性能、生产硬实时或正式Go结论。结果另写报告。
