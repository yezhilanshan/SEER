# v2.5 在线模块实现与使用

依据：计划/方案书v2.5 (2).md。新入口是`continuous_mmwave.v25`，旧`PARradOnlineController`及旧权重保留。实现沿用PARrad的896维Qwen和实际0.18秒update，不强行改变现有LLM规格。

## 已补的代码链路

| 方案模块 | 新实现 | 关键约束 |
|---|---|---|
| Event State Update | v25/models.py AgeFreeStateGate | 网络仅收prev/delta，tanh residual；旧maturity参数兼容但不读取 |
| Semantic Difference | v25/models.py SemanticDifference | 128维时513维输入，无age |
| 物理辅助证据 | EvidenceProjection / physical_difference | 输入event tokens，属性用训练集固定归一化；缺失监督mask，不能填零当真值 |
| Stage2新gate训练 | v25/stage2.py Stage2Migration | 冻结原编码器、EventFormer主体、decoder和P；caption/alignment/consistency＋evidence＋原teacher key保留loss |
| Stage3训练 | v25/stage3.py | physical/semantic/evidence三阶段，独立oracle loss，age/class等质量配平；无Verify阶段 |
| 初始化偏差诊断 | v25/training.py age_bias_probe | 分age的same/diff概率、早期/成熟AUROC、same年龄相关及早期FPR，缺失指标为null |
| Candidate Episode / 校准 | v25/evidence.py | 生命周期label、原始轨迹、所有候选阈值及失败情况；只在开发episode上选阈值 |
| Sequential Evidence | SequentialEvidence | stability门控、log-odds、物理证据、leaky accumulation；warmup禁止决策，超时拒绝 |
| Boundary Localization | v25/boundary.py / controller.py | Confirm立即切provisional Active，后台定位；区分proposal/confirm/refined时间，无GT在线输入 |
| State Reconciliation | v25/controller.py | Pbase重建、分批tail catch-up、同watermark原子替换；stale/reset/failure不可伪装完成 |
| 特征保存 | v25/buffer.py | 普通短ring＋temporary pin；长Active的旧Commit输入有界池化，定位窗口保持原始特征 |
| Commit / Memory | v25/pipeline.py | 后台单队列保提交顺序，分层压缩也在worker；失败阻止后续静默提交，队列满显式报错 |
| 当前事件和QA | context / FrozenQA | L2/L1/L0＋可选当前Shadow/Active；生成适配器处理副本，原P检索tokens不被改写 |
| 权重与运行入口 | v25/checkpoint.py / factory.py / runtime.py | 新架构标记与SHA、严格载入；拒绝旧Verify权重；雷达编码每update一次 |

可选caption回调运行在Commit worker，caption失败单独记录，不用于事件控制或检索结构。Python线程队列提供异步机制，尚未验证CUDA调度优先级或硬实时保证。

## 验证与边界

测试覆盖：精确累积公式、warmup/timeout、梯度、新旧模型隔离、Reject恢复Shadow、定位前移/后移、慢worker继续接收观测、追赶/原子替换、连续确认、reset、失败/pin清理、真实TinyLLM EventFormer、递归Memory和QA输入。

`smoke`使用随机小模型和强制触发的头，输出中的确认数和LLM token索引只用于接口核查，不能解释为准确率。旧权重未经转换不会成为训练好的v2.5权重。

本轮没有启动真实雷达训练、服务器上传、独立测试或生产模型切换。P参数不动与检索准确率保留是不同结论：新gate会改变事件tokens，仍须对原检索任务重新评估。

最终相关回归：86 passed, 1 skipped，其中46项为新模块测试。最终40-update烟测生成13个确认区间＋1个EOF尾段，L0/L1/L2各2个unit，编码器恰好40次，失败数0。输入以最快速度喂入，没有模拟真实采集速率，因此12个过期重建被新确认取消，最后Active成功原子替换；不据此判断实时性能。原始记录：`outputs/v25-module-smoke-final-2026-10-06/result.json`、`episodes.json`、`memory.pt`。

独立审查因审查agent额度限制中断，不能标记为完整审查通过。已对其发现的问题完成失败测试→修复→全套回归：FP16/BF16证据/QA接口、提交队列溢出及失败的原始任务保留、释放archive pin、后台故障停止、新bias probe与校准/checkpoint来源和readiness校验。审查与修复记录见计划progress文件。

## 用法

在仓库根目录设置`PYTHONPATH=src`，使用interview环境：

```powershell
$env:PYTHONPATH='src'
& C:/User/anaconda/envs/interview/python.exe -m continuous_mmwave.v25 smoke --output outputs/v25-new-smoke --updates 40
& C:/User/anaconda/envs/interview/python.exe -m pytest tests/test_v25_evidence.py tests/test_v25_controller.py tests/test_v25_pipeline.py -q
```

真实路径：先在独立frontend实例上加载原Stage2权重，再显式`install_age_free_gate`；用Stage2Migration的`token_step`或`training_step`训练新gate和物理证据，原P/teacher冻结。完成后生成**新gate产生的**train/development事件缓存与episode。旧GT event-token缓存不兼容。

Stage3缓存必须含`schema_version=25`、`architecture=v25-age-free-tanh`、`frontend_digest`及`split=train`；每个semantic minibatch的每个age bucket必须同时有same/different样本。Closed-loop和oracle分别配平，再按独立系数加loss。

`fixed_budget_train`返回实际AdamW步数、逐步loss和optimizer_state；可通过以下命令训练SHA封存的Stage3缓存：

```text
python -m continuous_mmwave.v25 train-heads --config FRONTEND.yaml --bundle V25.pt --bundle-sha256 SHA --cache CACHE.pt --cache-sha256 SHA --phase semantic --steps N --output NEW_DIR
```

新训练阶段会使已有阈值校准失效。`calibrate_episodes`只接受完整有标签的开发episode，返回全部配置和选中的配置。正式加载前还需初始化bias probe和三个Stage3阶段及新gate的训练记录；未完成的bundle必须显式`allow_development=True`。

初始化bias probe在**训练后的当前Semantic Head**上，对独立development缓存重新测量，并绑定frontend/head/cache SHA。语义重训会清掉旧probe；不能把随机初始化头的报告当作训练后通过。`train-heads`可添加`--probe-cache`、`--probe-cache-sha256`及`--probe-criteria`。criteria JSON须显式给出`min_early_auroc`、`min_mature_auroc`、`max_same_early_fpr`、`max_abs_same_age_correlation`；代码不自行发明通过门槛。无门槛时仅生成诊断，passed为null，不能进入校准。

`calibrate_episodes(..., probe=..., provenance=...)`要求当前已通过probe；provenance含frontend/head/semantic head/controller config/episode SHA。检查点读回重新核对训练计数、probe、全部候选配置、selected资格及来源匹配，不信任单个status字符串。

`factory.build_runtime`把严格验证的v2.5 bundle接回原PARrad编码器；`V25Pipeline`接受已有EventMemory和显式选定的独立QA reader。原始连续回放使用同一`runtime.step`接口。每次step/poll通过`drain_finalizations`收集异步完成的job；EOF用`finish`等待并将尾段明确标记unconfirmed。部署reader和compressor仍需核对其训练来源和新事件分布。

Pipeline自动收集job，`pending_finalizations`和`retained_jobs`保存尚未完成或失败的原始payload，成功提交才释放。队列满时在消费下一雷达update前报错；等待及重试由调用者处理。后台boundary/reconciliation失败会停止后续观测，保留错误与provisional状态供核查；不能在失效的FIFO依赖链上继续生成看似成功的Memory。

## 下一步验收

固定训练预算与数据源后：训练新gate/evidence → 重建age-matched oracle/closed-loop缓存 → semantic/physical训练及训练后初始化bias probe → 开发episode校准 → 连续原始雷达回放，核对最终边界/Commit区间/Active origin，并接既有Memory/选定QA → 原检索保留与延迟、未见受试者评估。以上真实训练与效果验收尚未在本轮执行。
