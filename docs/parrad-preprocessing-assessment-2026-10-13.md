# PARrad预处理现状与下一步建议

当前canonical保存发布方HDF5中的RD/MD原值，没有额外归一化或显式杂波滤除；模型训练时另行做了预处理。不能据此断定PARrad发布的数据未经信号处理或数据质量低。

## 已确认的现状

- `rd_transfer.normalize_rd`对每个有效窗口做`sign(x)*log1p(abs(x))`后做z-score，padding不参与统计；`rd_scratch.RDResNetEncoder`在CNN前调用它。此次从头训练已经归一化，并非直接将未缩放RD送入网络。
- 旧双分支`RadarEncoder`对RD和MD分别执行同样的signed-log/z-score。新ResNet18只接收RD，MD保留但未参与本轮预测。
- 当前没有新增显式clutter removal。发布方是否已做杂波抑制、FFT shift及对数压缩，需依据其生成流程或README核对，不能仅凭变量名`rdn`认定。
- 转换与数据加载已检查NaN/Inf、形状和时间格；这些检查不能替代信噪比和杂波诊断。

本次只读抽查训练受试者01/02/13的set000，每个雷达取开头、中间、结尾各10帧，共6份传感器样本各30帧。源RD抽样最小值约−32.55、最大121.22，中位数54–56；MD约4,650–8,988。负值及数值范围说明不能直接假定为非负线性功率；负值本身也不等于坏点。这些观测提示存在已变换谱值的可能，但**不能单凭数值证明其为dB**。

另对02/set000两雷达各4帧检查，`mDoppler == rdn.sum(axis=range)`，最大差为0；仅对这些抽查帧作此结论。`cube`存储dtype为float32，不能把它直接当作保留相位的原始复数IQ。

此前在未确认源量纲前统一加入signed-log，是需要优先验证的设计选择。如果RD已经是对数谱，额外signed-log会再次改变动态范围，不应默认保留。现在不能断言它就是泛化差的原因。

## 推荐顺序

1. **确认量纲和轴。** 核对RD是幅度、功率还是对数谱，Doppler是否已经shift、哪个bin是真正零速，以及两个传感器bin对应的物理范围。官方数据页说明有技术README，但本次未取得可核验的该文件内容，单位仍标记为未确认。[PARrad官方说明](https://www.imec-int.com/en/79GHz-140GHz-radar-systems/parrad)。
2. **先隔离归一化问题。** 比较现有signed-log/z-score与直接z-score。若确认输入是dB，不再额外加log；若是线性幅度/功率，只进行一次与定义匹配的压缩。不要因出现负数就置零或做非负功率阈值。
3. **轻度异常值抑制。** 用训练受试者、按传感器估计稳健上下分位数，例如0.1%和99.9%作为候选，对输入做clip，再归一化。该数值不是已验证最优阈值，只能由validation选优。使用train统计不代表必须取消每窗口z-score，两者分别控制异常值与窗口增益。
4. **最后加入温和背景处理。** 优先保留原图作为静态证据，再提供可选的背景对比/残差表示；避免直接删除整条零Doppler带、把全session时间中值当作纯空房背景，或把前几秒默认作无人背景。躺床、坐床和低速动作本身会贡献持续或近零速回波。
5. **统一训练与推理。** RD和MD保持原时间索引与标签；每个模态独立统计、独立归一化。避免逐帧min-max使不同时刻的能量变化被抹平，优先一个窗口共用尺度。任何处理都不能只在训练或只在推理时启用。

在图像域做`D(t,r,d)=X(t,r,d)-median_t X(t,r,d)`属于背景对比增强，会同时减去持续人体回波，不能称为保证保留人体的物理杂波消除。若X为dB，这种差分也不是线性功率相减。建议将它作为可选残差通道，与未做背景差分的归一化RD共同输入；若要评价双通道收益，应有同通道数的原图复制对照。此扩展放在最小单通道消融之后。

真正的慢时间MTI需要确认原始信号及相位定义，不能把现有实值RD/MD图的时间差分当成等价实现。若后续从cube重建RD/MD，必须先确认cube语义；不在未知尺度下对现有MD做物理功率推断或盲目再次log。
