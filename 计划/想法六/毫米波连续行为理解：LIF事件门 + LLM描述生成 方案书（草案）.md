
# 毫米波连续行为理解：LIF 事件门 + LLM 描述生成 方案书（草案）

*2026-10-24 · 状态：草案，待实验验证 · 标【假设】的内容尚未验证，标【待定】的由你决定*

本方案用一个常开的 LIF 事件门把无边界的雷达流切成带时间的事件，LLM 只在事件发生时被唤醒，写出顺序、时长、次数都可核验的描述日志；分 4 个必做训练阶段，第一步只需在 PARrad 上验证事件门，不接 LLM。

## 1. 研究背景与目标

家庭看护、独居老人监护等场景，需要一种不用摄像头、能长期开着、还能说清“这个人做了什么、做了几次、持续多久”的感知方式。毫米波雷达保护隐私，LLM 擅长组织语言，但两者之间缺一个能处理无边界连续信号的接口。

**现有工作的缺口**

| 工作线 | 做法 | 缺口 |
| --- | --- | --- |
| 雷达-语言（RadarLLM、mmWave-QA、mmMind） | 几秒的片段与一句话对齐；mmMind 用 5 秒片段 caption 加文字记忆处理长时间 | 没有连续流中的边界与动作转换；次数、速度估计不准 |
| 流式视频 LLM | 压缩记忆、学习何时开口 | 依赖外观；多由提问触发；评测在视频问答上 |
| 传统雷达连续识别 | STA/LTA 或熵先切段再分类，或 BiLSTM、CTC | 只输出类别序列，没有语言；分段是瓶颈 |

**我们自己的 pilot 结果（PARrad，12 秒测试窗）**

- 完整序列正确率：生成模型 24.69%；同编码器的线性头加模板 18.88%；预测数量加段 Viterbi 的 P1 为 27.18%；纯 HMM 先验 25.52%；真数量 Oracle 34.02%。
- 结论：生成模型此前的优势主要来自数量和序列先验，不是 LLM 独有收益。
- 平滑参数 min\_duration 顶到了网格上界 0.6 秒，说明“窗口分类加后处理”容易过分割。
- 床相关动作的召回很低。

**研究目标**

1. **G1 不靠口令边界。** 只用“按顺序的事件列表”训练；事件数误差不高于 P1，序列正确率超过滑窗加平滑基线（数值预注册）。
2. **G2 输入有界。** LLM 的输入 token 数不随录像长度增长，每分钟唤醒次数可测。
3. **G3 可核验。** 每条描述带起止时间、时长、次数，与骨架算出的真值逐项对比。
4. **G4 近实时。** 事件结束后给出终稿的延迟，起点目标 4 秒内【待定】。

**范围：** 单人、单雷达、室内固定安装；动作粒度为身体级行为（站、走、坐、躺、起身、蹲、挥手、跌倒等）；不推断意图；不做多人；不把整个编码器换成 SNN。目标会议偏无线感知类（MobiCom、SenSys、UbiComp）。

## 2. 核心研究思想

**行为就是一段与当前状态一致的运动；偏离持续足够久，就是新行为开始。** 经典雷达分段（STA/LTA）早就用这个直觉，我们把它做成可学习的“漏电积分发放”事件门，并用文字顺序而不是手工阈值来训练。

三个关键想法：

1. **事件门（值班保安）。** 一个很小的 LIF 前端一直在线：逐帧累积“偏离当前状态多少”，漏掉短暂噪声，持续偏离才发火，确认一个事件结束。训练只需要“按顺序有哪些动作”。
2. **雷达管数字，LLM 管语言。** 起止时间、时长、次数由前端直接给出，LLM 只引用、不自己估计。这回应了 P1 的发现：LLM 的优势主要来自数量先验。
3. **证据稳定才说话。** 进行中的事件先写暂稿，同一描述连续几次不变才展示；事件结束再写终稿。证据不足就写“未识别的运动”，雷达证据可以推翻 LLM 先验。

**每个已知问题对应的机制**

| 问题 | 机制 |
| --- | --- |
| 连续流没有边界 | 事件门，只用事件顺序训练 |
| 训练与推理规则不一致 | 固定阈值的 LIF，不按真实事件数缩放 |
| 静止和噪声下慢漂移误发火 | 漏电：持续偏离才累积 |
| 过分割 | 自适应阈值（不应期），取代事后平滑 |
| 发火总比真实边界晚 | 回溯到电位开始爬升的时刻 |
| LLM 先验主导、数字不准 | 数字由前端给出，LLM 只引用 |
| 长时记忆随时间增长 | 事件 token 加有界文字日志 |
| 没见过的动作被硬套类别 | 低置信输出“未识别的运动” |

## 4. 模块详细设计

系统由四个模块组成：A 编码器和 B 事件门是要训练的小网络，C 是接 LLM 的接口，D 是不训练的提交规则。

### 4.1 A：因果雷达编码器

**作用：** 把每一帧雷达数据变成特征 h\_t，只用过去和极少量未来帧，能在线运行。

| 项目 | 设计（起点，非定论） |
| --- | --- |
| 输入 | RD 图与 MD 谱序列；先确认量纲，再做对数、限幅、背景处理的消融 |
| 帧率 | 内部统一为 8 帧/秒（可在 5–10 内调）；原始帧率更高时先按时间聚合 |
| 单帧网络 | 双分支 CNN（RD、MD 各一支）：4 层 3×3 卷积，通道 16-32-64-64，每层带 BN、ReLU 与池化；各分支输出 128 维，拼接后线性到 256 |
| 时序网络 | 2 层单向 GRU，隐层 256（备选：因果 TCN，膨胀 1、2、4、8，核 3）；输出延后 2 帧使用，相当于向右看 0.25 秒 |
| 输出 | h\_t，256 维 |
| 辅助头（只在训练时） | 骨架头：256→128→J×3，预测 J 个关节相对髋中心的三维坐标及其一阶差分；动作头：256→128→K，帧级类别 |
| 规模 | 约 2–4 M 参数 |

**与现有 pilot 的区别：** BiGRU 改为单向；训练时用 60 秒长片段，并随机起点、截断反传（每 15 秒一截，隐状态延续但不回传），让网络习惯“从中途接着看”。

### 4.2 B：LIF 事件门（核心）

h\_t 为编码器输出，Δt 为帧间隔，事件起点为 t0。

$$
m_t=\frac{1}{t-t_0+1}\sum_{s=t_0}^{t}h_s,\qquad a_t=\mathrm{softplus}\big(\mathrm{MLP}([h_t;\,m_t;\,h_t-m_t])\big)
$$

$$
v_t=\lambda\,v_{t-1}+a_t,\quad \lambda=e^{-\Delta t/\tau};\qquad \theta_t=\theta_0+\beta\,r_t,\quad r_t=e^{-\Delta t/\tau_r}r_{t-1}+s_{t-1}
$$

$$
s_t=\mathbf{1}[v_t\ge\theta_t],\qquad v_t\leftarrow v_t-\theta_t\,s_t
$$

- m\_t 是事件内特征均值，代表“当前在做什么”；长事件改用时间常数 60 秒的指数滑动平均，避免起点过旧。
- a\_t 是“偏离当前状态多少”，MLP 为 768→128→1。
- v\_t 是漏积分电位；τ 以秒为单位、可学习，初值 1.5 秒；θ0 固定为 1，尺度由 a\_t 去学。
- 发火后做软复位（减去阈值，保留余量）；硬复位作为消融。

**怎么调时间常数（设计公式）。** 持续驱动 a 下，从 0 到发火的时间为：

$$
t_{\mathrm{fire}}=-\tau\ln\!\Big(1-\frac{\theta\,\Delta t}{a\,\tau}\Big),\qquad \text{存在条件 } a>\frac{\theta\,\Delta t}{\tau}
$$

例：τ=1.5 秒、Δt=0.125 秒、θ=1 时，每帧驱动不超过约 0.083 就永远不发火；a=0.5 约 0.27 秒发火；a=0.1 约 2.7 秒发火。也就是说，τ 和 θ 决定了“最短证据时间”和确认延迟。

**四个机制**

1. **漏电：** 慢漂移和噪声被漏掉，只有持续偏离才发火。
2. **自适应阈值：** 发火后阈值暂时抬高，再按 τ\_r 回落，等于内置最短事件间隔，取代事后平滑；周期动作不会每一下都发火。
3. **回溯定边界：** 发火只是“确认”。事件终点取电位最近一次从低于 ε（0.1θ0）开始爬升的时刻 t\_on。用环形缓冲保存特征的累计和，区间均值 O(1) 可得，缓冲长度 192 帧（约 24 秒）。爬升期的帧归给新事件，新事件起点就是 t\_on。
4. **训练可微：** 训练时用 sigmoid 软发火（温度从 0.5 退火到 0.1），前向取硬发火、反向用代理梯度；推理时是纯硬阈值。

**事件输出：** e\_k = {z\_k, t\_start, t\_end, 时长, n\_k, p\_k, c\_k}

- z\_k：$[t_{\mathrm{start}},\,t_{\mathrm{end}}]$ 区间内特征的均值，256 维，经 Projector 变成 EVT token。
- n\_k：次数头。把事件内特征序列重采样到 32 步，经 1 维卷积加全局池化，输出 softplus 标量；监督来自骨架次数，只对周期类动作计损失，其余次数记为 1。
- p\_k：事件分类头 256→128→K；c\_k 为最大概率。
- 置信阈 κ：在验证集上选，使已知类有 95% 通过；低于 κ 的事件标为“未识别的运动”。

**进行中事件与紧急触发：** 未发火前，m\_t 可随时读出并送入分类头与次数头，供暂稿使用；高危类别（跌倒）每 0.5 秒检查一次，概率 ≥ 0.8 连续 2 次就立即提示，不等发火。

**多尺度（可选，后做）：** 再加一个慢神经元（τ 约 25 秒），驱动来自相邻事件的差异，触发“阶段摘要”，相当于 STA/LTA 的可学习多尺度版本。

**计算量：** 事件门本身每帧只增加一次小 MLP 加几个标量更新，约 0.1 M 次乘加。常开部分是 A 加 B，约几 M 参数，适合边缘 NPU 或 Jetson 级设备；真正按需唤醒的是 LLM。实际功耗和时延【待实测】。

### 4.3 C：事件到 LLM 的接口

- **LLM：** Qwen2.5-0.5B-Instruct（沿用 pilot），基座冻结，只训练 Projector 和 LoRA；1.5B 作为消融。
- **Projector：** 2 层 MLP，256→LLM 隐层维度→隐层维度（0.5B 约 896），每个事件对应一个 EVT token。
- **提示模板：**

```
[系统] 你是雷达行为记录员。只根据事件信息记录，数字原样引用；证据不足写“未识别的运动”；不要推测意图。
[日志] 00:00–00:12 站立；00:12–00:19 行走；……（旧内容已压缩）
[最近事件] <EVT> 起止 19.0–26.0 s，时长 7.0 s，次数 4，置信 0.91
[任务] 写出这个事件的一行记录。
```

- **输出：** 一行，如“19.0–26.0 s 深蹲 4 次，用时 7.0 s”。解码用贪心，最多 48 个新 token。
- **数字一致性校验：** 解析输出里的时间、时长、次数，与事件属性不一致就改用模板句，并记一次，计入幻觉率。
- **记忆只有两样：** 文字日志（上限 1024 token，超过 800 就把最旧的一半压缩成摘要；先用规则合并相邻同类事件并累计时长与次数，LLM 压缩作为消融）和最近 K=8 个事件。不另建向量记忆库。

### 4.4 D：提交规则（不训练）

| 情况 | 动作 |
| --- | --- |
| 发火（事件结束） | LLM 写终稿，覆盖该事件的暂稿，追加到日志 |
| 进行中，每 Δ=2 秒 | 读出 m\_t，LLM 写暂稿 |
| 暂稿连续 n=3 次相同 | 展示“进行中：…”（最早在事件开始后 6 秒） |
| 事件短于 6 秒 | 只出终稿 |
| 高危类别连续 2 次 ≥ 0.8 | 立即提示，不等发火 |

Δ 和 n 在验证集上选，换来延迟与稳定性的曲线。LLM 唤醒次数 = 发火次数 + 轮询次数。

## 5. 数据方案

### 5.1 PARrad（已有）

- **用途：** 调通 S1，比较事件数和序列正确率；**不用来评估边界和延迟**，因为帧标签是口令持续到下一个口令，不是真实动作时长。
- **事件列表：** 由口令序列直接得到（测试窗口约 81% 含三个动作）。
- **划分：** 沿用固定 9/3/3；已观察过的受试者（subject06、17、18）不再算未见测试，最终泛化结论只用新增受试者或自采留出数据。
- **预处理：** 先确认 RD 量纲（可能已是对数类谱，cube 不是原始复数 IQ），再做归一化、限幅、背景处理的消融（P0–P3）。

### 5.2 自采数据（雷达加深度相机）

| 项目 | 方案 |
| --- | --- |
| 设备 | 雷达（型号【待定】）与带骨架 SDK 的深度相机并排安装；雷达保存原始 ADC 复数 IQ 和配置，同时保存 RD/MD |
| 同步 | 硬件触发或 PTP/NTP；每段首尾各做一次拍手或挥板事件对齐，估计时钟漂移；容差小于 1 帧（0.125 秒） |
| 标定 | 金属球或角反射器在雷达和相机中同时定位，估计外参；用髋关节距离与雷达距离峰值互相验证 |
| 环境 | 起步 2 个，目标 3 个以上；至少 1 个含床 |
| 受试者 | 目标 15 人，对应 9/3/3 划分；参照：mmMind 为 23 人、7 个环境、17.9 小时 |
| 动作集 | 12–16 类【待定】：站、走、转身、坐下、起身、躺下、坐着不动、躺着不动、蹲、弯腰、挥手、模拟跌倒（安全垫）、离开、进入；另留 3 类只出现在测试里的“未知动作”（如跳、做操、打拳） |
| 脚本 | 每段 5–10 分钟连续录制，每段随机 8–20 个事件：类别随机、重复 1–6 次、持续 3–30 秒、含 30 秒到 5 分钟的静止；提示卡只写“做什么、几次”，不给口令和时间；每人至少 12 段，约 1.5 小时 |
| 配对集 | 每人额外录：顺序对 3 段（动作相同、顺序互换）、次数对 2 段、时长对 2 段 |
| 长序列 | 每人 1 段 30–60 分钟近自然使用（含静止、离开与返回）【待定】 |
| 合规 | 知情同意与伦理审批；只保存深度与骨架，不保存彩色图像【待定】 |

**标签生成：骨架到事件列表（规则，阈值为起点）**

| 事件 | 判据 |
| --- | --- |
| 站、坐、躺 | 躯干倾角与髋高度分类，持续 ≥ 2 秒 |
| 行走 | 髋水平速度 > 0.3 m/s，持续 ≥ 1 秒 |
| 静止 | 全身关节平均速度低于阈值，持续 ≥ 2 秒，姿态沿用此前姿态 |
| 坐下、起身、躺下 | 髋高度在 3 秒内下降或上升超过 0.25 m |
| 周期动作次数 | 关键关节高度经带通滤波后计峰值（深蹲用髋，挥手用腕） |
| 模拟跌倒 | 髋高度在 1 秒内快速下降，随后躺着不动 |
| 事件边界 | 取状态转移点，平滑 ±0.25 秒；短于 1 秒的事件并入相邻事件 |
| 质量控制 | 躺姿或遮挡时骨架置信度低于 0.7 的帧降权；每人随机抽 10% 片段人工核对，通过率达标才放行【待定阈值】 |

**文本生成：** 事件列表 → 模板句 → LLM 改写成 3–5 种说法；改写后用规则核对时间、时长、次数，不一致就丢弃。多个事件拼成的日志文本也按此生成。

**划分：** 按受试者、环境、整段录像；切窗口之前先划分；留出 3 名未见受试者和 1 个未见环境，全程不动。配对集和长序列随受试者划分。

## 6. 训练方案

4 个必做阶段加 1 个可选阶段。每个阶段只放开一部分；上一阶段通过预注册判据才进入下一阶段；checkpoint 只用验证受试者来选。

| 阶段 | 训练 | 冻结 | 监督信号 | 数据 | 通过判据 |
| --- | --- | --- | --- | --- | --- |
| S0 编码器预训练 | A + 骨架头 + 动作头 | 无 | 骨架坐标、骨架差分、帧级类别 | 自采，PARrad 作弱监督 | 骨架误差不退化；帧级 Macro-F1 不低于 pilot 的重训读出 |
| S1 事件门（CIF 版，不接 LLM） | B（CIF 模式）+ 事件头 + 次数头 | A | 事件顺序列表；骨架次数 | PARrad + 自采 | 事件数 MAE 与序列正确率优于滑窗加平滑 |
| S2 换 LIF 事件门 | B（LIF 模式）+ 事件头 | A | 同 S1；S2a 加 CIF 蒸馏 | 自采（评边界）+ PARrad | 静止假发火率、过分割率、延迟、帧率鲁棒性 |
| S3 接入 LLM | Projector，再加 LoRA | A、B、LLM 基座 | 描述文本；未知类；困难负样本 | 缓存的事件 token + 文本 | 数字、顺序、时长、次数正确率；雷达依赖度 |
| S4 联合微调（可选） | A 顶层 + B + Projector + LoRA | LLM 基座 | 同 S3 | 同 S3 | 仅当 S3 受事件质量限制时才做 |

**S0 编码器预训练**

$$
L_0=L_{\mathrm{skel}}+0.5\,L_{\mathrm{vel}}+1.0\,L_{\mathrm{cls}}
$$

- L\_skel：Smooth-L1，J 个关节相对髋中心的 3D 坐标（按身高归一化），只对骨架置信度 ≥ 0.7 的帧计损失；L\_vel：一阶差分；L\_cls：交叉熵，标签平滑 0.1。
- 课程：先 5 个 epoch 只用单动作片段（3–8 秒），再 15 个 epoch 用 60 秒连续片段。PARrad 的口令类别作弱监督，权重 0.3。
- 优化：AdamW，lr 3e-4，cosine，预热 500 步，权重衰减 0.01，混合精度；每步 8 段，累积 4 步。
- 数据增强（S0–S3 通用）：帧率重采样、加噪、距离与幅度扰动、随机起点。

**S1 事件门（CIF 版）**

先用 CIF，因为计数损失精确、训练稳定，先得到一个可用的事件分割。$\alpha_t=\mathrm{sigmoid}\big(\mathrm{MLP}([h_t;\,h_t-m_t])\big)$，累加到 ≥ 1 就发火，token 为 $\sum_t\alpha_t h_t$；训练时把 α 缩放到 Σα = N\*（真实事件数）。

$$
L_1=L_{\mathrm{qty}}+L_{\mathrm{cls}}+0.5\,L_{\mathrm{cnt}},\qquad L_{\mathrm{qty}}=\Big|\sum_t\alpha_t-N^*\Big|
$$

- L\_cls：第 m 个 token 与第 m 个事件类别的交叉熵；L\_cnt：Huber(log(1+n̂), log(1+n))，n 来自骨架。
- 优化：A 冻结，lr 1e-3，30 个 epoch，每步 16 段。
- 判据（预注册，起点）：验证受试者上事件数 MAE 不高于 P1，序列正确率不低于 P1 的 27.18%，且高于滑窗加平滑基线。失败证据不覆盖。

**S2 换成 LIF**

- **S2a（8 个 epoch）：** B 换成 LIF 模式，MLP 权重由 S1 初始化，τ 先固定为 1.5 秒。损失 = L\_qty-soft + L\_ctc + 0.5 L\_cnt + λ\_d L\_distill；L\_distill 是软发火对 CIF 发火时刻（±0.25 秒高斯平滑）的 BCE，λ\_d 初值 1.0，在 S2b 线性降到 0。
- **S2b（12 个 epoch）：** 去掉蒸馏，放开 τ、β、τ\_r（学习率乘 0.1）。

$$
L_{\mathrm{qty}\text{-}\mathrm{soft}}=\Big|\sum_t\tilde s_t-N^*\Big|,\qquad L_{\mathrm{ctc}}=\mathrm{CTC}\big(\{p_k\},\ \text{事件类别序列}\big)
$$

- CTC 的空白类表示“多余的发火”，所以发火数不等于事件数时仍能对齐，不再需要 CIF 那种“按真实事件数缩放”的步骤，训练与推理规则一致。
- 优化：lr 5e-4，软发火温度 0.5 → 0.1，代理梯度用 fast-sigmoid。
- 上限消融：另加骨架边界的弱监督（BCE），只看“边界监督能带来多少”，不进主结果。
- 判据（起点，数值待你定）：相对 CIF 版，静止长序列的假发火率下降，过分割率下降，事件召回不低于 CIF 版的 98%，帧率降到 5 Hz 后事件数变化不超过 10%。

**S3 接入 LLM**

- 先用 A、B 在训练集上跑一遍，缓存每个事件的 token z\_k 和属性，之后只训练 Projector 与 LoRA，不再跑编码器。
- S3a（3 个 epoch）：只训 Projector，lr 1e-3。S3b（8 个 epoch）：加 LoRA（r=8，α=16，作用于 q、v 投影），LoRA lr 2e-4，Projector lr 1e-4。

$$
L_3=L_{\mathrm{CE}}+0.2\,L_{\mathrm{rank}},\qquad L_{\mathrm{rank}}=\max\big(0,\,1-[\log p(y^{+})-\log p(y^{-})]\big)
$$

- L\_CE：描述文本的自回归交叉熵。L\_rank：正确描述 y+ 与“改了次数或顺序”的负样本 y− 之间的排序损失。
- 样本：日志中真值与模型前序输出各占一半（混合教师强制）；随机丢弃 10% 的事件 token，属性加 3% 噪声；未知类事件的目标写“未识别的运动”。
- 单卡可行：0.5B 模型半精度约 1 GB，序列不超过 512 token，每步 8 条。

**S4 可选联合微调：** A 顶层 lr 1e-5，B 1e-4，Projector 与 LoRA 5e-5，3–5 个 epoch。

**工程约定：** 3 个随机种子；每阶段 epoch 数提前写死，热节流时不临时改；每个 epoch 存档，可断点续训。

## 7. 在线推理过程

推理时没有任何按真实事件数缩放的步骤，只有固定阈值的 LIF 和规则。

```
每来一帧（Δt = 0.125 s）:
  h_t = A(frame)                      # 因果，GRU 状态延续
  m_t, a_t, v_t, θ_t = B.update(h_t)  # 只更新几个标量
  缓冲区追加 h_t 的累计和
  if v_t ≥ θ_t:                        # 事件结束被确认
      t_on = 电位开始爬升的时刻
      e_k = {池化特征[t_start, t_on], 起止, 次数, 类别概率, 置信}
      终稿 = LLM(日志, 最近 K 个事件, e_k)；数字校验；追加日志
      新事件起点 t_start = t_on；m_t 以 [t_on, t] 的均值重置
  elif 到了轮询时刻（每 2 s）:
      暂稿 = LLM(日志, 最近 K 个事件, 进行中事件)
      连续 3 次相同 → 展示“进行中”
  if 高危类别概率 ≥ 0.8 且连续 2 次:
      立即提示
```

**时序示例（40 秒）**

| 时刻 | 真实情况 | 系统输出 |
| --- | --- | --- |
| 0–12 秒 | 站立 | 6 秒起展示“进行中：站立” |
| 12.0 秒 | 开始行走 | 电位从 12.0 起爬升 |
| 13.0 秒 | — | 发火；终稿“0.0–12.0 s 站立，12.0 s” |
| 19.0 秒 | 开始深蹲 | 电位爬升 |
| 19.6 秒 | — | 发火；终稿“12.0–19.0 s 行走，7.0 s” |
| 26.0 秒 | 坐下并保持静止 | 电位爬升 |
| 26.5 秒 | — | 发火；终稿“19.0–26.0 s 深蹲 4 次，7.0 s” |
| 32 秒起 | 静止 | 暂稿连续稳定后展示“进行中：坐着不动” |

### 8.2 指标

| 类别 | 指标 | 定义 |
| --- | --- | --- |
| 事件级 | 序列正确率 | 去重后的事件类别序列与真值完全一致的比例 |
| 事件级 | 事件数 MAE；过分割率 | 过分割率 = 预测事件数 ÷ 真值事件数 |
| 事件级 | 起止 F1；边界误差 | 时间 IoU ≥ 0.5 且类别一致；匹配事件起止误差的中位数（秒） |
| 实时 | 终稿延迟 | 终稿出现时间 − 真值事件结束时间 |
| 实时 | 暂稿首次正确时间；改口率 | 相对事件起点；暂稿被终稿推翻的比例 |
| 系统 | 每分钟 LLM 唤醒次数、输入 token 数 | 直接统计 |
| 系统 | 前端每帧乘加数、显存、边缘设备时延 | 设备【待定】 |
| 语言 | 时间、时长、次数一致率 | 解析描述中的数字与骨架真值比：时间 ±0.5 秒，时长 ±20%，次数精确 |
| 语言 | 幻觉率 | 描述中出现、但真值事件列表里没有的事件占比 |
| 语言 | 雷达依赖度 | （原序列正确率 − 替换雷达后）÷ 原序列正确率；替换为同统计量噪声、他人录像、顺序被打乱的雷达 |
| 语言 | 未知运动检出 | 留出类别法，AUROC |
| 泛化 | 未见受试者、未见环境、帧率降到 5 Hz、距离分桶 | 同上指标 |

## 10. 主要风险与应对策略

每条风险都配一个保底方案：即使 LIF 或 LLM 的假设不成立，仍有可发表的结果。

| 风险 | 表现 | 应对 | 保底（止损判据） |
| --- | --- | --- | --- |
| 发火数与动作数对不上（重复、并行动作） | 重复动作被切碎，或并成一个 | 周期动作算一个事件加次数头；并行动作按主导动作标，边走边挥手暂不处理 | 过分割率超过 1.5 且调 β 无改善：加最短时长后处理 |
| 边界整体偏早或偏晚 | 边界误差大 | 回溯定边界；弱边界监督看上限 | 回溯后中位误差仍超过 1 秒【待定】：论文报告“确认延迟”，不宣称边界精度 |
| 静止期误发火，或开放事件的暂稿失真 | 长静止里出现假事件 | 漏电；状态通道保持；专门准备长静止测试序列 | S2 在假发火率上不优于 S1：保底用 CIF 加最短时长后处理，贡献改为“事件门加系统” |
| LIF 训练不稳 | 发火数发散 | 三步训练（CIF → 蒸馏 → 微调）；τ 先固定；温度退火 | 同上 |
| LIF 超参敏感（τ、β、τ\_r） | 换环境就失效 | 以秒为单位；网格预注册；可学习 | 报告敏感性曲线 |
| 躺姿、被子、遮挡下骨架质量差 | 床类标签噪声大 | 低置信度降权；相机俯视安装；床类单独汇报 | 床类标签核对通过率低：床类事件改为人工标注 |
| 时间同步与标定误差 | 边界误差下限被同步误差限制 | 拍手事件对齐；估计时钟漂移；验收小于 1 帧 | 同步不达标的录像不进边界评测 |
| 数据量不足、过拟合受试者 | 未见受试者上掉点 | 增强；15 人起步；先在 PARrad 验证 | 增加受试者，或只报告留出集结果 |
| LLM 先验主导，数字与事件不符 | 描述与事件对不上 | 数字由前端给出；一致性校验并回退模板；困难负样本；暂稿稳定性 | LLM 相对 B4 无增益：主张改为“事件门加模板，少量 LLM 润色”，重点放系统与评测 |
| 没见过的动作被硬套类别 | 未知动作被当作已知 | κ 阈值；留出类别验证 | 报告 AUROC，不宣称开放集能力 |
| 单卡 2080 Ti 热节流 | 训练中断或结果漂移 | 缓存特征；预注册 epoch；分阶段短跑 | 缩小 S3 规模 |
| 新颖性被撞 | 同类工作先发表 | 投稿前系统检索；先做出 S1、S2 的可发表原型 | 突出自采数据与评测 |
| 受试者隐私与伦理 | 审批延误 | 知情同意、伦理审批、脱敏存储 | 先用 PARrad 推进，采集延后 |

## 11. 预期创新点与投稿定位

1. **事件门控的连续雷达-语言接口。** 只用事件顺序文字训练，不需要边界标注；LLM 的输入随事件数而不是随时间增长。
2. **LIF 事件门是 STA/LTA 的可学习泛化。** 漏电和不应期内置了最短证据时间与最短事件间隔，取代事后平滑；训练与推理规则一致。
3. **雷达管数字，LLM 管语言的可核验描述。** 起止时间、时长、次数由前端给出并经一致性校验，可以和骨架逐项对照。
4. **系统层。** 常开前端加事件唤醒的 LLM，给出延迟-准确率曲线、唤醒占空比和边缘设备实测，不需要神经形态芯片也成立。
5. **数据与评测。** 自采连续雷达-深度数据集，以及顺序、次数、时长一致率和雷达依赖度这套评测。

**新颖性说明：** CIF 来自语音识别，本身受积分发放神经元启发；雷达 SNN 已有手势分类工作；连续雷达识别做过 CTC 加 HMM；视频领域有事件幻觉基准和顺序、次数奖励。我没查到把 LIF 式事件门接到 LLM 做雷达连续描述的工作，但没有系统查过，投稿前必须做系统检索。

## 13. 我认为存在的问题
问题一：运动变化不等于语义变化
这是我认为最大的理论问题。

假设一个人正在做深蹲：

站直 → 下蹲 → 站直 → 下蹲 → 站直

雷达特征在周期内会反复发生明显变化。

但是语义上，这完全可以属于同一个“连续深蹲”事件。

相反，一个人：

缓慢行走 → 缓慢减速 → 停止

相邻时刻的特征差异可能很小，但从语义上已经完成“行走→站立”的转换。

Claude 认为 LIF 可以积累这些偏离证据，但实际上：

LIF 只负责积累输入的变化信号，不能保证积累的是语义变化。

真正决定事件语义的仍然是：
$$
a_t=\operatorname{softplus}(\operatorname{MLP}(\cdots))
$$

因此，创新的关键未必在 LIF，而在于如何训练这个变化驱动，使其对事件内部运动不敏感、对事件之间的语义变化敏感。

这是目前方案没有充分展开的部分。
问题二：当前事件原型可能被缓慢变化污染
Claude 使用：
$$
m_t=\frac{1}{t-t_0+1}\sum_{s=t_0}^{t}h_s
$$

当人物逐渐改变运动状态时，新特征持续进入 $m_t$。

因此，事件原型本身也在变化。

这会出现你之前研究 EMA 事件原型时提出过的类似问题：
如果参考状态一直追随当前状态，模型可能无法察觉逐渐发生的事件转换。

简单的事件平均虽然比短窗口 EMA 更保留历史，但仍没有彻底解决这个问题。

我认为需要区分：
- 稳定的事件语义原型；
- 当前瞬时运动状态；
- 事件内部允许的变化范围。
这样才能更准确地描述“偏离原事件”的含义。
问题三：LIF 的时间离散化存在一个明确的问题
文档写的是：
$$
v_t=e^{-\Delta t/\tau}v_{t-1}+a_t
$$

虽然遗忘系数考虑了帧间隔，但每帧增加的 $a_t$ 没有根据时间间隔归一化。

这可能直接破坏文档宣称的帧率鲁棒性。

举个例子，假设每帧的驱动分数恒为 $0.1$，$\tau=1.5$ 秒、阈值为 1：
帧率	稳态电位（未发火假设）	能否达到阈值
8 Hz	约 1.25	能
5 Hz	约 0.80	不能

同样的持续变化，8 Hz 可能触发事件，5 Hz 却可能永远不触发。

一种更合理的连续时间离散化形式是：
$$
v_t=e^{-\Delta t/\tau}v_{t-1}
+\tau(1-e^{-\Delta t/\tau})u_t
$$

这里 $u_t$ 表示单位时间的驱动强度。

它不能保证整个网络天然具备帧率泛化能力，但至少消除了积分公式中一个明显的帧率依赖来源。

此外，回溯边界所用的“电位开始爬升时刻”也不一定可靠：如果基础驱动长期为正，电位可能始终没有回落到设定的低阈值以下。
问题四：LLM 究竟学到了多少运动语义？
Claude 设计的事件表示只有：
$$
z_k=\operatorname{MeanPool}(h_{t_s:t_e})
$$

即把整个事件的逐帧特征平均成一个 256 维向量。

然后经过 Projector，变成一个 EVT Token。

这带来两个问题：
1. 平均池化可能丢失动作内部的先后变化、局部运动与阶段结构。
2. 文本训练主要来自类别、时间和次数生成的模板，LLM 很容易学习模板化表达。
例如同样是“坐下”：
- 缓慢弯腰后坐下；
- 迅速坐下；
- 先扶住桌子再坐下。
这些细节可能无法通过一个均值 Token 充分表达。

如果最终描述只是：
12–19 秒，行走 7 秒。

那么使用分类器加模板就可以完成。

此时 LLM 并不是实现任务的必要模块。

好在 Claude 设计了 B4（相同事件 Token + 模板或 HMM）的对照，这是非常必要的实验。

还有一点：文本中的数字通过规则校验与前端属性一致，并不代表数字与真实动作一致。前端的边界或次数预测错误，LLM 仍可能生成一条形式完全正确、实际却错误的日志。
问题五：事件驱动的低功耗优势需要重新评估
文档强调 LLM 只在事件触发时唤醒。

但它同时规定，每隔 2 秒需要生成一次暂稿。

也就是说，在一段持续静坐、没有事件切换的 60 秒记录中，LLM 仍可能被调用约 30 次。

因此，当前设计更准确地说是：
事件触发终稿 + 周期轮询暂稿。

它不完全是稀疏事件驱动系统。

能否节约计算，需要通过 LLM 唤醒次数、GPU 活跃时间和实际功耗证明。


## 14. claude提出的解决方案
这五条我基本都认同：三和五是我写错或写过头的地方，一和二是我没展开的核心，四需要补实验。

**一、二：运动变化不等于语义变化，原型被慢变污染**

这两条是同一个问题，我用同一套改法解决。你说得对，LIF 只是积分，真正决定“什么算变化”的是驱动 a_t，而现在它只靠序列级弱监督间接学出来，没有任何机制保证“事件内部不敏感、事件之间敏感”。我还把长事件的原型改成了 60 秒 EMA，这会让原型更容易追着当前状态跑，更糟。

改法是把“参考”拆成三样东西：

- **锚点 c：** 事件稳定 1.5 秒后取一次，之后冻结。只有电位很低（小于 0.2θ）时才允许以约 20 秒的时间常数慢更新。一旦开始漂移，电位升高，锚点自动停止更新，所以缓慢的“行走到停止”不会被原型追上。
- **当前状态 s_t：** 最近约 3 秒特征的均值和标准差。窗口覆盖至少一个周期，深蹲内部的起伏就被抹平了。
- **允许范围 r：** 事件内部正常的起伏半径，由稳定期的偏离分布估计（如 γ 倍标准差）。

驱动变成：

```
d_t = ‖P(s_t) − c‖          （P 是学出来的投影）
u_t = softplus((d_t − r)/s)   （超出允许范围才算偏离，范围内为 0）
```

训练 P 时加一项度量学习损失：

- 正样本：同一事件内不同相位的帧，以及做过时间拉伸、幅度缩放的版本。
- 负样本：相邻事件的帧，以及把真实转换拉慢后合成的慢转换。
- 事件身份来自自采数据的骨架标签。PARrad 的口令只能作弱监督。

评测要专门量两个失败模式：周期动作（深蹲、挥手、原地踏步）内部的假发火率，以及慢转换（缓停、慢坐、缓躺）的漏检率和延迟随转换时长变化的曲线。数据采集脚本里要补这两类。

**三：时间离散化**

你的算术是对的：每帧驱动 0.1、τ=1.5 秒时，稳态电位 8 Hz 约 1.25，5 Hz 约 0.80。我文档里“换帧率不用重调”的说法只对遗忘项成立，驱动项没归一化，说过头了。用精确的零阶保持离散化：

```
v_t = e^{-Δt/τ}·v_{t-1} + τ(1 − e^{-Δt/τ})·u_t
稳态 v* = τ·u；发火时间 t_fire = −τ·ln(1 − θ/(τu))，条件 u > θ/τ
```

u 是每秒的驱动强度，设计公式里的 Δt 也随之消失，比原来更简洁。但这只保证积分和阈值与帧率无关，整个网络的帧率鲁棒性仍要靠帧率增强加 5 Hz 测试来验证，文档措辞要降级。

回溯起点的问题，一并被上面的死区解决：事件内部 u=0，电位会衰减回接近 0，起点取最后一次电位不高于 ε 的时刻，这就是 CUSUM 的经典做法。缓冲内找不到回落点时，用 t_fire 减去按平均驱动估计的爬升时间兜底。

**四：LLM 到底学到多少运动语义**

- **表示：** 把单个均值 token 换成每个事件 5 个 token：4 个相位 token（用 4 个可学习查询对事件内帧做交叉注意力），加 1 个动力学 token。动力学 token 由雷达物理统计量（多普勒质心、带宽、峰值速度、主频、时长）经小 MLP 得到。K=8 个事件共 40 个 token，仍然有界。
- **监督：** 文本不只来自类别模板，要加骨架算出的细节属性，如快慢、是否停顿、先弯腰后坐还是直接坐。同时给 S1、S2 的事件头加这些属性的辅助损失。
- **先探针，后追责：** 先用线性探针检查 z_k 里到底有没有这些属性。探针都读不出来，问题在池化和表示，不在 LLM。
- **诚实的定位：** 如果输出只是“12–19 秒，行走 7 秒”，分类器加模板就够。LLM 的必要性应在两处证明：一是细节级描述，与 B4 加属性头对比；二是日志层的开放问答与摘要（如“昨晚起夜几次”），这是规则模板难覆盖的。事件行本身只是基础。
- **数字一致不等于数字正确：** 一致性校验只防 LLM 改数。评测要把“一致率”和“真实率”分开报。对前端再加一路独立估计：次数头对自相关周期计数，两者不一致就在日志里写“次数不确定”，低置信数字写“约 4 次”。

**五：低功耗卖点**

你说得对，“只在事件结束时唤醒”和“每 2 秒轮询暂稿”自相矛盾，静坐 60 秒会调用约 30 次。改法有两步：

1. **暂稿不用 LLM：** 由前端分类头加模板生成，稳定规则也只看类别是否连续不变。LLM 只写终稿。
2. **长事件按指数退避：** 如果仍需要 LLM 报进度，间隔取 2、4、8、16、32 秒，60 秒静坐约 5 次而不是 30 次。

指标也要诚实：每分钟 LLM 调用数（静止、混合两种场景分别报）、GPU 活跃占比、目标设备上每小时的焦耳数，并把常开前端 A 加 B 的能耗算进总能耗，与 B2（固定 5 秒片段，约 12 次/分钟）和 2 秒周期调用（30 次/分钟）对比。措辞改成“事件触发终稿，加稀疏进度提示”。

这些改动会落在方案书的 4.2、4.3、4.4 节，S2 的损失，评测指标，架构图标题和首句。要我直接改文档吗？
