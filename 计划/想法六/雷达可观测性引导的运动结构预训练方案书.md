**版本**：v0.2｜开发者可执行实验规范（2026-10-25）  
**英文暂名**：Radar-Observable Motion Structure Learning  
**研究性质**：独立的毫米波 Radar Encoder 预训练 MVP；**不属于** v2.6 / v1.0 的正式模块，不连接 LLM、事件切分或记忆库。  
**文档目标**：开发者据此完成数据解析、预处理、模型、对照训练、统一探针、结果归档；所有未核实的真实数据语义有明确的核验与停止条件。

## 0. 一页执行合同（先看这里）

### 0.1 只验证一个核心假设

**研究问题**：相较于完整骨架位置回归或普通三维运动速度监督，使用与**毫米波雷达视线方向**相关的人体整体/局部运动监督，能否让相同雷达编码器学习更好的动作/局部运动表征？

- **训练输入**：只给网络毫米波点云；训练标签由与之同步的 3D 骨架离线计算。
- **推理输入**：仍然只有毫米波点云；不调用骨架、相机或动作类别作为 Encoder 输入。
- **模型**：共享 `PointNet(5→64→128) + 1-layer GRU(128)`，下游冻结评估。
- **第一阶段数据**：MM-Fi `E01`，整受试者切分，所有动作均可供预训练。
- **主要结论依据**：同等数据、模型和预算下的**冻结编码器八类动作 Macro-F1**及共同运动属性线性探针，而非各组不可比较的预训练 loss。
- **不研究**：事件边界、连续跨类动作链、LLM 描述、跨环境泛化、绝对 Doppler 真值、完整人体姿态重建。

### 0.2 必须执行的四个实验

| 实验                       | 预训练预测目标                    | 输出维度 | 对比要回答的问题          |
| ------------------------ | -------------------------- | ---: | ----------------- |
| A — Pose                 | 17×3 关节绝对位置（常规监督基线）        |   51 | 直接骨架回归有多强？        |
| B — Motion Magnitude     | 根节点三维速度幅值 + 四肢相对躯干速度幅值     |    5 | 仅仅换成运动量监督是否有效？    |
| C — Radial Motion        | 根节点带符号径向速度 + 四肢相对躯干的径向运动强度 |    5 | 雷达视线约束是否优于方向无关速度？ |
| D — Radial + Echo Weight | 与 C 相同，但使用回波支持度权重          |    5 | 回波支持度加权是否提供额外收益？  |

> **强制闸门**：A/B 无需雷达—相机外参即可执行；C/D 必须先验证骨架→雷达坐标变换。若无法验证，产出 `BLOCKED_GEOMETRY` 审计报告并只运行 A/B；严禁用未说明的“相机=雷达原点”假设代替真实标定。也不能以缺失 C/D 冒充完成四组对照。

### 0.3 完成条件

1. `reports/data_audit.json` 写出数据列、坐标、单位、帧对应与缺失率，并保存审计图；2. `pytest` 所有合成数据测试通过；3. A/B 能训练并完成冻结探针；4. 几何闸门通过则 C/D 也完成；5. 每组保存相同 split、seed、配置、权重、验证曲线及测试结果；6. 出具一页**支持 / 不支持 / 证据不足**结论。

## 1. 为什么这样设计？

**原始矛盾**：视觉骨架提供高度细致的绝对位置，但单站雷达可靠观测的主要是带几何约束的散射点位置、距离、视线向速度与相应强度。所有关节的三维位置并不是都能从稀疏点云中唯一恢复。让雷达直接拟合完整骨架，可能把容量投入难以观测的细节。

**最小干预**：不引入复杂教师网络或物理仿真，只把可用骨架转成 5 个**可解释的运动统计目标**。A、B、C 的差别集中在**监督目标**；D 额外研究简单回波权重。训练结束后扔掉预训练头，统一使用相同的冻结编码器探针评估。

**限定**：关节点不是电磁散射中心，骨架径向投影只能称为 `skeleton-derived radial-motion proxy`（骨架派生径向运动代理监督），绝不能称为逐反射点真实 Doppler Ground Truth。D 的点云动态比例是启发式支持度，不能宣称物理可观测概率。

## 2. 数据集、目录和数据切分

### 2.1 数据来源（已核实的官方格式）

官方仓库：<https://github.com/ybhbingo/MMFi_dataset>  
原始论文：<https://proceedings.nips.cc/paper_files/paper/2023/file/3baf7a39d07e9f4f1e258a412df94521-Paper-Datasets_and_Benchmarks.pdf>

官方加载器在 `mmfi_lib/mmfi.py` 中，`mmwave/frameXXX.bin` 以 **`np.float64` 读取后 `reshape(-1, 5)`**；单个动作目录下 `ground_truth.npy` 为 3D 关节序列。帧目录按 `frame001.bin` 等命名；官方代码对每条标准录制枚举 297 帧。应以实际文件枚举和形状检查为准，而不是强制所有录制恰好 297 帧。

论文将点云的五个物理量写为 `(x, y, z, d, I)`，`d` 表示 Doppler、`I` 表示强度；**官方加载器只做 reshape，没有独立注释第 3/4 列顺序**。因此需要在数据审计中核定第 3、4 列含义，未核定之前不能执行 D，也不能把任一列当成 Doppler。

论文报告多传感器记录通过 ROS 时间戳对齐、以 10 Hz 输出对齐帧、采集同步误差约 25 ms；其毫米波点云对邻近约 0.5 s 的原始帧进行了聚合。因此本实验以**发布的每 0.1 s 对齐时序**训练，不声称逐点具有 0.1 s 瞬时速度精度，也不用于端到端真实在线延迟评估。

### 2.3 固定数据划分——只做 E01 pilot

| 集合 | 受试者 | 用途 |
|---|---|---|
| train | S01、S02、S03、S04、S05、S06 | 训练 Encoder、训练线性探针；拟合标准化量 |
| val | S07、S08 | 早停、选择 checkpoint、检查探针 |
| test | S09、S10 | 只在一切决策锁定后读取一次 |

- 训练不读取 `Axx` 作为 Encoder 监督，但为了下游线性探针，可以在预先声明的 8 类动作片段上使用文件夹类别标签。

## 3. 阶段 P0：数据与几何审计（没有通过就不训练）

### 3.1 `scripts/01_audit_data.py` 做什么

对 E01 的全部录制递归枚举；至少人工展示 train/val/test 各 3 条且覆盖举手、挥手、深蹲、踏步。自动输出每个录制的：

```json
{
  "recording_id": "E01/S01/A13",
  "split": "train",
  "ground_truth_shape": [297, 17, 3],
  "ground_truth_dtype": "float32 or float64",
  "mmwave_frame_count": 297,
  "mmwave_frame_dtype": "float64",
  "mmwave_columns": 5,
  "point_count_min": null,
  "point_count_median": null,
  "point_count_max": null,
  "nan_count": 0,
  "empty_frames": 0,
  "matched_frame_count": null,
  "joint_map_verified": false,
  "geometry_status": "UNVERIFIED",
  "doppler_column_status": "UNVERIFIED"
}
```

这些 null/false 是**报告字段范例**，运行时必须填入真实统计，不得把示例数值当审计结果。记录异常而不是悄悄截断。

具体核验：

1. **文件解码**：单帧字节数是 `8×5` 的整数倍；使用 `np.fromfile(file, dtype=np.float64).reshape(-1,5)`；为空文件时记录空帧而非 reshape 崩溃。禁止 `float32` 直接读取磁盘文件。
2. **帧号**：解析 `frame(\d+)\.bin`，按数值而非字符串字典序排序；检查重复、缺帧、起始索引。骨架下标 `frame001 → pose[0]` 只在成功核对序列长度和原官方对齐逻辑后启用；否则标记冲突停止。
3. **尺寸**：骨架期望 `[T,17,3]`，容许 `dtype` 浮点；帧数实际枚举，禁止将 297 写死到模型。
4. **异常与单位**：对五列分别输出 min/p1/p50/p99/max、NaN、Inf 和零值比例；对各关节坐标及肢段长度给出分布。骨架世界坐标的原点按论文是 RGB 相机中心，**长度单位需要通过文档和样本尺度核验**，不能猜测自动乘 100 或 1000。
5. **关节顺序**：准备 `configs/joints.yaml`，对 17 关节点可先用常见 COCO-17 候选顺序（肩 5/6、肘 7/8、腕 9/10、髋 11/12、膝 13/14、踝 15/16）；**它不是未经核验即可采信的 MM-Fi 事实**。按 10 条实际骨架连线图人工确认左右、人体朝向和连接关系，确认后将文件的 `verified: true`，保存可视化截图与核验人。
6. **毫米波列顺序**：论文将五维定义为 `x,y,z,d,I`，但实现只 reshape；按论文、采集程序字段定义和实际数据分布三者核定列 3/4。记录 `doppler_col`, `intensity_col`, `doppler_units`, `doppler_sign`. 如果仍有歧义，A/B 可以使用三维坐标，**C 可以仅用几何标签，但 D 必须阻塞**；若确定速度符号不可靠，不做符号一致性结论。
7. **可视化**：至少 10 个时刻的雷达点云散点与骨架分别绘制，另绘根节点随时间的三维轨迹、四肢速度分布和每帧点数。若未校准，**只并排展示，不在同一三维轴上伪装空间已对齐**。

**P0 验收**：输出 `reports/audit/recordings.csv`、`reports/audit/data_audit.json`、`reports/audit/plots/`、`artifacts/split.json`、`artifacts/joints.yaml`。存在无法解释的列、单位或帧映射时，按下文相应闸门阻塞，不可标注 `PASS`。

### 3.2 P0G：骨架→雷达几何闸门

发布论文采用**RGB 相机中心作为世界坐标原点**。如果骨架坐标在该世界系、雷达点坐标在雷达局部系，则必须求出或获得**世界→雷达**刚体变换：

$$
p^r=Rp^w+t,\quad R\in SO(3),\;t\in\mathbb R^3.
$$

**允许的几何来源（按可信度排序）：**

1. 官方外参或可核验的采集标定资料（优先）；
2. 使用有已知对应关系的标定物/场景共同点估计 R,t，并在不同样本上验证；
3. 仅用训练受试者的点云中心与骨架根轨迹做粗配准，可标注为**proxy geometry**，需要独立误差审计，**不得宣称为精确物理外参或精确径向速度实验**。

不能直接把 Radar 与 Camera 的坐标系设为相同，也不能用 test 的骨架配准、再拿来报告 test 上的泛化结果。

**几何检查具体输出**：`configs/extrinsics_e01.yaml` 包含 `R[3×3]`、`t[3]`、坐标/单位约定、来源、拟合使用的录制 ID、验证使用的录制 ID、平均和 P95 对齐误差、`verified: true/false`。另检查 `R^TR≈I`、`det(R)≈+1`，且静态点/可核验共同几何对应关系合理。**不能仅凭关节位置范围看起来接近就过闸门**。

对于只知道相机和雷达位置近似但无法精确标定的情况，可运行 `C_proxy` 探索组，**必须与主 C/D 分开命名、不计入主结论**。主 C/D 的状态为 `BLOCKED_GEOMETRY`。

### 3.3 时间对应闸门

原论文报告 ROS 时间戳近似对齐，但发布为聚合点云，通常无法从每个 `.bin` 推回每个反射点的独立原始时刻。实验只采用配对帧下标，不补造硬件时间戳。

- 每条录制固定 `frame001` 对应 `ground_truth[0]`（须从官方加载器和实际长度验证）。
- 对根节点轨迹、点云位置/可核定 Doppler 变化绘制随时间曲线，人工检查明显的起止变化是否大致一致；对齐问题写进报告。
- 不根据 test 标签手动调整时延；若需要统一的时间偏移，只允许在 train 中决定并保存后在 val/test 原样使用；不能声称纠正了原始采集的全部同步误差。
- 0.5 s 聚合导致相邻点云时间相关，本 MVP 不研究小于该量级的精确时刻定位。

## 4. 阶段 P1：样本生成和数据契约

### 4.1 输入窗口

在每条录制内部滑动：

- 对齐帧率：`fps=10`，帧间隔 `dt=0.1 s`；
- `window_size=16` 帧（1.6 秒），训练窗口步长 `train_stride=8`；
- 验证、测试窗口步长 `eval_stride=16`（无重叠主评价）；
- 每帧最多 `P=128` 点；点不足补 0；超过 128 点时从该帧的**全部有效点**均匀无放回抽取 128 个；
- 训练时可以按 `(seed, epoch, recording_id, frame_id)` 确定性随机抽样；验证、测试必须固定同一选点种子并缓存索引，以保证 A/B/C/D 完全相同的输入。

生成张量：

| 键 | 形状 | 含义 |
|---|---|---|
| `points` | `[B,16,128,5]` float32 | `(x,y,z,feature3,feature4)`；经列审计后统一转换到明确顺序 `(x,y,z,d,I)` |
| `point_mask` | `[B,16,128]` bool | 原始有效点 True，填充 False |
| `frame_mask` | `[B,16]` bool | 同时满足有效骨架与有点云观测，且速度目标可定义的帧 |
| `pose` | `[B,16,17,3]` float32 | 原始（必要时已米制化）的真值骨架，仅进入标签构造器/监督分支 |
| `action_id` | `[B]` int | 只供下游探针，不输入编码器，不参与预训练损失 |
| `recording_id` | `B` 个字符串 | 审计、去重及按录制聚合指标 |
| `target_A/B/C` | `[B,16,51/5/5]` | 缓存的预训练标签；只读对应实验自身目标 |
| `target_mask` | `[B,16,51/5/5]` bool | 坐标、关节、速度目标的有效性 |
| `echo_weight` | `[B,16]` float32 | D 使用，其余统一置 1 |

数据读取时 `np.float64` 只用于磁盘解码；再转为网络的 `float32`。**缺失点不是真实的 `(0,0,0,0,0)`**，所有 pooling 和损失必须用 mask。

### 4.2 输入标准化

- `x,y,z`：保留原始雷达坐标方向，**不可每帧以点云质心减中心**，因为 C/D 需要雷达视线几何；可以用仅在 train 计算的逐维 `mean/std` 标准化，记录参数。
- `d`：只在字段和单位核定后标准化；若不明确，A/B 也先统一使用经过明确顺序占位的五列，但不得将不明确列称为 Doppler，报告 `feature_semantics_unverified`。
- `I`：先审计强度有无负值、dB / 线性单位，再选择统一的线性标准化；不要未经检查直接使用 `log1p`。
- 统计仅在 train 的**有效真实点**上计算；标准差下限 `1e-6`。验证与测试使用同一统计量，不允许各自重算。
- 输出 `artifacts/input_stats.npz` + 来源受试者与 SHA256。

### 4.3 有效帧和丢弃策略

1. 原始点数 0 → `point_mask` 全 False，编码器该帧特征设为零。
2. 骨架含非有限值或整帧全零等明显缺失标记 → 相关目标无效；不可把“关节在原点”当作正常运动。
3. 标签默认使用 **因果 3 帧中位数滤波** `median(p[t-2],p[t-1],p[t])` 以降低骨架抖动；速度由滤波后第 t 与 t−1 帧差除 0.1 s。最初 `t<3` 帧不设速度监督。
4. A 的关节回归允许按关节逐项 mask；B/C/D 只计算所需关键关节均有效的身体区域，其余单独按分量 mask；切勿因左腕丢失把右腿监督也丢掉。
5. 窗口中至少 12 个有点云的有效帧，且至少 12 个有任意有效目标的帧才使用；否则计数并丢弃。丢弃标准所有实验统一，否则 A/B/C/D 的样本分布可能不同。
6. **先生成各组都可用的共同窗口清单**，在几何闸门成功的主比较 A/B/C/D 中保证完全一致。C/D 被阻塞时，A/B 使用由 A/B 共同有效条件得到的窗口清单；不得把后续过滤悄悄更改成更多样本。

保存 `artifacts/manifest_{train,val,test}.jsonl`，每一项包括 `recording_id`, `start_frame`, `end_frame`, `num_valid_frames`, `split`, `action_id`，并保存 manifest SHA256；下游所有实验使用同一份版本化文件。

## 5. 阶段 P2：从骨架生成四组监督目标

### 5.1 统一符号及关节定义

记原始世界坐标骨架为 `P[t,j]∈R³`，`t` 为对齐帧下标；当外参通过验证后 `P_r[t,j]=R P[t,j]+t_ext`。**变量 `t` 是时间索引，`t_ext` 是平移向量，代码中不可混名。**

采用核验后的骨架顺序（候选 COCO17）：

```yaml
# configs/joints.yaml —— 候选；必须人工确认后 verified:true
verified: false
left_shoulder: 5
right_shoulder: 6
left_elbow: 7
right_elbow: 8
left_wrist: 9
right_wrist: 10
left_hip: 11
right_hip: 12
left_knee: 13
right_knee: 14
left_ankle: 15
right_ankle: 16
groups:
  left_arm: [5,7,9]
  right_arm: [6,8,10]
  left_leg: [11,13,15]
  right_leg: [12,14,16]
```

使用髋中心定义人体根：`c[t]=(P[t,left_hip]+P[t,right_hip])/2`。身体各部位相对根坐标：`q[t,j]=P[t,j]-c[t]`。

固定差分（骨架经 P1 的滤波后）：

$$
v^c_t=\frac{c_t-c_{t-1}}{\Delta},\quad
v^{rel}_{j,t}=\frac{q_{j,t}-q_{j,t-1}}{\Delta},\quad \Delta=0.1s.
$$

原始骨架位于同一世界系时，B 可以直接用世界坐标；C 必须把位置及相对位移通过世界→雷达旋转转换。速度标签不能用**经过网络输入标准化**的坐标计算，必须在真实米制空间计算。

### 5.2 实验 A：Pose Coordinate Regression

每帧目标：`yA[t]=P[t,:,:].reshape(51)`（真实 3D 坐标，不是只输出中心点）。输出 Head 为 `128→64→51`。

损失：对训练集的每坐标维标准化后，按有效关节/维取 Smooth L1 / Huber（`beta=1`），避免 51 维直接求和造成损失尺度异常。A 的 Head 不进入后续线性探针。

说明：与 B/C 目标维数和难度不同，因此**绝对预训练 loss 不可横向比较**；真正公平的比较是冻结同一大小 Encoder 后的相同探针结果。

### 5.3 实验 B：方向无关的 Motion Magnitude

每帧五维，单位 m/s：

$$
y^B_{t,0}=\|v^c_t\|_2,
\qquad y^B_{t,g}=\frac1{|g|}\sum_{j\in g}\|v^{rel}_{j,t}\|_2.
$$

顺序固定为：`root_speed, left_arm, right_arm, left_leg, right_leg`。

注意：四肢均为**相对根的速度**，可减弱身体整体平移导致的混淆，但没有任何跨模态几何约束。输出 Head 为 `128→64→5`，标准化 Huber。

### 5.4 实验 C：Radar-Observable Radial Motion

**前置**：`extrinsics_e01.yaml: verified=true`，包括外参单位/来源/校验结果。

以雷达为坐标原点，根位置 `c^r_t`，视线单位向量：

$$
u_t=\frac{c^r_t}{\max(\|c^r_t\|_2,10^{-6})}.
$$

完整五维：

$$
y^C_{t,0}=u_t^\top v^{c,r}_t,
\qquad
y^C_{t,g}=\frac1{|g|}\sum_{j\in g}\left|u_t^\top v^{rel,r}_{j,t}\right|.
$$

- 根速度**带符号**：正负表示在本方案定义下沿“雷达→目标”射线方向的增减，**不自动等于 MM-Fi 文件 Doppler 的正负定义**。
- 局部四肢速度取绝对投影后均值，表示该身体区域沿视线方向的活动强度。
- 每个身体区域统一用**根视线向量** `u_t`，不逐关节更新视线方向，降低最小方案复杂度。这是合理近似，不是完整人体散射模型。
- 若 `||c_r||` 太小或外参不可用，该时刻 C 标签 invalid；不能用随机方向代替。

输出 Head 与 B 同形状 `128→64→5`，按 train 目标分量 `mean/std` 标准化后 Huber。

### 5.5 实验 D：C + 动态回波支持度加权

仅当 `doppler_col`、`doppler_units` 通过数据审计时启用。给定帧中 `N_t` 个有效雷达点，计算：

$$
r_t=\frac{1}{N_t}\sum_{i=1}^{N_t}\mathbf1(|d_{t,i}|>0.1\ \mathrm{m/s}),\quad
w_t=0.25+0.75\,\mathrm{clip}(r_t/0.25,0,1).
$$

`N_t=0` 时 `w_t=0.25` 但 `frame_mask=false`，不进入 loss。

- `0.1 m/s`、`0.25` 与 `[0.25,1]` 是**首轮固定假设**，不是传感器标定结论。
- `w_t` **不参与梯度**；仅用于训练的样本/时间加权，不送入网络，不用骨架 GT 计算它。
- 只根据训练集的回波支持度分布判断它是否有足够变化；若几乎恒定，标注 D 为 `LOW_DIAGNOSTIC_VARIATION`，不反复调整阈值寻找更高 val 分数。
- 由于发布点云做过 ~0.5s 聚合，`r_t` 不是独立瞬时可观测概率，也不证明某关节实际被雷达探测到。

### 5.6 全部实验统一的损失归一化

令 `pred`、`target` 为 `[B,16,K]`，`target_mask` 为同形状布尔值。先用**各实验各维 train-only 均值方差**标准化标签，再用相同 Huber：

```python
err = torch.nn.functional.smooth_l1_loss(pred, target_normalized, beta=1.0, reduction='none')
w = torch.ones(B, T, 1, device=pred.device) if exp != 'D' else echo_weight[..., None]
mask = target_mask & frame_mask[..., None]
# sum over each (frame, component) 有效元素，并归一化总权重
loss = (err * w * mask).sum() / (w.expand_as(err) * mask).sum().clamp_min(1.0)
```

如果 A 的 51 维与 B/C 的 5 维标签方差相差很大，标准化可防止数值病态，但**不会让不同任务的预训练损失变得可直接比较**。缺失标签必须显式 mask，不能把目标置零视为有效监督。

### 5.7 标签缓存和产物

`scripts/02_build_targets.py` 读取 `manifest`、`joints.yaml`、可用外参，按上述公式生成每录制标签缓存：

```text
cache/targets/E01/S01/A13.npz
   A: [T,51]      A_mask: [T,51]
   B: [T,5]       B_mask: [T,5]
   C: [T,5]       C_mask: [T,5]    # 几何阻塞时 absent
   echo_weight: [T]               # Doppler未核实时 absent
   dt: 0.1
   label_spec_version: "v0.2"
```

生成前/后都需记录 SHA；绝不从 test 集目标重新估计标准化参数；test 真实骨架仅允许生成**评估 GT**，不得作为 Encoder 的输入、目标归一化参数或选择依据。

## 6. 阶段 P3：模型与张量契约

### 6.1 同一主干（A/B/C/D 共享）

```text
Input points           [B,16,128,5]
Pointwise Linear+ReLU    5 → 64
Pointwise Linear+ReLU   64 → 128
Masked MaxPool across P [B,16,128]
Single-layer GRU        input=128, hidden=128, unidirectional
Per-frame hidden H      [B,16,128]
Experiment Head          128 → 64 → {51 or 5}
Prediction               [B,16,K]
```

`PointNet` 对同一帧各点共享 MLP。先将 padding 位置设为 `-inf` 再 max pool；如果整帧点云为空，聚合输出设 0，防止 NaN。空帧在 GRU 仍占一个时间步，不能压缩时间轴跳过它。

最小 PyTorch 核心逻辑（结构规范，不是完整仓库代码）：

```python
class RadarEncoder(nn.Module):
    def __init__(self):
        super().__init__()
        self.point_mlp = nn.Sequential(nn.Linear(5, 64), nn.ReLU(),
                                       nn.Linear(64, 128), nn.ReLU())
        self.gru = nn.GRU(input_size=128, hidden_size=128, batch_first=True)

    def forward(self, points, point_mask):
        # points [B,T,P,5], point_mask [B,T,P]
        f = self.point_mlp(points)
        f = f.masked_fill(~point_mask[..., None], -torch.inf)
        per_frame = f.amax(dim=2)
        has_points = point_mask.any(dim=-1)
        per_frame = torch.where(has_points[..., None], per_frame, torch.zeros_like(per_frame))
        H, _ = self.gru(per_frame)
        return H
```

`Head`: `Linear(128,64)→ReLU→Linear(64,K)`，不额外输出 Sigmoid/Softmax（回归目标正负均需保留）。绝不将 `pose`、`action_id`、`echo_weight` 拼进 Encoder 输入。

### 6.2 前向接口

```python
H = encoder(batch['points'], batch['point_mask'])   # [B,16,128]
pred = pretrain_head(H)                             # [B,16,51/5]
loss = masked_huber(pred, batch['targets'], batch['target_mask'], batch['frame_mask'], weight)
```

所有实验共享架构与 Encoder 初始化分布；训练 `seed=42` 可用同一初始 Encoder 权重副本 `artifacts/encoder_init_seed42.pt`，只替换预训练目标与输出 Head。总参数因不同 Head 稍有差异；报告 Encoder 参数数和 Head 参数数，**不得声称完整可训练参数完全相同**。

### 6.3 模型检查

- 随机输入含全空帧时，前向输出 shape 正确且无 NaN/Inf；
- 任何填充点的值改变不应影响池化结果（mask 属性测试）；
- `pose` / `action_id` 改变不影响 Encoder 前向；
- backward 后至少一个 PointNet 参数和 GRU 参数获得有限非零梯度；
- GRU 不是双向；验证/测试时没有将未来帧作为输入；但**上游 MM-Fi 已聚合数据，不能据此声称传感端实时因果**。

## 8. 阶段 P5：统一的冻结编码器评估（论文主结果）

### 8.1 公平性原则

所有 A/B/C/D 预训练完成后：

1. 丢弃不同的预训练 Head；
2. `encoder.eval()`、`requires_grad_(False)`，且不更新 BN/GRU（本模型无 BN）；
3. 使用完全相同的 train / val / test manifest、点云预处理、编码维度、学习率、训练预算和种子；
4. 只训练一个**从零初始化**的 128→8 线性分类头，或者一个 128→5 的线性运动属性头；
5. test 只有最后一次读出，不根据 test 调阈值、挑 epoch 或改类别集合。

### 8.2 八类动作分类探针（**主要指标**）

预训练得到每个窗口的逐帧 `H∈[16,128]`，取**有效帧的 masked mean pooling**为 `[128]`：

$$
z_w=\frac{\sum_t m_t H_t}{\max(\sum_t m_t,1)}.
$$

分类头 `Linear(128,8)`，CrossEntropyLoss；`AdamW(lr=1e-3,wd=1e-4)`、batch 64、最多 50 epoch、patience 5，按 val **macro-F1** 选最佳（同一固定探针预算）。仅从预设八类抽取窗口训练分类头。

**主指标以整段录制为单位**，不是重叠窗口准确率：对同一 `recording_id` 的窗口 logits 取均值，再 Softmax 得到 8 类预测。每段录制只算一次样本；报告 `clip-level Accuracy`, `Macro-F1`, `per-class F1`, `confusion matrix`, `per-subject Macro-F1`。可以附加 window-level 结果，但不能作为主结论。

为什么这么做：MM-Fi 原始 E01 每条动作录制接近 30 秒，相邻窗口相关性很高。只看大量重叠窗口会高估独立样本数量。

### 8.3 共同运动属性回归探针（**次指标**）

使用所有实验共同的五维 **B 标签**（根速度幅值和四肢相对根速度幅值）作为 probe target，防止“C 只在 C 的指标上证明自己”。

从冻结 Encoder 的每帧 `H_t∈R128` 接 `Linear(128,5)`，训练集按 B 标签标准化，用相同 Huber 训练，使用 val B-MAE（m/s）早停。测试恢复物理单位，报告 `root/left_arm/right_arm/left_leg/right_leg MAE`，以及五项平均 MAE。报告每段录制、每位受试者聚合，防止有效点多的录制占全部权重。

**重要限制**：因为 B 组预训练直接优化这些属性，B 在这个探针上具有天然的目标优势。真正决定新研究假设是否有支持，仍以共同八类动作 Macro-F1、跨组局部动作混淆矩阵与一致的冻结探针为主。若 C/D 的 B-MAE 略差但分类更好，不可简单判定失败。

### 8.4 可选的径向运动探针（只有几何通过才报告）

冻结 Encoder，训练统一 `Linear(128,5)` 预测 C 标签，报告根 signed radial MAE 和四肢 abs radial MAE；明确这是额外诊断，而非主结果，因为对 C/D 同样可能有目标优势。

### 8.5 结果表模板（不得预填虚构指标）

| 预训练 | 几何闸门 | Clip Macro-F1 ↑ | Clip Acc ↑ | B-MAE $m/s$ ↓ | C-MAE $m/s$ ↓ | 说明 |
|---|---|---:|---:|---:|---:|---|
| A Pose | N/A | 待测 | 待测 | 待测 | 仅几何通过 | 标准对照 |
| B Magnitude | N/A | 待测 | 待测 | 待测 | 仅几何通过 | 运动量对照 |
| C Radial | PASS / BLOCKED | 待测 | 待测 | 待测 | 待测 | 方向约束 |
| D Radial+Echo | PASS / BLOCKED | 待测 | 待测 | 待测 | 待测 | 简单回波权重 |

**判定规则**：

- `C > B`（以同一 test 的 clip Macro-F1 为主，辅以 per-subject 变化）→ 给出“有初步支持”；
- `D > C` → 给出“回波支持度加权有初步支持”；
- 效果接近或种子间不稳定 → “证据不足”，不改写成成功；
- A/B/C/D 仅 pretrain loss 变好、下游不改善 → 当前假设未被支持；
- 单 E01、test 两名受试者是 **pilot**，不能报告严格统计显著性或跨环境泛化。

只有确定第一轮实现正确后，完全冻结配置并追加 `seed=43,44`，报告 `3 seeds mean±std`；**不能根据 test 结果修改训练参数再反复测试**。

| `test_split_isolation` | 同一 subject 出现在 train 和 test | 显式断言失败 |
| `test_no_pose_input` | 相同雷达、改变骨架 | Encoder 输出相同 |
| `test_backward` | 随机小批量 | Encoder 的梯度有限且至少有非零值 |

单元测试标准：`pytest -q tests/` **全通过**。验收记录必须保存失败日志，修复后重新执行，不能删除失败测试以“过关”。

### 9.1 数据闸门退出码

| 状态 | 意义 | 允许的操作 |
|---|---|---|
| `PASS_AB` | 基础解码、骨架标签、受试者划分已核验 | A/B 训练 |
| `PASS_CD` | 已通过空间外参与必要 Doppler/几何核验 | C/D 训练 |
| `BLOCKED_DATA` | bin 解析、帧对应、骨架布局不明确 | 停止全部训练 |
| `BLOCKED_GEOMETRY` | 雷达与骨架世界系没有可验证变换 | 仅 A/B，C/D 停止 |
| `BLOCKED_DOPPLER` | 无法核定 Doppler 列/单位 | A/B、几何通过则 C 可做；D 停止 |
| `LOW_DIAGNOSTIC_VARIATION` | D 权重近乎常数 | 记录为不具诊断力，不用调阈值补救 |

**区分**：C 的监督来自骨架与已核实外参，即使点云的 Doppler **列尚未核实**，仍可训练 C；D 必须知道 Doppler 列/单位。报告中的 `PASS_CD` 实际需要 C 与 D 分别状态，程序推荐保存 `allow_A`, `allow_B`, `allow_C`, `allow_D` 四个布尔值及理由。

### 10.2 接口合同（不应由开发者再自由决定）

`mmfi_io.load_recording(path) -> Recording`：返回 `points_per_frame: List[np.ndarray(N,5)]`, `pose: np.ndarray(T,17,3)`, `frame_ids`, `recording_id`, `action_id`，以及数据语义元信息。

`preprocess.make_windows(Recording, split, cfg) -> manifest records`：绝不跨录制边界，记录 `(recording_id,start,end)`；同一 manifest 缓存用于所有组。

`targets.compute_targets(pose, geometry, joints, dt) -> dict`：输出 A、B、合法时 C 标签及逐维 valid mask；仅在 `verified` 时允许计算 C。

`targets.compute_echo_weight(points, doppler_col, units) -> [T]`：单位未核验抛出有含义错误，不把未知列默认为 Doppler。

`dataset.WindowDataset.__getitem__()`：返回 P1 所述张量；除明确的 probe 之外，不向 Encoder 传动作 ID 或骨架。

`engine.train_pretext(exp, cfg)`：`exp` 仅允许 `A/B/C/D`；创建固定初始化、训练、验证、checkpoint；不访问 test 数据。

`probe.run_linear(exp, cfg)`：冻结 Encoder、在 train/val 拟合线性探针、保存 `probe_best.pt`；test 只在 `evaluate --locked` 中读取。

`evaluate --locked`：检查所有关键 manifest/config hash 与训练一致；写一份版本化 test 指标，若先前已存在 test 输出则默认拒绝覆盖（需要新实验版本号）。

## 11. 实验风险、可能反例及论文表述边界

**风险 R1：骨架并不完全等于真实回波散射。** 即使 C/D 改善分类，也只能说明雷达相关运动代理监督有效，不能声称恢复了真实散射体径向速度或证明物理精确性。

**风险 R2：雷达点云 0.5 s 聚合损害精细时间监督。** C/D 可能不如 B，原因可能是径向投影监督与聚合点云时间粒度不匹配，而不是物理先验完全没有价值。主报告应记录该限制。

**风险 R3：外参拿不到。** 那么该 MVP 能得出 A/B 对照，但不能证明“雷达可观测方向约束”的核心假设，报告结论应明确为 `BLOCKED_GEOMETRY`。

**风险 R4：输入已有 Doppler，任务可能过于直接。** 这并不构成数据泄漏，因为 Doppler 本来就是雷达观测；但要增设可选消融 `remove_doppler_feature`，判断提升是否几乎全部来自网络读取现成的 Doppler 数值。该消融属于后续附加实验，**首轮不改变四组核心矩阵**。

**风险 R5：E01 的受试者太少，且动作均为孤立录制。** 只能证明短时表征在此设置下可能改善，不能推广到连续跨动作事件形成、长时间文本描述、跨环境部署或实时因果性能。

**风险 R6：可靠性权重可能在低信噪区反而忽略重要运动。** D 应报告每个动作类别的权重分布；如果某类权重系统性偏低，可能反映任务偏差，不可将其解释为这些动作不重要。

**推荐最小科学结论格式**：

> 在 MM-Fi E01 跨受试者 pilot、固定 PointNet+GRU 和统一冻结线性探针设置下，相比普通速度幅值监督（B），经验证的雷达径向运动监督（C）的 clip 级 Macro-F1 [提升/下降/无明显变化]，其增益为 [实测数值]；动态回波权重（D）相对 C 的增益为 [实测数值]。由于点云时间聚合、样本量与可观测代理误差限制，这只能构成初步证据，不能直接宣称跨环境泛化或真实事件理解提升。
