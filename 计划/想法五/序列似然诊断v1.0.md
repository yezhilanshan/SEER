# 冻结Qwen序列似然诊断 v1.0

## 评分前锁定（2026-10-19）

按用户提出的实验方向，结束A/B完成状态判断支线。本轮不训练、不自由生成、不搜索新提示；先检验完整动作候选在冻结Qwen中的条件似然。沿用先前固定的transcription指令，证据为动作短语及ongoing标记组成的有序JSON列表。既有代码、模型、原结果与G0/G2协议保留。

面板固定为438例：已有Text Oracle 150例；原144组各取complete_evidence，保持旧43失败/101成功分层；新增144例确认序列。新序列种子2026101903，三类结构各48例，与旧150例及此前两轮144组的complete/remaining参考均不重合；仅因重复重采样，不依赖评分。新增面板属于开发阶段确认，不能称为独立受试者测试。既有Oracle可能有重复参考，按案例和独特参考分别核对。

每例确定性构造至多6类错误候选：交换两个已完成且类别不同的实例；将一动作换成未出现类别；将一个重复出现实例换成序列中另一已有类别并保留类别集合；仅翻转末实例ongoing；删除一实例；增加一实例。纯错序不移动ongoing实例，避免状态混杂；不存在相应结构时不造伪对照，报告实际分母。增加实例若原末动作ongoing则插在其前。候选均为规范完整描述。

使用普通完整句分词、add_special_tokens=False，尾部只追加一次EOS。采用teacher forcing，统计所有答案Token的全词表条件对数概率；不使用语法遮罩、重复惩罚或温度。主指标为含EOS的平均对数概率，同时报告含/不含EOS的总分、平均分、EOS单独得分和逐Token分数。普通分词可能合并`).`，本实验直接计算合法词表Token的概率，不经过旧生成语法；它不是旧解码路径的复测。

每对候选在两种文本证据下各评分一次：正确参考证据、错误候选对应证据。报告正确证据下的胜率与margin；错误证据下应反向偏好；双证据均排序正确；margin差（evidence_delta）。这样能区分固定候选偏好与随证据变化的响应。错序、错类、错重复额外报告候选Token数相同的子集；状态及增删实例分列，展示总分与均分的偏差及EOS排序翻转。

原生CausalLM交叉熵与首5条取分做数值核对；保存模型、局部适配器、194份包代码与全部输入哈希，前后核对冻结参数。保存每个实际评分的输入/答案Token、逐Token对数概率及比较引用，以便独立复算。

为避免看结果后选择何时进入雷达诊断，预设保守工作路由：原144组与新确认面板都要求错序、错类、错重复的等Token子集及全部状态对照分别至少20对；主胜率至少75%，双证据正确至少60%，margin与evidence_delta中位数均为正。增删实例只作长度敏感诊断。这个路由阈值是执行顺序的操作约定，不是用户原G0标准，不定义模型能力的充分必要条件。若全部满足，再用既有Projector零更新检查正确/置零/错配雷达；否则先报告文本读出中的具体限制，不追加训练。

任何似然结果均不替代原有完整生成准入及32/32内部拟合要求。G0原标准未达到，G2不得启动。

## 雷达对照的评分前锁定

沿用原G0训练内32个固定窗口、19个录制文件、原donors.json和原200步Projector检查点，不追加优化步骤。取上述文本面板中32个T0参考对应的全部148对候选，不重新采样或挑选容易的候选。三个雷达输入为正确窗口、同长度且保留时间/掩码结构的置零窗口、原先固定且等长度的错配窗口；三者使用相同候选、EOS规则和完整句分词。

雷达输入使用检查点训练时的原规范描述指令，三个雷达条件完全相同，提示中不加入真实动作文本。Text Oracle提示包含动作文字证据，雷达提示包含雷达前缀，两者输入形式不同；跨模态的绝对分数不作直接比较。主观察为各雷达条件的正确候选胜率、正确减置零/错配的margin变化，以及真实候选自身似然的变化；同时报告四种评分、等Token子集、按错误种类和19录制文件宏平均。既有训练内诊断不能支持受试者泛化结论。

全部模型参数、检查点、cells及模型来源做前后核对；不创建优化器、不调用生成。不以本轮分数定义G0通过或启动G2，也不自动追加Projector训练。原始证据另存`outputs/g0-sequence-likelihood-20261019-v1/radar`。

全部等Token子集仅26对：正确17/26、置零16/26、错配15/26。细分为错序19对、错类6对、错重复1对；其中等Token错类正确雷达2/6、置零3/6、错配1/6。顺序与类别的证据仍薄弱，4个重复对照也远不足以宣称重复实例问题已解决。

含EOS均分下，正确雷达相对置零的候选margin在102/148对中提高，中位变化+0.2121 nat/Token；相对错配96/148对提高，中位+0.0964。按19个录制文件先求组内平均再宏平均，margin变化为+0.2033、+0.0901，分别18/19、15/19个文件方向为正。真实候选自身似然优于置零144/148、优于错配114/148；由于同一真实候选复用，这些也不是独立计数。不将这些描述性指标称为预注册统计显著性检验。

长度偏好在雷达面板中十分明确：对“增加实例”候选，未归一化总分在三种输入下全部32/32偏好较短真实答案，无法据此证明雷达计数能力；均分分别28/32、4/32、17/32。删除实例则从总分10/31、1/31、6/31变成均分21/31、16/31、15/31。去掉EOS后，正确雷达有8对均分胜负翻转，状态从21/31降至18/31；不能隐去EOS贡献或只呈现较好的评分。

因此，本轮支持“已有接口包含可影响冻结Qwen候选似然的信息”，且与完整自由生成不同；但不支持“雷达顺序/类别/重复均已可靠读出”。总体增益中，增加实例与状态贡献较大，应避免仅凭108/148宣布整个动作序列问题解决。
