# 完成状态独立判断诊断

日期：2026-10-19。按用户授权，将“判断已经完成”与“动作后选择句号”分开测量；原描述提示、雷达代码、512 Token上限均未修改，未训练或启动G2。

**本轮发现：新增A/B完成判断协议被强烈的标签偏好主导，未建立可靠测量。不能把它接入终止控制，也不能把低正确率直接解释成模型不理解完成状态。**

## 主实验设计

- 使用同一冻结Qwen2.5-0.5B-Instruct及原有模型文件。
- 原144对全部保留，并按此前1.0设置下的101个成功配对、43个失败配对分层报告，未只选失败样本。
- 另固定144对确认案例，种子2026101902；前缀与原面板不重合，采用新的长度/动作组合，先固定再评分。
- 原面板另有120个、确认面板另有144个“同实例数、同类别计数、仅顺序错误”条件；单动作或全同类别无法构造错序时不伪造对照。
- 合计840个条件：288已完成、288仍有剩余、264错序。每个条件比较两种标签映射，共1680次打分。
- A表示COMPLETE/B表示NOT_COMPLETE，以及A表示NOT_COMPLETE/B表示COMPLETE。A和B均为一个Token，ID分别为32和33。
- 正确须两种映射都正确；一对正确须“已完成”和“仍有剩余”两个条件均稳健正确，即四次打分全部正确。对称化平均分只作预先规定的辅助指标，不替代主指标。
- 无答案生成；给定用户消息后读取第一回答位置的原始A/B分数，不使用GT限制输出，不进行提示搜索或事后调阈值。原描述提示不动，新增的是另一个固定的诊断问题。

## 主结果

| 条件 | 原面板稳健正确 | 新确认面板稳健正确 |
| --- | ---: | ---: |
| 已完成 | 0/144 | 1/144 |
| 仍有剩余动作 | 0/144 | 0/144 |
| 同数量但顺序错误 | 0/120 | 0/144 |
| 同一配对两种状态均正确 | 0/144 | 0/144 |

原来的101个成功配对、43个失败配对，在新判断协议下稳健配对正确均为0。因此目前无法用这个判断器把两组原因区分开。

低分的直接表现不是“模型没学会输出字母”：1680次的全词表最高分Token均为A或B，A/B合计概率质量中位数约0.999859。然而840个条件中，835个在交换标签含义后仍两次选择A；仅5个条件改变字母选择。合计1675/1680次选择A，5次选择B。

如果只看一种标签映射，会得到误导性的结果：当A表示完成时，所有已完成条件都判对，却把所有未完成和错序条件也判成完成。交换映射后，正确率随标签含义反转，反映了字母偏好而非稳健完成判断。

预先规定的对称化分数也没有恢复判别：原面板和确认面板都把全部条件判为完成，配对正确率仍为0。不能取平均后另定事后阈值，再将同一面板的改善当作成功证据。

## 固定的诊断问题

```text
Check an action description against an ordered evidence list.
COMPLETE means the description contains every evidence entry exactly once, in the original order, with no omissions or added actions. Repeated entries are separate action instances. Otherwise the status is NOT_COMPLETE. Equal counts alone are insufficient if the order differs. Ignore a missing final period or end-of-sequence token.
Evidence entries: [...]
Description prefix: "The person ..."
Which status applies?
A: COMPLETE
B: NOT_COMPLETE
Answer with exactly one letter, A or B.
```

第二种映射仅交换末尾两个选项的含义。参考正确答案、旧配对成败分层等字段只用于离线评价，不出现在问题中。

## 事后最小测量校验

主结果出现后追加了以下62次固定校验，不用于选取新提示，不修改主实验结果：

| 校验 | 单次正确 | 交换映射后稳健正确 | 观察 |
| --- | ---: | ---: | --- |
| 直接要求输出A或B，3种简短措辞 | 6/6 | 不适用 | A、B各正确输出3次 |
| X/X、X/Y、M/M、M/N符号相等判断 | 4/8 | 0/4 | 8次全选A |
| 单动作短语相同或不同，12类各一正一负 | 24/48 | 0/24 | 48次全选A |

它能在直接字母指令下选择B，但在本轮二选一判别格式中仍表现出强烈A偏好；问题并非只在长动作序列或重复实例计数上出现。上述小样本不能用来证明模型一般情况下无法判断符号相等或动作匹配，只能说明当前判别接口未通过最低测量有效性检查。

另在6个校验点比较了当前取分路径与原生`CausalLM.forward(input_ids=...)`：A/B首选6/6一致，完整logit最大绝对差0.0078125，未观察到取分路径导致的选项反转。这不是穷尽所有实现问题，但不支持把当前强烈A偏好归因于这6例中的自定义取分反转。

## 对已有诊断的解释

此前固定描述前缀下，141/144对的句号/逗号分数随证据剩余按预期变化；这说明原描述任务中存在一定的覆盖状态响应。本轮显式A/B任务失败，并不否定该响应，也不能直接回答“模型知道结束但不会发句号”还是“模型根本不知道完成”。不同提问方式的读出可靠性不同，不能把它们混为同一能力测量。

本轮能够确认的是：**当前这套独立A/B裁判不适合作为停止门控。** 不能用它强制终止生成或宣称修复了循环。

本轮结束时曾将建立新的完成状态测量列为后续候选；这不是已执行结果。2026-10-19用户随后明确结束A/B完成状态诊断支线，改为冻结Qwen的完整候选序列似然诊断，不再继续更换A/B、Yes/No或其他判断提示。后续实际执行以《序列似然诊断v1.0.md》为准。原G0和G2准入结论保持不变。
