# G0 / G2 验证实验设计 v1.0

日期：2026-10-18。状态：实验建议稿；本轮只做设计及标注清单只读统计，没有开始训练、读取封存测试信号或修改现有程序。

依据：用户贴出的G0–G3验证建议、《方案书v1.0.md》、当前latent_memory实现及既有HARrad结果。本文不引用或核验外部论文的具体提升数值，也不把视频任务结果作为雷达预期收益。

## 1. 本轮要回答的问题

**G0：冻结LLM通过可训练的雷达接口，是否确实利用连续雷达证据恢复已标注动作，而非依赖输出模板、时间长度或类别先验？**

**G2：在相同模型权重、候选记忆快照、LMT数量、检索数量及更新次数下，让演化后的LMT重新选择证据，是否比始终读取第一次选择的证据更好地恢复顺序和重复次数？**

推荐顺序：数据与读出检查 → G0直接对齐 → 所有LMT实验臂共用的适配 → G2同检查点消融 → 现有压缩记忆复核。

本轮可以建立有限历史、已标注动作序列上的机制证据；不能仅凭这组开发实验宣称完整录制的详细自然描述、实时性或跨人普遍有效。

## 2. 为什么G2先使用未压缩历史

用户本轮优先G0/G2，不开展完整G1记忆消融。为减少压缩损失的干扰，建议G2主实验在固定16秒历史内保留所有局部雷达Token，仅按年龄组织三层：近4秒为S，之前4–12秒为M，更早部分为L。检索访问仍为S、S∪M、S∪M∪L。

年龄划层只使用查询时钟，不使用动作边界；候选内容不池化、不丢弃。两帧局部适配单元及其4个Token保持原样。16秒为240帧、120个两帧单元、480个局部Token，完整直接读出预算可明确计算。

**不能只把当前容量调大来代替这个模式**：当前按容量晋升的实现会使数据全部留在Short，三组候选池趋同，不再是计划中的三个访问范围。需新增独立、保留所有单元的按年龄记忆视图。

随后仅替换记忆视图，使用当前16/16/16容量、group_size=4的压缩记忆复测E1/E3/E4。全程冻结同一套权重。未压缩视图与压缩视图之间不作等Token预算优劣宣称；两种视图各自内部的E3/E4才是主要配对比较。

这样可以区分“演化检索本身没有收益”和“压缩损失掩盖了收益”。未压缩有效、压缩无效时，只支持前者机制，不宣布完整三尺度压缩方案成功。

## 4. G0：分清语言读出、雷达对齐和潜在读出

### 4.1 先固定读出方式

本轮读出统一为冻结LLM自回归生成12类动作短语的有序描述，保留重复。不是新增分类头，也不是仅用分类探针代替生成结果。固定指令、词表、EOS、生成预算和解码策略在各实验臂相同。

建议主指标用只限制合法短语和连接格式的语法约束解码，**不能限制正确动作数、正确类别或顺序**；同一套约束用于全部对照。自由生成另作诊断，不把格式改善混为语义改善。GT只在生成结束后评分。

建议所有16秒主实验统一最多512个生成Token，32秒亦先保持512并单列截断；若资源预检显示不足，只能在正式评测前统一调整，不能按实验臂或答案长短动态加预算。

### 4.2 G0实验矩阵

| 编号 | 输入与路径 | 主要判断 |
| --- | --- | --- |
| T0 Text Oracle | 正确动作短语序列作为文字证据，冻结LLM生成规定描述 | 语言模型能否保留类别、顺序、重复；不代表雷达能力 |
| T-order | 同集合/同次数但顺序不同的文字证据 | 输出是否随文字顺序正确改变 |
| T-count | 同类别集合但重复次数不同的文字证据 | 输出是否保留重复，非只列类别集合 |
| R0 Full Radar | 未压缩局部雷达Token→Projector/时间编码→冻结完整LLM，直接生成；不经过LMT | 基础雷达—语言语义接口 |
| R-null | 雷达cells置零，保留同样时间戳、mask、位置及Token数 | 排除时长、数量和时间编码先验 |
| R-swap | 换成另一个同长度episode的真实雷达；参考仍为原episode | 排除类别/句式先验；替换对先固定 |
| R-compressed | 同一Projector读取当前压缩记忆后直接生成 | 压缩读出的诊断，不作为E4的主因果比较 |
| Z0 Bootstrap | 公共接口完成后，经Bootstrap LMT读出，R=0 | 确认潜在读出本身没有完全失效 |

Text Oracle必须覆盖单动作、同集合异序、相邻同类、交替重复及右边缘进行中实例。可以用合成文字作语言诊断；不得把拼接Oracle动作片段的结果当自然连续雷达性能。

R-swap还要同时对替换源参考评分：有意义的模型应更支持真实输入对应的参考，而不是对所有输入生成固定答案。比较相同输入形状，避免Token数量改变成为唯一线索。

### 4.3 训练与诊断

第一阶段只训练Projector和时间投影，冻结CNN、旧局部适配器和Qwen，用完整、按时间排列的4/8/16秒episodes及标准答案CE做基础对齐。按长度均衡抽样，不按动作边界取训练段。

记录fit与inner-dev的真实生成结果及CE。单动作Macro-Accuracy只在离线标注为单实例的固定窗口子集上报告，注明边缘截断比例；不把这种后验分组解释成实时单动作检测能力。旧RD分类结果只作为背景，不能把不同窗口/重置协议的85%左右直接当作本实验达标线。

额外作顺序对比诊断：同一雷达输入下，比较正确参考与同多重集合异序参考的长度归一化LLM答案对数似然；错配雷达也同样测。它只用于定位读出/对齐问题，不替代自回归Sequence EM。

G0至少需要看到：正确雷达相对R-null/R-swap的可靠增益；更换或重排证据能相应改变输出；多动作顺序能力不能仅由类别集合命中支撑。若只出现训练CE下降、单动作有信号而多动作仍读不出，应记录“基础可解码但连续接口未就绪”，不宣布G0完整通过。

本稿不擅自设置90%/80%准确率线。正式训练前应依据预实验，锁定最低可用绝对水平及最小有意义效应；不能观察subject7主结果后再定义“通过”。Text Oracle经常失败时先处理语言读出；R0失败时先处理投影/输入接口，不用HME掩盖。

## 5. G2：共享权重的E0–E4主实验

### 5.1 共用适配，避免谁被训练过谁占优

基础对齐后冻结G0的Projector与时间编码，冻结CNN、局部适配器和Qwen。训练一份所有LMT实验臂共用的Initial LMT及state_norm，不训练独立分类头、不增加辅助损失。

建议适配中均衡使用以下6种模式：R=0；R=1；R=2固定证据；R=2动态证据；R=3固定证据；R=3动态证据。R=1的固定/动态路径完全相同，不重复计作两种。各模式共享全部参数，不向模型提供模式标签，每步只采用其中一种模式与同一CE目标。

这样E1、E3、E4都使用同一检查点，避免只训练E4、再把未适配的R=0/固定路径当成公平基线。这里允许训练新接口/LMT；“冻结LLM”不等于所有模块从未训练。评测时不更新任何参数，不进行测试时优化。

### 5.2 固定实验臂

| 实验 | 精确定义 | 信息/计算解释 |
| --- | --- | --- |
| E0 Direct | 全部候选雷达Token按时间排序，直接交冻结LLM生成；无LMT读出 | 直接语义读出的信息参考；解码前缀比LMT长，不称等成本对照 |
| E1 Initial | 一次三组Bootstrap，连接三组LMT后生成，R=0 | 潜在压缩基线 |
| E2 One-shot RAG | 用Bootstrap LMT只检索一次；取所选原证据、跨组去重、按时间拼接后直接生成，不执行LMT更新 | 普通一次检索读出；不作为严格等计算主比较 |
| E3 Fixed | Bootstrap后更新2轮，各组两轮都使用第一次选择的证据 | 控制多次冻结LLM前向 |
| E4 Evolved | Bootstrap后更新2轮，每轮根据当前LMT重新选择证据 | 本轮核心机制 |

主要比较预先固定为 **E4(R=2) − E3(R=2)**。E4−E1辅助说明演化总体价值；E0/E2说明直接读出和普通检索的表现，但不能把不同长度/不同调用次数的差异全部归因动态检索。

E3/E4必须共用候选快照、Projector、LMT初始化/归一化、每组4个LMT、每组top4时间单元、时间编码、输出预算与解码器。每单元4个局部Token，所以每轮最多读取48个证据Token；2轮合计最多96个，短候选池按实际数量报告。两臂均执行3次Bootstrap组前向+6次演化组前向+1次文本生成，计算真实耗时而非只数API调用。

为匹配检索计算，E3仍计算每轮当前分数，但第二轮丢弃新排序、继续读取第一次的选择。固定的是同一组证据张量，不是只固定检索数量。

### 5.3 逐轮与机制检查

所有臂先生成一次Bootstrap状态。R=0/1/2/3的读出使用同一检查点，每个读出都从相应阶段状态独立开始生成，生成文字不回写后续检索。

不可缺少的检查：

- E3/E4的Bootstrap及第1轮选择、状态和输出应一致；否则主比较有实现差异。
- 记录每组每轮候选、分数、选中单元、时间范围、状态变化量、相邻轮Jaccard重合与新增证据覆盖。
- 以真实两帧单元与GT区间交集评估检索覆盖和每实例可见时长覆盖；不能仅用压缩摘要的宽时间跨度宣称它保存了所有动作。
- E4/E3选中证据完全相同且最终答案相同，是合法负结果；状态变化或检索变化本身不算性能收益。
- 不要求每轮严格单调变好，不根据验证曲线反选最优R。R=2是主结果，R=0/1/3为解释曲线。
- 额外固定随机检索或均匀时间采样可以作为扩展，不能替代E3这个等计算对照。

## 6. 顺序与重复的负对照

优先使用自然形成的同动作多重集合、不同顺序配对；若模型对两条流输出同一序列，就不能靠类别集合匹配宣称顺序理解。分别报告两条都正确的配对比例，避免单边碰巧命中。

另外使用固定种子的两帧单元乱序作为敏感性诊断：保持冻结局部Token内容及数量，打乱单元后重新赋予当前观察序列的时间位置。**不能保留原时间戳让模型直接还原原序**。用相同打乱输入和元数据处理所有实验臂。

乱序会造成不自然的动作过渡，且会改变实例片段结构；因此“原始GT下分数下降”只说明依赖时序输入，不单独证明语义顺序正确，也不把原GT硬当作乱序流的新真值。需要可评分的重排真值时，另设Oracle动作块重排诊断，并明确使用GT进行构造，不混入自然连续主结果。

重复次数单列相邻同类、同类再现/交替重复两组。根据动作实例计数，不把一个长drumming实例解释成若干次敲击。

## 7. 统一指标，先修正现有口径

主指标为逐窗归一化Edit Score，再按原录制等权平均：

`EditScore = 1 − Levenshtein(pred, gt) / max(len(pred), len(gt), 1)`。

当前代码的normalized_edit_distance除以GT长度且只汇总可解析样本，不能直接改名当上述Edit Score。需新增实验专用评分，保留原报告定义。非法输出不丢弃：主EditScore记0、EM记错，单列解析率；语法约束解码不能掩盖EOS/预算截断。

非法输出的计数按空预测计，保留invalid标记，不能只在可解析样本上报告更低Count MAE；截断输出按已完整解析的实例计数，同时主EditScore记0、EM记错。空GT窗口单列，不让其计数误差0抵消生成失败。

同时报告：

1. Sequence EM：整个有序实例序列完全一致。
2. Total Count MAE：`mean(abs(len(pred)−len(gt)))`。
3. Class Count L1：每窗12类实例计数绝对差之和，再平均。当前代码是再除以12的版本，应另列兼容列，不与Total Count MAE混用。
4. 重复类别子集的EM/Edit/两种次数误差。
5. 进行中状态完整正确率，及仅在类别序列正确时的状态准确率；不把条件子集分数当总体分数。
6. 解析率、截断率、实际证据Token数、LLM调用、延迟、峰值显存。

短动作召回如作为辅助指标，采用inner-fit完整实例时长的第25百分位作预注册短动作界限；窗口边缘截短不让一个长动作变成短动作。使用固定、可独立复算的顺序匹配，明确重复同类匹配的tie-break。不在观察验证结果后调整阈值。

## 8. 预算建议及结果判读

### 8.1 建议的两段预算

先做诊断：Text Oracle及32个固定inner-fit窗口，seed42，基础接口最多200次更新，检查损失、真实生成及梯度；此权重不作正式初始化。如果无法拟合训练小面板，停止排查接口，不自动延长预算或启动全部HME实验。

32窗仅从固定时钟网格选择，在看模型输出前保证12类标注覆盖及重复/顺序诊断案例；允许依据inner-fit标签选择已有窗口，不移动边缘对齐动作。若32窗无法覆盖，先报告覆盖不足并在正式锁定面板前统一扩容，不在结果出来后补有利样本。

随后在设计及最低可用标准锁定后，建议正式G0接口与公共LMT适配各1000次成功更新，seed42/43/44；每阶段共3000更新，两阶段总计6000。局部适配器与Qwen均冻结，AdamW lr1e-4作为工程起点，只用inner-dev决定是否在正式实验前修改。模式/长度抽样清单、初始化及每步来源提前保存，最终固定1000步检查点，不依据subject7择优。

每阶段保存0/100/300/1000步；中间点只用于学习诊断，不增加正式预算。首轮先实测各长度的耗时/峰值显存，再估算总时长，不凭两步90帧工程预检估计整轮成本。本段数值是建议预算，当前没有启动或锁定为不可变研究参数。

### 8.2 有效性证据与失败解释

建议预注册的方向性必要条件：主面板E4相对E3的录制宏平均Edit Score为正增益，三seed方向一致；同时检查EM与次数误差，不能用流畅输出、更多文字或更高解析率替代顺序改进。最小有意义增益及允许的次指标波动范围应在正式subject7评测前锁定，不事后定义。

| 结果 | 能支持的结论 | 下一步 |
| --- | --- | --- |
| Text Oracle失败 | 语言/格式读出尚未建立 | 先修读出，暂不解释雷达或HME失败 |
| Oracle成功，R0不胜无证据/错配 | 缺少基础雷达—语言对齐证据 | 修Projector或输入接口 |
| R0成功，Bootstrap读出失败 | 潜在压缩/读出适配存在瓶颈 | 检查公共LMT适配，而非只加演化轮数 |
| E4优于E1但与E3相近 | 多次前向可能有用 | 不能宣称动态重新检索有独立收益 |
| E4稳定优于E3，顺序/重复也改善 | 支持固定有限历史下动态检索演化有额外价值 | 用当前压缩视图复核 |

subject7只有4条录制、1位受试者。逐窗结果高度相关，不能把104窗或全部配对当作104个独立受试者，也不能把4录制×3seed当作12个独立人。报告各录制、各seed及配对差值；以录制为簇的bootstrap区间仅作探索性不确定性描述，不当作跨人显著性结论。最终外推仍需要锁定后的封存受试者实验。
