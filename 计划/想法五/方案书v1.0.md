# 无显式动作分段的毫米波连续行为描述方案书

**版本：v1.0（讨论确认版）**  
**日期：2026-10-18**  
**参考论文：** [LatentStream — *Beyond Retrieval: Progressive Latent Memory Evolution for Streaming Video Understanding*](https://arxiv.org/abs/2609.04131)

> **版本边界**：本文只固定本次讨论已经明确的总体方向和 LatentStream 中决定参考的技术流程。此前由助手自行建议、但尚未获得明确确认的参数、网络细节、损失函数与实验门槛均不写成既定设计；需要进一步讨论的内容统一标为“待定”。本方案为独立的 v1.0，不自动继承旧版事件分割方案的模块。

## 一、研究目标

面向**单人室内毫米波连续人体行为描述**。系统接收连续到来的毫米波雷达信号，不在输入端或中间表示中显式划分动作片段，而是维护不同时间尺度的外部记忆，定期通过三组 Latent Memory Tokens（LMT）查询历史证据，利用语言模型演化潜在表示，最终生成反映动作**先后顺序、变化过程和细节**的自然语言描述。

任务使用**固定的行为描述指令**，而不是面向不断变化的用户问答。指令的准确文字尚未确定；其含义为“按时间顺序描述截至当前时刻观测到的人体行为”。

本方案不把预先检测出的动作边界、动作片段或事件 Token 当作 LMT 的必要输入。

## 二、已确定的总体思想

1. **无显式动作分段**：连续雷达流不经过 Proposal、Verify、Boundary Localization 等动作分割流程；动作之间的变化和顺序由后续潜在记忆与语言模型理解。
2. **三尺度外部记忆**：将雷达历史组织为 Short / Mid / Long 三个时间尺度，供查询使用；具体时间窗口、容量和压缩策略未定。
3. **固定任务、定期查询**：系统每隔一段时间执行一次记忆读取，目标始终是连续行为描述；查询周期未定。
4. **三组 LMT**：按照短、中、长时间感受野组织可学习潜在 Token，并采用逐渐扩大的历史访问范围。
5. **Bootstrap 初始化**：参考 LatentStream 原文，在正式迭代检索前，首先将固定指令、初始 LMT 与外部记忆送入冻结的语言模型进行一次前向传播，取 LMT 位置的隐藏状态作为后续检索的起点，而不是使用时间锚点初始化。
6. **Evolved LMT**：使用当前 LMT 检索相关历史证据，再通过语言模型更新 LMT；更新后的 LMT 继续指导下一轮检索，形成“检索—内化—再检索”的演化过程。
7. **语言输出**：将演化后的潜在记忆交给语言模型，生成连续的人体行为文本描述，而不是仅输出离散动作类别。

## 四、模块与信息流

### 4.1 Radar Encoder

将连续毫米波雷达数据转换为可供记忆系统存储和语言模型读取的时序特征。MVP 可以优先复用此前实验已有的连续雷达特征，以避免在验证记忆机制时同步改变上游编码器。

雷达输入形式、编码器结构及其与 LLM 的具体特征对齐接口**待定**；本版本不新增或指定未经确认的网络结构。

### 4.2 Hierarchical External Memory

持续接收 Radar Encoder 产生的特征，将历史组织为：

- **Short Memory**：近期较细粒度的信息；
- **Mid Memory**：中等时间跨度的信息；
- **Long Memory**：更长时间范围的历史信息。

这里的“分层”是按**记忆时间尺度**组织信息，**不是按动作边界划分事件**。记忆应保留历史的时间顺序，但时间编码的具体实现尚未确定。

是否直接采用 LatentStream 的 Jenks-guided adaptive consolidation、各层保留多少 Token、如何聚合历史，均**待定**。

### 4.3 三组 LMT 及访问范围

记三层记忆为：

$$
\mathcal{M}^{s},\quad \mathcal{M}^{m},\quad \mathcal{M}^{l}.
\tag{1}
$$

参考 LatentStream 的渐进式访问机制，三组 LMT 的候选检索范围分别为：

$$
\begin{aligned}
\mathcal{C}^{s} &= \mathcal{M}^{s}, \\
\mathcal{C}^{m} &= \mathcal{M}^{s} \cup \mathcal{M}^{m}, \\
\mathcal{C}^{l} &= \mathcal{M}^{s} \cup \mathcal{M}^{m} \cup \mathcal{M}^{l}.
\end{aligned}
\tag{2}
$$

即更大尺度的 LMT 不会失去访问近期细节的能力。每组 LMT 的数量与具体维度**待定**。

### 4.4 Bootstrap Forward Pass

以固定描述指令 $q_{\mathrm{fixed}}$、初始 LMT $Z^{\mathrm{init}}$ 和当前外部记忆 $\mathcal{M}_{t}$ 为输入，按照对应分组的注意力可见范围进行一次冻结 LLM 前向：

$$
\widehat{Z}_{t}^{(0)}
= \operatorname{LLM}_{\mathrm{frozen}}
\big(q_{\mathrm{fixed}},\, Z^{\mathrm{init}},\, \mathcal{M}_{t};\, A_{\mathrm{group}}\big)_{\mathrm{LMT}}.
\tag{3}
$$

该式表示**提取 LMT 对应位置的隐藏状态**，不是要求 LLM 先生成文字。此后，LMT 携带固定任务语义和已读取的记忆上下文，作为迭代检索的查询表示。

本版本**不采用时间锚点初始化**。

### 4.5 Hierarchical Latent Memory Evolution（HME）

在第 $r$ 轮演化中：

1. 使用当前 LMT 表示与允许访问范围内的记忆特征计算相关性；
2. 从相应层级选取相关历史证据；
3. 按组将检索证据注入对应 LMT 的语言模型输入上下文；
4. 通过冻结 LLM 前向更新 LMT 的隐藏状态；
5. 以更新后的 LMT 重新检索，进入下一轮。

抽象地表示为：

$$
\widehat{Z}_{t}^{(r)}
\;\xrightarrow{\ \text{retrieval from } \mathcal{C}\;}
\mathcal{E}_{t}^{(r)}
\;\xrightarrow{\ \text{frozen LLM update}\;}
\widehat{Z}_{t}^{(r+1)}.
\tag{4}
$$

**每轮重新检索**是本方案希望保留的 Evolved LMT 核心，不将其简化为一次固定 Cross-Attention。具体检索数量、相似度实现、迭代轮数及资源预算**待定**。

### 4.6 LLM 连续行为描述

将 Evolved LMT 作为历史运动证据的潜在表达，在固定描述任务下生成按时间顺序组织的文本。

需要实现雷达表示与 LLM 隐藏空间之间的有效衔接，但其具体训练方式、Projector 结构以及是否采用 LoRA **待定**。本版本不规定具体 LLM 型号。

## 五、工作时序

1. 连续雷达数据到达，Radar Encoder 产生连续特征。
2. 外部记忆持续维护 Short / Mid / Long 三个尺度。
3. 到达定期查询时刻后，在固定描述指令下执行 Bootstrap Forward Pass。
4. LMT 在三尺度记忆上进行多轮检索与演化。
5. 将 Evolved LMT 交给 LLM，生成截至当前时刻的连续行为描述。
6. 后续雷达数据继续写入外部记忆，并在下一个查询时刻重复上述过程。

**关于跨查询周期的 LMT 是否直接继承上一轮状态：尚未确认。** 当前只确定一次查询内部的多轮 Evolved LMT，不把跨周期状态递推写成既定机制。

## 六、MVP 验证范围

MVP 重点验证：**没有显式动作分段时，Evolved LMT 是否比未演化的 LMT 更能保留连续雷达中的动作顺序和变化信息。**

讨论过的最小对照包括：

- **Initial LMT**：Bootstrap 后直接用于读出，不执行后续演化；
- **Evolved LMT**：Bootstrap 后执行 LMT 引导的多轮历史检索及更新。

优先关注以下结果：动作的**先后顺序、重复次数、完整动作序列是否正确**，以及最终文本是否保留已发生的关键行为。

此前讨论过利用已有 **HARrad 连续特征**开展初步验证；是否采用哪一版特征、数据划分、训练方式、评测阈值和 LLM 接入顺序，均不在本版中重新锁定。

## 八、当前方案边界与后续决策

**已确定的研究主线**是：连续雷达输入 → 三尺度外部记忆 → 固定指令与 Bootstrap 初始化 → LMT 引导的分层反复检索 → Evolved LMT → LLM 连续描述。

**尚不能宣称**：该方案已经解决连续动作顺序理解，已经具备实时性能，或者比显式事件分割方案更准确。以上均需要后续实验验证。

**文献与本方案的区别**：LatentStream 原文面向问题驱动的视频理解；本方案把任务固定为连续毫米波人体行为描述。把 LMT 用于定期固定任务检索是本项目的研究设想，不是原论文已验证的结论。
