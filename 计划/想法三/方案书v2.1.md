# 毫米波连续动作实时语义理解与分层事件记忆系统方案书

**版本：v2.1（模块结构冻结版）**

## v2.0 → v2.1 变更清单

1. **Fork-and-Replay 替换并行跟踪**：proposal 触发时快照并冻结 Active，Candidate 独立吸收后续雷达；Reject 时将缓存雷达 replay 给快照恢复（原"双状态并行更新"废止）；
2. **冻结全部模块内部结构**：Radar Encoder、检测前端、Event Former、各 head、Compressor 均给出具体层结构与维度；
3. **前端尺寸紧缩**：F_t 从 32×3584 紧缩为 4×256（cross-attention 的 K/V 投影天然完成维度映射，无需预投影到 LLM 空间）；
4. **Event Token 区域改用 Prefix-LM mask**（token 间双向可见）；
5. **门控更新改为逐 token 标量门**（含成熟度输入）；
6. **Radar Transition 迁入独立的 128 维归一化原型空间**，z-score 化偏差 + age 特征；
7. **Proposal 改用 noisy-OR**（不再训练第三个网络）；
8. **Transition Decision 改为单调 Logistic Head + 超时 Reject 规则**；
9. **Idle 控制器输入扩展为四统计量**（明确"静止站立 ≠ Idle"）；
10. **记忆检索统一至 Semantic Projection 空间**（不再单独训练检索编码器）；
11. **系统抽象为三个可学习核心模块**（Radar Encoder / Streaming Semantic Event Former / Hierarchical Memory Compressor），其余为轻量 head。

# 一、任务目标与问题定义

面向**单人室内连续毫米波人体行为理解**。输入为持续到来的毫米波雷达流；系统在线理解"当前人在做什么"，在动作语义转换时形成事件，并生成按时间顺序组织的自然语言描述。

三个核心问题：①连续雷达流中什么时候可能发生动作变化；②当前语义是否已从原事件转变为新事件；③如何把已完成的事件长期保存，使 LLM 能理解完整行为历史。

核心思想：**在持续理解过程中形成事件**，而非"先切事件再理解事件"。

## 三条设计原则

1. **Token 是信息的唯一货币**：所有雷达信息在事件 commit 前蒸馏进 Event Semantic Tokens；commit 后原始雷达特征即被丢弃，LLM 深层永远不接触雷达原始特征；
2. **语义事件一致性优先于帧级边界精度**：接受 0.5~1s 量级的确认延迟，换取不过度分割、语义纯净的事件序列；
3. **Propose-and-Verify 分工**：前端轻量检测器高召回提出假设，语义层严格验证与拒绝。

# 二、总体架构

## 2.1 系统视角：七个模块

```text
Continuous mmWave
       │
       ↓
① Streaming Radar Encoder（stateful，F_t: 4 radar tokens）
       │
       ├──────────→ ② Local Change Detector ────────────┐
       ├──────────→ ③ Radar Transition Detector ────────┤
       └──────────→   Idle/Presence 控制器              │
                       │                                │
                noisy-OR Proposal                       │
                       │                                │
        ┌──────────────┴──────────────┐                 │
        ↓                             ↓                 │
  ④ Active Event State        ⑤ Candidate Event State   │
  （fork 后冻结快照）          （P_base 独立启动）        │
        │                             │                 │
        │                    Semantic Diff / Stability ─┤
        │                             │                 │
        │                      ⑥ Transition Decision    │
        │                      ┌───────┴───────┐        │
        │                    Reject          Confirm     │
        │                 （replay 恢复）  （fork 定稿）  │
        ↓                             ↓
   E_commit ← Commit Refiner      Candidate 接管为新 Active
        │
        ↓
⑦ Hierarchical Event Memory（Level 0/1/2 + Query Compressor）
        ↓
   完整 LLM（推理路径，只读 token）
```

## 2.2 学习视角：三个可学习核心模块

系统看似七个模块，真正需要训练的核心网络只有三个：

$$\boxed{\text{Radar Encoder}}\quad\boxed{\text{Streaming Semantic Event Former}}\quad\boxed{\text{Hierarchical Memory Compressor}}$$

Local/Radar/Semantic/Stability/Decision 全部是围绕 Event Former 的轻量 head。坚持三个"**不新增模型**"原则：**Candidate 与 Active 共享模型；Commit Refiner 复用 Event Former；Memory Retrieval 复用 Semantic Projection**。论文 Method 按三模块叙事组织。

## 2.3 双路径计算框架

|  | 流式路径（Streaming Path） | 推理路径（Reasoning Path） |
| --- | --- | --- |
| 运行频率 | 每 chunk（2~5 Hz） | 每事件 commit + 每次用户查询 |
| 涉及结构 | LLM 层 1-4（含 gated cross-attention）+ 全部轻量 head | 完整 LLM（全部层） |
| 输入 | 当前 chunk 雷达特征 F_t、Instruction Tokens、Event Tokens | Event Tokens、记忆 Tokens、Instruction/查询 |
| 雷达注入 | **是（仅层 1-4）** | **否（只读 token）** |
| 职责 | 增量维护 E_t；运行全部判决 head | 生成事件描述 y_i；长程推理与问答 |

雷达只在层 1-4 注入的理由（分层记忆一致性 / 近因偏差 / token 唯一货币）见 v2.0，此处不变。信息瓶颈补救阶梯不变：增大 K → commit 精修重编码 → 受限深层注入（Stage 2.5，须附 token-only 长历史问答对照实验）。

## 2.4 事件生命周期（Fork-and-Replay 版）

```text
正常流式：Active 持续吸收雷达
       │
       │ proposal 触发（t_p 时刻）
       ↓
┌─ 快照并冻结：E_A^snap = E_A，R_A^snap = R_A（含 Welford 统计 n/μ/M2 与 EMA 状态）
│              A 的特征缓冲区在 t_p 处封口
│
│  Candidate：E_C = P_base，R^C 从零开始累积，独立吸收 t_p 之后的雷达
│  z_A 冻结为固定参照系，p_diff 比较更稳定
│
├─ Reject：将缓存的 F_{t_p:t} replay 给快照（E 与原型统计同步重放恢复），Active 继续
│
└─ Confirm：
   ① A 缓冲区 F_{t0:t_p} → Commit Refiner（复用 Event Former，事件内非因果）→ E_commit 入库
   ② Candidate 接管：E_new^A = E^C，R_new^A = R^C
   ③ 新事件开始时间回溯标注为 t_p；旧事件结束时间 = t_p，边界归属无歧义
   ④ 生成 y_i；A 的雷达通道永久关闭，缓冲区释放
```

相比 v2.0 的并行更新，Fork-and-Replay 消除了三个问题：旧事件 E_commit 被新动作污染；p_diff 参照系移动导致差异信号侵蚀；边界归属歧义（v2.0 §6.4 的"互相吸收"取舍段废止）。

# 三、模块①：Streaming Radar Encoder

## 3.1 结构（冻结版）

假设雷达帧率 20fps，chunk = 8 帧（0.4s），不重叠滑窗，chunk 率 2.5Hz。

```text
                    一个 chunk
                       │
        ┌──────────────┴──────────────┐
        ↓                             ↓
    RD Frames                     Point Frames
        │                             │
   2D CNN Encoder              Point Transformer Lite
   (32→64→128→256,             (6→64→128, 2~3层局部注意力,
    Conv3×3-BN-GELU-Down)×4     显式相对位置 p_i−p_j)
        │                             │
   2个 learnable pooling queries   2个 learnable pooling queries
        │                             │
   Causal TCN ×4                 Causal TCN ×4
   (dilation 1,2,4,8,            (dilation 1,2,4,8,
    depthwise+pointwise+GELU+残差)  同左)
        │                             │
    2 RD tokens                   2 PC tokens
        └──────────────┬──────────────┘
                       │
              modality + time embedding
                       │
               Transformer × 2
                       │
              F_t ∈ R^{4×256}
```

要点：

- **两个分支各用 2 个 learnable pooling queries** 读出 token（偏全局/偏局部的分化交给训练，不人为规定）；不做全局平均池化压成单向量——Event Tokens 需要读取不同粒度的雷达信息；
- **L=4 是与毫米波信息密度匹配的选择**：不是 1（损失粒度），也不需要 32；
- **Causal TCN 做成 stateful**：跨 chunk 缓存隐状态，在线推理不重算历史帧——CNN/Point Transformer 回答"这一帧看到什么"，TCN 回答"最近这段运动怎么变化"；
- 点云分支第一版可用 PointNet（共享 MLP + max-pool）跑通管线，Stage 1 的 pose 误差下不来再升级为 Point Transformer Lite；
- F_t 保持 256 维，**不预投影到 LLM 空间**（cross-attention 的 W_K/W_V 完成映射）。

## 3.2 事件内特征缓冲区

有界缓冲区仅缓存当前活跃事件（fork 后含 Candidate 段）的 F_t（4×256，极小）；容量按最长预期事件（约 60s，150 chunks）设计；confirm 定稿后立即释放。

## 3.3 Stage 1 预训练（刻意从简）

$$H_t = \text{Pool}(F_t) \in \mathbb{R}^{256} \xrightarrow{\text{Pose Head } 256→512→J×3} \text{3D skeleton}$$

$$L_{pose} = L_{MPJPE} + \lambda_v L_{velocity},\quad L_{velocity} = \|\Delta\hat S_t - \Delta S_t\|_1$$

MPJPE 教"人体结构在哪里"，velocity loss 教"人体怎么动"。**Stage 1 完成后整个 Pose Head 删除**，不维护复杂 skeleton teacher——本阶段只是给雷达表示注入人体运动先验。推理时仅需毫米波。

# 四、变化检测前端（模块②③ + Proposal）

## 4.1 ② Local Change Detector

在 encoder 输出的 4 个 radar tokens 上逐 token 构造差异（先 LayerNorm）：

$$D_t = [\bar F_t - \bar F_{t-1},\ |\bar F_t - \bar F_{t-1}|,\ \bar F_t \odot \bar F_{t-1}] \in \mathbb{R}^{4×768}$$

```text
Linear 768→128 → GELU → Attention Pooling（跨4个token）→ Linear 128→64→1 → sigmoid
```

输出 s^local。**不使用 Transformer**：它的功能只是"这里突然发生了一点变化"，越复杂越容易被训练成另一个动作分类器。特性：高敏感、高召回、易误报；参照系是"刚刚的过去"，输出为瞬态脉冲。

## 4.2 ③ Radar Transition Detector（128 维原型空间）

不在高维空间维护原型，建立专用 **Motion Prototype Space**：

$$r_t = \text{MLP}_{256→128}(\text{Pool}(F_t)),\quad r_t \leftarrow r_t/\|r_t\|$$

```text
R_fast：EMA，α=0.9（"现在是什么样"）
R_slow：Welford running mean + variance，confirm 锚定重置（"本事件本来是什么样"）
δ_t = (R_fast − R_slow) / √(σ² + ε)     # z-score 化偏差，方差自适应
Z_t = [R_fast, R_slow, |δ_t|, R_fast⊙R_slow, 1−cos(R_fast,R_slow), age]
      → MLP(128×4+2 → 128 → 32 → 1) → s^radar
```

- **confirm 锚定重置**：confirm 为 R_slow 提供事件起点锚点，消除跨事件污染；
- **R^C 接管**：Candidate 跟踪期间同步维护自身原型统计（从 t_p 开始累积），confirm 时 R_new^A = R^C，与 E_new^A = E^C 对称，消除预热空窗；
- **age 特征**（事件已持续的归一化时长）使 head 显式感知事件年龄，与预热屏蔽互补；
- 该 head 学的是"当前短期运动分布是否偏离本事件长期统计"，而非动作分类。

## 4.3 Proposal：noisy-OR（不训练网络）

$$p^{proposal} = 1 - (1 - s^{local})(1 - s^{radar})$$

任一证据强即允许 proposal；p^proposal > τ_p 且持续 1~2 个 chunk 即启动 Candidate。定位是**高召回、不求精确**，不值得训练第三个 MLP。

## 4.4 两检测器分工与消融

| 维度 | Local Change | Radar Transition |
| --- | --- | --- |
| 参照系 | 刚刚的过去（相邻 chunk） | 整个事件（累积原型） |
| 时间特性 | 瞬态脉冲（触发时机定位） | 持续电平（持续偏移证据） |
| 特征粒度 | 逐 token 差分（细粒度） | 池化原型统计（整体状态） |
| 缓慢渐变转换 | 漏检 | **可检**（R_slow 不随漂移） |
| 短暂扰动 | 高响应 | 低/中响应 |

保留双模块；"仅 Radar / 仅 Local / 两者联合"列为 Stage 3 正式消融。

# 五、Streaming Semantic Event Former（模块④⑤，核心网络）

## 5.1 基本约定

- **K=8** 个 Event Tokens，E_t ∈ R^{8×d_LLM}；新事件 E_0 = P_base（全局训练的可学习 prompt）；
- **空间约定**：所有 Event Tokens 一律在 embedding 空间存储流转；层 1-4 输出经 W_out 投回 embedding 空间后才参与状态更新；W_out = **Linear(d→d)，identity 初始化**（不加复杂 MLP，数值异常时再加 LayerNorm）；
- **Prefix-LM mask（关键细节）**：Instruction tokens 区域保持正常 causal；**8 个 Event Tokens 之间双向全连接**——它们是并列的 memory slots 而非一句话，因果 mask 会造成信息不对称；
- Instruction Tokens 的各层 K/V 会话开始时缓存一次，之后每 chunk 复用；
- 层 1-4：主干冻结 + LoRA（q,v，rank 16）；cross-attention tanh 门控、门初值 0。

## 5.2 层内结构（层 1-4，每层）

```text
Event Tokens
     │
  native self-attention（Prefix-LM mask）     ← 冻结 + LoRA
     │
  Radar Cross-Attention：Q = Event Tokens，K,V = W_K F_t, W_V F_t
     │
  H ← H + tanh(α_l) ⊙ CrossAttn_out           ← α_l 初值 0，每层独立
     │
  native FFN                                   ← 冻结
```

Cross-attention 只对 Event Tokens 计算（Instruction Tokens 不过，省算力且更干净）。每层 cross-attn 约 50M 参数（Q/K/V/O 四个 256↔3584 投影），4 层合计约 200M，是全系统最大新增参数块；第一个瘦身消融为"只在第 2、4 层插入"。

## 5.3 跨 chunk 门控更新（逐 token 标量门）

前四层输出 H_t⁴，经 W_out 得 Ê_t，构造 ΔE_t = Ê_t − E_{t−1}。**每个 Event Token 独立生成一个标量门**：

$$\lambda_{t,k} = \text{MLP}([LN(E_{t-1,k});\ LN(\Delta E_{t,k});\ maturity_t]) \in \mathbb{R}$$

$$E_{t,k} = E_{t-1,k} + \tanh(\lambda_{t,k})\,\Delta E_{t,k}$$

8 个 token 各自决定本 chunk 更新多少；不使用 d 维向量门（参数多、难解释、易过拟合）。调试期绘制 ‖E_t‖ 随 chunk 变化曲线作诊断。

## 5.4 Candidate 规则

- 与 Active **100% 参数共享**——"两个假设用同一个语义模型竞争"；区别仅在于 E_A 从事件起点累积，E_C = P_base 从 t_p 起点累积；
- **并发规则：同一时刻最多一个 Candidate**；新 proposal 仅在当前 Candidate 被 Reject 后受理（对快速连续动作的召回牺牲在实验中如实报告）；
- 可选增强：Candidate 只读记忆支路（C_t = CrossAttn(E^C, M_L0, M_L0)，不进门控更新、不进 p_diff/s_stable、门初值 0）；最小实现为仅推理路径读 Level-0。

## 5.5 Semantic Projection Head 与 Difference Head

**Projection Head（共享）**：

```text
learnable semantic query q_s → Attention(q_s, E, E) → h_E
→ Linear(d→256) → GELU → Linear(256→128) → L2 Normalize → z_E ∈ R^128
```

z_A、z_C 来自同一个 Projection Head。

**Difference Head**：

```text
D = [z_A, z_C, |z_A−z_C|, z_A⊙z_C, 1−cos(z_A,z_C), maturity]  ≈ 514维
→ Linear 514→256 → GELU → Dropout(0.1) → Linear 256→64 → GELU → Linear 64→1 → p^diff
```

**成熟度增广（保留 v2.0 核心对策）**：z_A 为成熟态、z_C 为新生态，训练对必须覆盖成熟度维度，否则 head 学到"新旧之别"而非"语义之别"：

| pair | 标签 |
| --- | --- |
| z_mature(A) vs z_nascent(A 前缀，前 k=1~5 chunks) | same（核心） |
| z_mature(A) vs z_mature(A 另一片段) | same |
| z_mature(A) vs z_nascent(B 前缀) | different |
| z_mature(A) vs z_mature(B) | different |

辅以：maturity 标量显式输入（已含）；Candidate 启动后前 1~2 个 chunk 预热屏蔽（不算 p_diff）。训练目标为 same/different 二分类，无需固定类别标签，适配开放语义场景。

## 5.6 Candidate Stability（3-chunk 窗口版）

单帧 cos(z_{C,t}, z_{C,t−1}) 太弱——尚未形成语义的 Candidate 也可能连续两帧几乎不变。改看最近 3 个 chunk：

$$V_t = [\cos(z_t,z_{t-1}),\ \cos(z_t,z_{t-2}),\ \|z_t - z_{t-1}\|,\ \text{Var}(z_{t-2:t}),\ maturity]$$

```text
MLP(5→32→1) → s^stable
```

判断的不是"是什么动作"，而是"这个 Candidate 最近是否已收敛成稳定语义"。

# 六、模块⑥：Transition Decision

## 6.1 单调 Logistic Head + 时间迟滞

$$p_t^{trans} = \sigma(w_1 s^{local} + w_2 s^{radar} + w_3 p^{diff} + w_4 s^{stable} + b),\quad w_i = \text{softplus}(\hat w_i) \geq 0$$

单调性约束给出可写的归纳偏置：**任何一种转换证据变强，都不会反而降低转换概率**。

判决规则（显式操作化）：

- **Confirm**：p^trans > τ_c 且连续 2 个 chunk 成立；
- **Reject**：Candidate 已运行 1.5~2s 且持续 p^diff < τ_r。

循环依赖防护不变：R_slow 重建初期（约 1s）s^radar 降权，此间判决由 p_diff、s_stable 承担。

## 6.2 Confirm 六动作

1. E_new^A = E^C；R_new^A = R^C（语义与物理原型同步接管）；
2. 旧 Active 缓冲区 F_{t0:t_p} 经 Commit Refiner 定稿（见 6.3），E_commit 入库；
3. 时间戳：新事件 t_start = t_p（回溯至 proposal 触发时刻），旧事件 t_end = t_p；记录 t_confirm 用于延迟统计；
4. 生成 y_i（见 9.1）；
5. 旧事件雷达通道永久关闭，缓冲区释放；
6. R_slow 以 R^C 为起点继续累积（无预热空窗）。

## 6.3 Commit Refiner（复用 Event Former，不新增网络）

平时 streaming 是 E_{t−1} \xrightarrow{F_t} E_t；commit 时同一套参数执行：

$$P_{base} \xrightarrow{[F_1, F_2, \dots, F_T] \text{ 一次性可见}} E_{commit}$$

区别仅在 cross-attention 的可见范围：streaming 每步只见当前 chunk（因果实时）；commit 一次见整个事件（定稿允许用事件内完整信息）。**参数完全共享**。事件过长时先将 event buffer 时间池化到最多 256 个 radar tokens。

# 七、Idle / Presence 控制器（物理化，不深度学习化）

输入四统计量：

$$x_t = [N_{points},\ E_{RD},\ E_{dynamic},\ tracker\ confidence]$$

标准化后经 p^presence = σ(w^T x + b)，双阈值迟滞（τ_enter > τ_exit）：

```text
Idle   ── p > τ_enter ──→ Active
Active ── p < τ_exit 持续 N chunks ──→ Idle
```

**关键警告：静止站立 ≠ Idle**——不能只看 Doppler/动态能量，必须同时考虑人体 ROI 总能量、点数与 tracking confidence。Idle 控制器保持独立规则系统，不与 LLM 纠缠。

状态规则（与 v2.0 一致）：Idle 期间 Active 冻结不更新、不触发新 proposal、在途 Candidate 丢弃；人走出视场时 Active 以低置信度 partial commit；中断 < 2s 恢复原 Active，否则从 P_base 开新事件。

# 八、模块⑦：Hierarchical Event Memory

## 8.1 记忆单元

$$M_i = \{E_i,\ T_i,\ c_i,\ k_i,\ y_i\}$$

- E_i：Event Semantic Tokens（embedding 空间，8×d）——记忆内容本体；
- T_i = (t_start, t_end, t_confirm)：t_start 为回溯的 proposal 触发时刻；
- c_i：置信度（partial 事件降低）；
- **k_i = z_{E_i}：入库时顺手存储的 128 维检索键**（见 8.4）；
- y_i：commit 时完整 LLM 生成的文本描述。

原则不变：Token 是记忆内容；Text + Time + Confidence 是 metadata。

## 8.2 三级结构与 Query Compressor

```text
Level 0：最近 8 个完整事件（tokens + metadata）
   ↓ 满后，最旧 2~3 个时间相邻事件
Query Compressor → Level 1：Event Group 摘要（24 tokens → 4 tokens）
   ↓ 继续变旧
Query Compressor → Level 2：长期行为摘要
```

**Compressor 结构（冻结）**：标准 Transformer Decoder × 2；4 个可学习 Summary Queries；输入事件 tokens 加 Event Position Embedding + Token Position Embedding + **Time Embedding**；两级压缩**共享同一套参数**，另加 level embedding（e_{L0→L1} / e_{L1→L2}）告知当前压缩级别。

压缩触发附加条件不变：语义高度雷同的连续事件组不压缩，直接按合并规则去重。

训练（Stage 4）：前端全冻结，L_memory = L_summary + λL_retain（摘要文本生成损失 + 语义保持余弦损失）；Summary 目标文本只覆盖被压缩事件，模型自然学会摘要 tokens 与 Level-0 tokens 的时间分工。

## 8.3 同类事件合并规则（粒度控制）

合并在记忆写入层执行（事后簿记，不进实时判决路径）：

```text
IF  y_prev 与 y_new 文本标签匹配
AND (t_start^new − t_end^prev) < τ_gap（2~3s，粒度旋钮，消融参数）
AND 间隔期间无其他已确认事件（仅 idle/停顿）
THEN tokens 经 Compressor 合并为单组；T 合并；c 取 min；
     文本由 LLM 读合并 tokens 重新生成（禁止字符串拼接）；
     合并单元 metadata 记录发生次数 count（保留频率信息，供"起身三次"类叙述）
```

## 8.4 检索（统一语义空间）

复用 Semantic Projection 空间，**不再单独训练检索编码器**：

$$s_i = \underbrace{\cos(z_q,\ k_i)}_{\text{语义}} + \beta\underbrace{\exp(-\Delta t_i/\tau)}_{\text{时间衰减}} + \gamma\underbrace{c_i}_{\text{置信度}}$$

其中 z_q 由 Stage 2 的 Text Encoder 编码查询文本得到。Level 0 全读不检索；Level 1/2 按 s_i 取 Top-k（如 Top-2 / Top-1）。

**前置验证要求**：z 空间由 same/different 损失训练，"可分"不必然"与文本对齐"——先用检索探针实验（12.3）实测；若命中率不足，再给 z 加一个小对齐损失。

## 8.5 溢出与隔离

Level 2 溢出 FIFO（或 future work 再压缩一级）；**Memory 不参与 Transition Decision**（架构硬约束：记忆支路不进门控更新、不进 p_diff/s_stable）。

# 九、LLM 推理路径

- y_i 在 commit 时由完整 LLM 对 E_commit 生成（每事件一次）；
- 查询/总结时输入带显式叙述结构标记：[History Summary Tokens (Level 1/2)] → [Recent Event Tokens (Level 0)] → [Current Event Tokens]；
- 流式主动叙述（如需要）：维护"已叙述到事件 #k"指针，只对新 commit 事件增量生成；
- 幻觉监控：检查生成 token 对 event tokens 的注意力权重，接近均匀/接近零即在"瞎编"，需加强 L_align 或减小 LoRA 自由度。

# 十、训练流程

| 阶段 | 核心目标 | 训练模块 | 冻结策略 | 成本 |
| --- | --- | --- | --- | --- |
| Stage 1 | 雷达运动表示 | Radar Encoder（+临时 Pose Head） | — | 中 |
| Stage 2 | 雷达→语言事件语义 | 层1-4 LoRA + cross-attn + W_out + 标量门 | LLM 主干冻结 | 中 |
| Stage 3 | 连续事件转换判决 | 全部轻量 head + 事件状态小 LR | Encoder 基本冻结 | 低 |
| Stage 4 | 事件压缩与检索 | Query Compressor | 前端全冻结 | 低 |
| Stage 5（可选） | 联合微调 | Event Former、heads、Compressor | Encoder 冻结/极低 LR | 中 |

论文呈现合并叙述为三阶段（表示+对齐 / 流式判决 / 记忆压缩）。

**Stage 2 为 go/no-go 裁决点**：L_stage2 = L_text + λL_align（L_align 的 Text Encoder 使用冻结 LLM 自身 embedding 层 mean-pooling，保证对齐目标、检索空间、探针实验三者语义几何闭合）；完成层数消融（2/4/8）× 描述质量 × 探针准确率对照表；多指令增广迫使 E_t 任务无关；消融"流式路径去 instruction vs 保留"。不达标按补救阶梯升级（K 扩容 → 精修重编码已在架构内 → 层数加深 → 独立编码器）。

**Stage 3**：L_stage3 = λ₁L_local + λ₂L_radar + λ₃L_semantic + λ₄L_transition；容差区间边界标签转为逐 chunk 高斯软标签（区间中心为均值、宽度为标准差）；Semantic head 用 2×2 成熟度增广训练对；完成检测器冗余消融。

**Stage 4**：摘要文本由标注管线合成；Compressor 两级共享训练（level embedding 区分）。

# 十一、数据集建设（自建）

1. **自然过渡**：禁止"演完 A 停一下再演 B"，过渡段是三类证据信号的关键学习材料；
2. **容差边界标注**：区间标注（如 8.0~8.5s），与 Semantic Event Consistency 立场自洽；
3. **显式收录无人/静止站立/出入视场片段**（Idle 控制器与 Stage 3 负样本依赖；静止站立片段用于校验"静止≠Idle"）；
4. **同步录制 RGB 或 3D 骨架**：Stage 1 监督与文本标注载体；
5. **泛化划分从第一天定**：leave-one-subject-out + 跨房间/雷达位姿，结果进论文主表；
6. **文本标注管线**：RGB → 视频理解模型初标单事件 caption → 人工校对 → LLM 合成多事件摘要 → 人工抽检。

# 十二、评估体系

## 12.1 四层指标

| 层面 | 指标 |
| --- | --- |
| Event Detection | Boundary F1、**Over-segmentation Rate**（重点）、欠分割率、最小可检测事件时长（规格报告） |
| Semantic Event | same/different accuracy、事件语义纯度 |
| Language | BLEU/ROUGE/CIDEr + 结构化叙事指标（12.2） |
| Streaming | **Transition Latency**、输出延迟、长流稳定性、Memory 压缩效果、**延迟预算表**（各模块每 chunk FLOPs/ms、LLM 触发频率、目标硬件） |

## 12.2 结构化叙事指标（任务评价贡献）

生成文本经 LLM/规则解析回结构化事件序列 [(动作, 顺序, 时间)]，计算：

- **Event Order Accuracy**：与 GT 的 Kendall tau / LCS——抓顺序错乱（"摔倒后站起来"vs"站起来后摔倒"，BLEU 失明）；
- **Event Coverage / Hallucination**：GT 提及率、提及真实率——抓漏报/编造；
- **Temporal Localization Error**：提及事件 T_i 与 GT 边界偏差。

训练侧第一阶段仅用正确结构目标 + 语言建模损失隐式监督；可微增强（乱序对比、逐事件探针、时间回归头）与 RL 奖励微调列为后续可选。

## 12.3 探针实验（核心宣称的必需证据）

1. **语义探针**：仅用记忆库 E_i，线性分类器恢复动作类别；
2. **检索探针**：文本查询从记忆库检索事件的命中率（同时裁决 8.4 节的 z 空间对齐问题）。

## 12.4 Baseline 与消融

Baseline 自建：滑窗+离线识别+逐窗 caption 流水线（下界）；视频流式理解方法迁移对比。消融清单：层数（2/4/8）、K（4/8/16/32）、L（radar tokens 数）、τ_gap、检测器配置、记忆层级数、合并规则、门控形式（标量/向量）、W_out 形式。

# 十三、创新点与论文定位

**一句话 claim**：一个统一表示（Event Semantic Tokens）同时承担四个角色——流式理解的状态、边界判决的基底、分层记忆的单元、LLM 推理的输入。

三个创新点：①Prompt-as-episodic-memory（语言对齐 token 作为情景记忆单元，存于 LLM 原生 embedding 空间，可直接被检索、推理、复述）；②面向雷达流的在线语义完备性判决（Active/Candidate 双假设 + same/different 开放判决 + Fork-and-Replay）；③多粒度分层事件记忆（Query Compressor 以 LLM 摘要损失训练）。

**EST 理论映射**写入 Introduction：Event model ↔ Active State（门控防污染）；prediction error 瞬增 ↔ Local/Radar 检测；释放旧模型构建新模型 ↔ Candidate 从 P_base 启动；边界是更新副产品 ↔ Confirm。注意划界：EST 计算化实现已有先例，本文创新在于事件模型首次以语言对齐可学习 token 形式存在。

**相关工作区分**：雷达+LLM 离线理解（片段级、无流式无记忆）；雷达-语言驾驶场景模型（离线、非人体行为）；传统连续雷达分割（无 LLM 无语言输出）；流式视频 LLM（帧级 KV 压缩记忆，非事件级语义 token）；HEM（query 驱动事件记忆，无 LLM）；HoloLLM 类固定 query 吸收 sensor 特征的工作（**其 query 是一次性编码，本方案的 Event Tokens 是跨时间持续更新的状态**——这是关键区分点）。措辞用 "To the best of our knowledge..."，**投稿前重新检索一次**。

**隐私卖点**：commit 后原始雷达特征即焚，长期保存的只有抽象语义 token 与文本，全链路无可识别原始信息。
