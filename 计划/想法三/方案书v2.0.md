# 一、任务目标与问题定义

## 1.1 任务设定

面向**单人室内连续毫米波人体行为理解**。输入不是预分割的单动作片段，而是持续到来的毫米波雷达流；系统需要在线理解"当前人在做什么"，在动作语义发生转换时形成事件，并最终生成按时间顺序组织的自然语言描述。

本方案不以"精确到帧的动作边界"为核心目标。需要解决的三个问题是：

1. 连续雷达流中什么时候可能发生动作变化；
2. 当前语义是否已经从原事件转变为新事件；
3. 如何把已完成的事件长期保存，使后续 LLM 能够理解完整行为历史。

## 1.2 核心思想

传统范式：

```text
Radar → 精确动作分割 → 每段独立识别 → LLM
```

本方案：

```text
Radar Stream
      ↓
持续形成当前事件语义（Active Semantic Event State）
      ↓
检测局部/物理变化（两类前端证据）
      ↓
建立 Candidate 语义假设
      ↓
判断 Candidate 是否真正不同于 Active
      ↓
确认事件转换 → 事件定稿入库
      ↓
Hierarchical Event Memory
      ↓
LLM 连续行为描述与推理
```

即：**在持续理解过程中形成事件**，而不是先切事件再理解事件。

## 1.3 三条设计原则

1. **Token 是信息的唯一货币**：所有雷达信息必须在事件 commit 前蒸馏进 Event Semantic Tokens；commit 后原始雷达特征即被丢弃，LLM 深层永远不接触雷达原始特征。
2. **语义事件一致性优先于帧级边界精度**：接受 0.5~1s 量级的实时确认延迟，换取不过度分割、语义纯净的事件序列。
3. **Propose-and-Verify 分工**：前端轻量检测器高召回地提出变化假设（宁可多报），语义层负责验证与拒绝（严格把关）。

# 二、总体架构

## 2.1 七模块结构

```text
Continuous mmWave
       │
       ↓
① Streaming Radar Encoder
       │
       ├────────────→ ② Local Change Detector ──────────┐
       │                                                │
       └────────────→ ③ Radar Transition Detector ──────┤
                                                        │
Instruction Tokens                                      │
       ↓                                                │
④ Active Semantic Event State                           │
       │                                                │
       └──── candidate triggered                        │
                    ↓                                   │
⑤ Candidate Event State + Parallel Tracking             │
                    │                                   │
                    └── Semantic Difference/Stability ──┤
                                                        ↓
                                         ⑥ Transition Decision
                                                  │
                                      ┌───────────┴───────────┐
                                    Reject                  Confirm
                                      │                       │
                              Active继续更新           Active → Memory
                                                              │
                                                       Candidate接管
                                                              │
                                                              ↓
                                               ⑦ Hierarchical Event Memory
```

②、③、⑤分别产生三类核心证据：**Local Change + Radar Transition + Semantic Transition**，由⑥联合判决。另有贯穿全程的 **Idle/Presence 控制器**（见第七章）。

## 2.2 双路径计算框架（关键架构决策）

整个系统的计算分为两条路径，**共享同一套 LLM 权重，区别仅在于"雷达 KV 是否在场"**：

|  | 流式路径（Streaming Path） | 推理路径（Reasoning Path） |
| --- | --- | --- |
| 运行频率 | 每 chunk（2~5 Hz） | 每事件 commit + 每次用户查询 |
| 涉及结构 | LLM 层 1-4（含 gated cross-attention）+ 全部轻量 head | 完整 LLM（全部层） |
| 输入 | 当前 chunk 雷达特征 F_t、Instruction Tokens、Event Tokens | Event Tokens、记忆 Tokens、Instruction/查询 |
| 雷达注入 | **是（仅层 1-4）** | **否（只读 token）** |
| 职责 | 增量维护 E_t；运行 Local/Radar/Semantic 三个判决 head | 生成事件描述 y_i；长程推理与问答 |

### 为什么雷达只在层 1-4 注入

分层记忆体系决定了：事件一旦 commit，原始雷达特征即被丢弃，Level 0/1/2 记忆中只有 token。如果完整 LLM 的深层可以通过 cross-attention 回查雷达 KV，则：

1. 当前事件的理解会绕过 token 直达原始特征，而历史事件无雷达可读——架构层面内置**近因偏差**；
2. 训练压力被雷达旁路分流，E_t 的信息承载能力退化，token 的"唯一货币"地位被动摇。

因此：**全部跨模态融合被强制发生在层 1-4（编码器角色），全部语义推理发生在 token 空间（层 5-28 及完整前向）**。功能上，层 1-4 + cross-attention 扮演 Q-Former 的角色，只是借用 LLM 自身的前 4 层权重实现；从层 5-28 与记忆系统的视角看，雷达信息以 embedding 空间 token 的形态"在输入端"进入。

### 信息瓶颈的补救阶梯（按优先级）

若 Stage 2 实验证明 K 个 token 信息容量不足：

1. **增大 K**（4~8 → 16~32）：成本最低，架构不变；
2. **commit 时刻精修重编码**（见 5.2 节）：利用事件内非因果性提升 E 质量；
3. **深层注入（最后手段，作为 Stage 2.5 引入）**：仅在第 12/18/24 层等中部偏后位置加 tanh 门控 cross-attention（初值 0），KV 仅限当前事件雷达特征，且必须附带"屏蔽深层注入、仅用 token 完成长历史问答"的对照实验，证明记忆推理不依赖雷达旁路。

## 2.3 事件生命周期

```text
事件进行中（流式路径，每 chunk）
   雷达特征 F_t ──注入──→ LLM 层 1-4（gated cross-attn）
                            │
                            ↓
                     增量更新 E_t（embedding 空间）
                            │
                     三个轻量 head 持续判决
                            │
事件 commit ───────────────┘
   ① 精修重编码（用缓冲区中整个事件的 F 做事件内非因果重编码）→ E_commit
   ② E_commit 入库；生成 y_i
   ③ 该事件的雷达通道永久关闭，缓冲区释放
   ④ Candidate 接管为新 Active（E_new^A = E^C，R_new^A = R^C）
```

雷达通道是**按事件开关**的：旧事件通道关闭时，新事件通道早已打开（Candidate 从 proposal 触发点起就在吸收雷达），持续到来的雷达流不存在无人接收的空窗。

# 三、模块①：Streaming Radar Encoder

## 3.1 结构

```text
Continuous mmWave
        │
   ┌────┴─────────┐
   ↓              ↓
Range-Doppler   Point Cloud
   ↓              ↓
RD Encoder     Point Encoder
   ↓              ↓
Causal TCN     Causal TCN
   └──────┬───────┘
          ↓
     Fusion / Projection
          ↓
         F_t ∈ R^{L×d}
```

- 以短 chunk（若干连续雷达帧）为一次实时更新单位；
- 全部时间建模采用 causal 结构：F_t = f(X_{1:t})，推理时不可见未来；
- 本模块只负责获得稳定的运动表示，不直接决定动作边界。

## 3.2 事件内特征缓冲区

为支持 commit 时刻的精修重编码，维护一个**有界缓冲区**，仅缓存当前活跃事件（及 Candidate）的 F_t：

- 容量按最长预期事件（如 60s）设计，chunk 特征 L×d 量级下内存占用可控；
- 事件 commit 后立即释放；旧事件的缓冲区不保留。

## 3.3 预训练（Stage 1）

以同步 3D 骨架为主要辅助监督，使毫米波表示学到人体运动结构；推理时移除骨架，仅用毫米波。可复用现有毫米波表示学习成果作为初始化。

# 四、变化检测前端（模块②③）

## 4.1 ② Local Change Detector

发现很短时间尺度上的突然变化。比较相邻 chunk：

$$
D_t = [F_t - F_{t-1},\ |F_t - F_{t-1}|,\ 1-\cos(F_t, F_{t-1})]
$$

经轻量 1D Conv/MLP 输出：

$$
s_t^{local} = \sigma(f_{local}(D_t)) \in [0,1]
$$

特性：**高敏感、高召回、易误报**——本身不能决定事件切换。参照系是"刚刚的过去"，输出为**瞬态脉冲**（仅在变化发生的瞬间响应）。

## 4.2 ③ Radar Transition Detector（双时间尺度版）

回答："当前的物理运动状态，是否已经偏离**本事件**的典型运动模式？"

### 双时间尺度原型

固定窗口 EMA 存在两难：窗口短则原型跟随漂移、缓慢转换漏检；窗口长则跨事件污染、事件初期误报。因此采用双时间尺度设计（CUSUM 式变化检测）：

```text
R_slow：仅在当前事件生命周期内累积的运行均值
        （confirm 时刻清零；语义 = "本事件本来是什么样"）
R_fast：短窗 EMA（α ≈ 0.9，有效窗口约 2s）
        （语义 = "现在是什么样"）

s^radar = f( distance(R_fast, R_slow) )
```

距离构造：

$$
Z_t = [R_{slow},\ R_{fast},\ |R_{fast}-R_{slow}|,\ 1-\cos(R_{fast}, R_{slow})]
$$

$$
s_t^{radar} = \sigma(f_{radar}(Z_t))
$$

### 关键机制

1. **confirm 锚定重置**：confirm 信号为 R_slow 提供"本事件从哪一刻开始"的锚点，消除跨事件污染；
2. **原型随 Candidate 接管**：Candidate 跟踪期间同步维护自身原型 R^C（从 proposal 触发时刻开始累积），confirm 时执行 R_new^A = R^C，与 E_new^A = E^C 对称，消除重置后的预热空窗；
3. **预热屏蔽**：新事件前约 1s 内 R_slow 样本不足，s^radar 屏蔽或降权，此间判决由 p_diff、s_stable 承担；
4. **方差自适应**：同时维护 running variance，偏差除以标准差形成 z-score，使高波动事件（walking）与低波动事件（站立）共用同一灵敏度基准。

### 与 Local Change 的分工

| 维度 | Local Change | Radar Transition |
| --- | --- | --- |
| 参照系 | 刚刚的过去（相邻 chunk） | 整个事件（累积原型） |
| 时间特性 | 瞬态脉冲 | 持续电平 |
| 特征粒度 | 原始特征差分（细粒度） | 池化窗口统计（整体状态） |
| 角色 | 触发时机定位（发令枪） | 持续偏移证据（耐力证人） |
| 缓慢渐变转换 | 漏检 | **可检**（R_slow 不随漂移） |
| 短暂扰动（甩手臂） | 高响应 | 低/中响应 |

两者有部分功能重叠，保留双模块；将"仅 Radar Transition / 仅 Local Change / 两者联合"列为 Stage 3 的正式消融实验，以数据裁决是否可简化。

# 五、语义事件状态（模块④⑤）

## 5.1 基本约定

- Instruction Tokens：普通文本 token（默认通用指令，如 "describe the ongoing action"），非可学习 prompt；其各层 K/V 在会话开始时缓存一次，之后每 chunk 复用；
- Learnable Event Prompt：全局训练得到的一组可学习 token，P_base ∈ R^{K×d}，K = 4~8（信息不足时按补救阶梯增大）；
- **空间约定（关键）**：所有 Event Tokens 一律在 **embedding 空间**存储和流转。层 1-4 输出的 h⁴ 经输出投影 W_out 投回 embedding 空间后才参与状态更新——保证记忆单元、Compressor、检索、LLM 输入全部统一在同一空间，由端到端训练（梯度穿过冻结 LLM 回流）保证空间匹配；
- 层 1-4 参数策略：主干冻结 + LoRA；cross-attention 采用 tanh 门控（门初值 0，Flamingo 式初始化），训练初期等价恒等映射，保护预训练表示。

## 5.2 流式更新（每 chunk）

```text
Instruction Tokens(KV已缓存) + Event Tokens
        → LLM 层 1-4（self-attn + gated cross-attn，Q=Event Tokens，KV=F_t）
        → W_out 投影回 embedding 空间
        → 门控残差更新 E_t
```

更新公式采用 **tanh 门控残差形式**（替代凸组合，避免范数随事件时长漂移导致门控系统性偏移）：

$$
E_t = E_{t-1} + \tanh(\lambda_t)\odot \Delta E_t,\quad \lambda_t = W_\lambda[E_{t-1};\Delta E_t],\ \lambda_{init}\equiv 0
$$

调试期需绘制 ‖E_t‖ 随 chunk 的变化曲线作为诊断（持续衰减或爆炸均为异常）。

## 5.3 新事件启动与 Candidate 规则

- 新事件开始时 E_0^A = P_base；
- Candidate **必须从干净的 P_base 初始化**（禁止 E_0^C = E_t^A），防止旧动作语义污染新动作；
- **并发规则：同一时刻最多一个 Candidate**；新 proposal 仅在当前 Candidate 被 Reject 后受理。承认此规则对快速连续动作（A→B→C 三连）的召回有牺牲，需在实验中报告；
- 启动条件：p_t^proposal = f(s_t^local, s_t^radar) > τ_p 且持续若干 chunk；阈值偏低（高召回），语义层负责 Reject。

### Candidate 只读记忆支路（可选增强）

动机：部分动作语义依赖历史（"走过去坐下" vs "走回来坐下"）。最小实现为仅在 commit 后的推理路径读取 Level-0（默认方案）；增强实现为流式路径中增加只读支路 C_t = CrossAttn(E^C, M_L0, M_L0)，须满足三条架构硬约束：

1. C_t 不进入门控残差更新（状态演化只由雷达驱动）；
2. C_t 不进入 p_diff 与 s_stable 的计算（边界判决严格无记忆）；
3. 记忆注意力加可学习门（初值 0）。

训练需"历史依赖型描述"数据（同一段雷达因历史不同而 caption 不同的序列对）。

## 5.4 Semantic Change Head（成熟度增广版）

### 问题：成熟度混淆

z_A 是经长期累积的"成熟态"，z_C 是刚从 P_base 出发的"新生态"——即使语义相同，两者在 embedding 空间也天然距离很远。若训练对全部由成熟态构成，head 会学到"新旧之别"而非"语义之别"，导致每次 Candidate 启动都误判 different → 虚假 confirm → 过度分割。

### 对策一：2×2 训练对（语义 × 成熟度）

用 Stage 2 单动作数据构造两种状态：成熟态（从 P_base 跑完整片段）与新生态（从 P_base 只跑前 k 个 chunk，k 随机取 1~5）：

| pair | 标签 |
| --- | --- |
| z_mature(A) vs z_nascent(A 的前缀) | same（核心：教 head 对成熟度不变） |
| z_mature(A) vs z_mature(A 的另一片段) | same |
| z_mature(A) vs z_nascent(B 的前缀) | different |
| z_mature(A) vs z_mature(B) | different |

### 对策二：成熟度显式输入

将 Candidate 已吸收的 chunk 数（或归一化证据量）作为标量特征加入 f_sem 输入，使 head 可条件化于成熟度做判断。

### 对策三：预热屏蔽

Candidate 启动后前 1~2 个 chunk 不计算 p_diff（此时 z_C 必然接近 P_base，无信息量）。与 s_stable 互补：稳定性管"判得太早"，预热屏蔽管"看得太早"。

### Head 结构

共享 Semantic Projection Head：Event Tokens → Attention Pooling → 2-layer MLP → z。构造：

$$
D_{sem} = [z_A, z_C, |z_A - z_C|, z_A \odot z_C, 1-\cos(z_A, z_C), maturity]
$$

$$
p_t^{diff} = \sigma(f_{sem}(D_{sem}))
$$

训练目标为 **same event / different event 二分类**，不需要固定类别标签，适配开放语义场景。

## 5.5 Candidate Stability

$$
s_t^{stable} = \cos(z_{C,t}, z_{C,t-1})\quad\text{或}\quad s_t^{stable} = f_{stable}(z_{C,t-k:t})
$$

语义：Candidate 已持续形成一个与 Active 不同的新运动语义——不要求动作 B 完成，不要求等到下一个动作出现。

# 六、模块⑥：Transition Decision

## 6.1 判决输入

$$
u_t = [s_t^{local},\ s_t^{radar},\ p_t^{diff},\ s_t^{stable}],\quad p_t^{trans} = \sigma(f_{trans}(u_t))
$$

注意循环依赖防护：s^radar 依赖 confirm 锚定的 R_slow，confirm 又依赖 s^radar——通过预热屏蔽期（R_slow 重建初期 s^radar 降权）保证该反馈环稳定。

## 6.2 Reject 路径

Candidate 最终与 Active 接近（如 walking 中突然减速后又恢复）→ 丢弃 Candidate，Active 继续。此后方可受理新 proposal。

## 6.3 Confirm 路径

物理、局部、语义变化均支持转换时：

1. **语义状态接管**：E_new^A = E^C（Candidate 已提前吸收新动作初始阶段信息，避免开头丢失）；
2. **物理原型接管**：R_new^A = R^C；
3. **旧 Active 定稿入库**：先执行精修重编码（用缓冲区整个事件的 F 做事件内非因果重编码，得 E_commit），E_commit 入库，缓冲区释放，该事件雷达通道关闭；
4. **时间戳回溯**：新事件开始时间标注为 **proposal 触发时刻**（而非 confirm 时刻），同时记录 confirm 时刻（两者之差即 Transition Latency）；
5. 生成 y_i（见 9.1 节）。

## 6.4 边界误差的取舍

Candidate 启动稍早会吸收少量 A 的尾部，稍晚则 Active 吸收少量 B 的头部。本任务关注 **Semantic Event Consistency** 而非 Frame-level Boundary Precision，接受 0.5~1s 量级的确认延迟，不引入复杂回溯搜索或多假设动态规划。

# 七、Idle / Presence 控制器

## 7.1 必要性

原始方案隐含假设"雷达流中始终存在一个正在进行的事件"。真实场景存在无人、静止、出入视场等片段，若不显式处理，空房间噪声会被 Active 持续吸收、污染事件语义，甚至触发虚假 Candidate。

## 7.2 最小可行规格

- **Presence 信号**：点云点数 + RD 能量，双阈值迟滞（进入阈值 > 退出阈值，防抖动）；
- **三态状态机**：Idle ⇄ Active；
- **Idle 期间规则**：Active State 冻结不更新（非清空）；不触发新 proposal；已有 Candidate 直接丢弃；
- **人走出视场**：当前 Active 以低置信度按"不完整事件" commit（metadata 标注 partial）；
- **从 Idle 恢复**：中断 < 2s 则恢复原 Active 继续，否则从 P_base 开新事件。

## 7.3 数据要求

数据集必须显式包含无人、静止站立、进出视场的片段（控制器的训练/标定与 Stage 3 负样本均依赖于此）。

# 八、模块⑦：Hierarchical Event Memory

## 8.1 记忆单元结构

$$
M_i = \{E_i,\ T_i,\ c_i,\ y_i\}
$$

- **E_i**：最终 Event Semantic Tokens（embedding 空间，K×d）——真正的记忆内容；
- **T_i = (t_start, t_end, t_confirm)**：t_start 为回溯的 proposal 触发时刻，t_confirm 用于延迟统计；
- **c_i**：事件置信度（partial 事件标注降低置信度）；
- **y_i**：commit 时刻由完整 LLM 生成的文本描述。

原则：**Token 是记忆内容；Text + Time + Confidence 是 metadata。** 只存文本会丢失未完全语言化的运动信息；只存 token 则丢失检索、解释与输出口的便利。

## 8.2 三级结构

```text
Level 0：Recent Event Memory（最近 6~10 个完整事件 tokens + metadata）
       ↓ 容量满后，最旧的 2~3 个连续事件
Memory Compressor（Summary Queries 过 cross-attention，如 12 tokens → 4 tokens）
       ↓
Level 1：Event Group Memory（事件组摘要 tokens）
       ↓ 继续变旧
Memory Compressor（再次压缩）
       ↓
Level 2：Long-term Memory（长期粗粒度行为摘要）
```

形成 single event → event group → long-term activity 的多粒度链条。

### 压缩触发条件

Level-0 满后，对最旧的 2~3 个**时间相邻**事件压缩成组；附加条件：**语义高度雷同的连续事件组不做压缩，直接按合并规则去重**（与 8.3 节呼应），避免压缩出无信息量的摘要。

## 8.3 同类事件合并规则（粒度控制）

问题："walking → 停顿 2s → walking"是一段还是两段？无规则时事件碎片化取决于噪声与阈值的偶然性。

**原则：合并发生在记忆写入层（事后簿记），不进入实时判决路径**（保持 Active/Candidate 状态机简单可分析）。

新事件写入 Level-0 时执行：

```text
IF  semantic_match(E_prev, E_new)            # 用 y_prev/y_new 文本标签匹配（E_new 新生未熟，不用 p_diff）
AND (E_new.t_start − E_prev.t_end) < τ_gap   # 间隔阈值，如 2~3s
AND 间隔期间无其他已确认事件（仅 idle/停顿）
THEN 合并：
    tokens：[E_prev; E_new] 过 Memory Compressor → 单一 tokens 组
    T：合并起止时间；c：取 min
    文本：LLM 读合并后 tokens 重新生成（禁止字符串拼接两句）
```

**τ_gap 是显式的事件粒度旋钮**：调大产出粗粒度事件，调小产出细粒度事件。论文中以 τ_gap 消融展示系统在不同粒度下的行为。

## 8.4 Memory Compressor 训练

冻结前端，训练目标：

$$
L_{memory} = L_{summary} + \lambda L_{retain}
$$

- L_summary：Summary Tokens 输入冻结 LLM，生成按时间顺序的多事件摘要文本（如 "The person stands up, walks forward, and then sits down."）；
- L_retain：语义保持损失，1 − cos(g(E_1,E_2,E_3), g_s(S))；
- 压缩时加入 Event Position Embedding 与 Token Position Embedding；
- 训练使 Summary 的目标文本只覆盖被压缩事件，模型自然学会摘要 tokens 与 Level-0 tokens 的时间分工（防止长程叙述重复）。

## 8.5 记忆读取（时间 + 语义双重规则）

- Level 0：不检索，全部直接使用；
- Level 1/2：检索分数 = 语义相似度 + 时间衰减项（或将 T_i 作为显式特征给排序器），Top-k 选取（如 Level 1 Top-2、Level 2 Top-1）。

纯语义余弦检索的缺陷：同类动作一天发生多次（"sit down"），语义几乎相同，无法区分"刚才那次"和"早上那次"——时间问题必须显式进入检索。

## 8.6 溢出与遗忘策略

Level 2 溢出时采用 FIFO 丢弃最旧单元（或作为后续工作再压缩一级）。策略需在方案中显式声明。

## 8.7 记忆与判决的隔离

Memory 主要用于历史理解、语言生成与长程推理；**不参与 Transition Decision**——防止历史语义惯性污染当前边界判断（架构上由 5.4 节的硬约束保证）。

# 九、LLM 推理路径

## 9.1 y_i 生成时机与叙述结构

- 事件 commit 时，完整 LLM 对已确认事件的 E_commit 生成描述 y_i（每事件一次，成本可忽略）；
- 用户查询/长程总结时，LLM 输入带显式叙述结构标记：

```text
[History Summary Tokens (Level 1/2)]   ← 远期，已压缩
[Recent Event Tokens (Level 0)]        ← 近期，未压缩
[Current Event Tokens]                 ← 进行中
```

- 流式主动叙述（如需要）：维护"已叙述到事件 #k"指针，每次只将新 commit 事件交给 LLM 生成增量叙述，避免重复叙述。

## 9.2 幻觉监控

软 token 喂冻结 LLM 的经典失败模式：LLM 忽略软 token、靠语言先验生成笼统文本（任何输入都输出 "the person is moving"）。监控方法：检查生成 token 对 event tokens 的注意力权重——接近均匀或接近零即说明在"瞎编"，需加强 L_align 或减小 LoRA 自由度。探针实验（12.3 节）可同时抓到此问题。

# 十、训练流程

## 10.1 五阶段管线

| 阶段 | 核心目标 | 训练模块 | 冻结策略 | 成本 |
| --- | --- | --- | --- | --- |
| Stage 1 | 可靠雷达人体运动表示 | Radar Encoder | — | 中 |
| Stage 2 | 雷达→语言事件语义对齐 | 层 1-4 LoRA + cross-attn + W_out | LLM 主干冻结 | 中 |
| Stage 3 | 连续事件转换判决 | 全部轻量 head + 事件状态小学习率 | Radar Encoder 基本冻结 | 低 |
| Stage 4 | 长期事件压缩与检索 | Memory Compressor | 前端全部冻结 | 低 |
| Stage 5（可选） | 整体联合微调 | Event State、Transition、Compressor | Encoder 冻结/极低 LR；LLM 冻结或 LoRA | 中 |

**论文呈现时可合并叙述为三阶段**（表示+对齐 / 流式判决 / 记忆压缩），细节放附录。

## 10.2 各阶段要点

### Stage 1：Radar Representation Pre-training

同步 3D 骨架辅助监督；推理时移除骨架。不引入 LLM、Memory、Candidate。

### Stage 2：Semantic Event Learning（go/no-go 决策点）

用切好的单动作训练：Radar → Event State → 冻结完整 LLM → Motion Description。

$$
L_{stage2} = L_{text} + \lambda L_{align},\quad L_{align} = 1-\cos(\text{Pool}(E), \text{TextEncoder}(Y))
$$

**本阶段是整条管线的裁决点**：验证"Event Tokens 能否承载雷达语义并被 LLM 读懂"。

- 达标（描述质量 + 探针准确率可接受）→ 继续；
- 不达标 → 按补救阶梯升级（层数 4→8 / 增大 K / 独立 Q-Former 式编码器），在投入 Stage 3/4 前以最小成本暴露问题；
- 本阶段完成**层数消融（2/4/8）× 描述质量 × 探针准确率**对照表；
- 用多种问法做指令增广，迫使 E_t 成为任务无关的观察性表示；消融"流式路径去 instruction（纯观察式）vs 保留"。

### Stage 3：Streaming Transition Learning

用连续动作序列（A→B→C）训练：

$$
L_{stage3} = \lambda_1 L_{local} + \lambda_2 L_{radar} + \lambda_3 L_{semantic} + \lambda_4 L_{transition}
$$

分别监督：边界附近局部变化 / 整体运动状态转换 / Active-Candidate 同异判定 / 最终 Confirm-Reject。Semantic head 训练对采用 5.4 节的 2×2 成熟度增广构造。本阶段完成 Local/Radar 检测器的冗余消融。

### Stage 4：Hierarchical Memory Learning

前端全冻结，仅训 Memory Compressor：L_stage4 = L_summary + λL_retain。多事件摘要文本由标注管线合成（11.3 节）。

### Stage 5（可选）：联合微调

完整连续长序列端到端联调；Encoder 冻结或极低 LR；不做全参数端到端训练。

# 十一、数据集建设（自建）

## 11.1 采集要求

1. **自然过渡**：动作间过渡（减速、重心转移）必须自然表演，禁止"演完 A 停一下再演 B"——过渡段是三类证据信号最需要学习的部分；
2. **容差边界标注**：边界标注为区间（如"转换发生在 8.0~8.5s"）而非精确帧，与 Semantic Event Consistency 立场及 Transition Latency 评估自洽；
3. **显式收录无人/静止/出入视场片段**（Idle 控制器与 Stage 3 负样本依赖）；
4. **同步录制 RGB 或 3D 骨架**：Stage 1 辅助监督与文本标注的载体。

## 11.2 泛化划分（数据集设计第一天就要定）

毫米波 HAR 领域最严重的问题是跨人、跨环境泛化虚高。必须规划：

- **跨被试划分**：leave-one-subject-out；
- **跨环境/雷达位姿划分**：至少两个房间或两个雷达角度；
- 两组划分结果作为论文主表（非附录）。

## 11.3 文本标注管线

```text
同步 RGB 视频 → 单事件 caption（视频理解模型初标 + 人工校对）
             → LLM 由连续单事件 caption 合成多事件摘要
             → 人工抽检
```

同时供给 Stage 2（单事件文本）与 Stage 4（多事件摘要文本）。

# 十二、评估体系

## 12.1 四层指标

| 层面 | 指标 |
| --- | --- |
| Event Detection | Boundary F1、**Over-segmentation Rate**（重点）、欠分割率 |
| Semantic Event | same/different accuracy、事件语义纯度 |
| Language | BLEU、ROUGE、CIDEr + **结构化叙事指标**（12.2） |
| Streaming | **Transition Latency**、输出延迟、长流稳定性、Memory 压缩效果、**延迟预算表**（各模块每 chunk FLOPs/ms、LLM 触发频率） |

另需量化并报告**最小可检测事件时长**（稳定性机制带来的短事件盲区规格）。

## 12.2 结构化叙事指标（自定义，作为任务评价贡献）

BLEU 类指标只衡量措辞 n-gram 重合，无法发现事件顺序错乱（"站起来后摔倒" vs "摔倒后站起来"措辞几乎相同）。因此定义两步评价：

**第一步**：用 LLM/规则将生成文本解析回结构化事件序列 [(动作, 顺序, 时间)]；

**第二步**：在序列上计算——

| 指标 | 计算 | 抓什么错 |
| --- | --- | --- |
| Event Order Accuracy | 与 GT 序列的 Kendall tau / LCS | 顺序错乱 |
| Event Coverage / Hallucination | GT 事件被提及比例；提及事件中真实发生比例 | 漏报 / 编造 |
| Temporal Localization Error | 提及事件的 T_i 与 GT 边界偏差 | 时间错误 |

训练侧：第一阶段仅以正确结构的训练目标 + 语言建模损失做隐式监督（当前决策）；可微增强（乱序对比损失、逐事件探针损失、时间回归头）与 RL 奖励微调列为后续可选项。

## 12.3 探针实验（支撑核心宣称的必需实验）

1. **语义探针**：仅用记忆库中的 E_i（不给雷达原始输入），线性分类器恢复动作类别的准确率；
2. **检索探针**：给定文本查询，从记忆库检索对应事件的命中率。

两组实验证明 "Event Semantic Tokens 承载了语言对齐的雷达语义"，否则该宣称不成立。

## 12.4 Baseline 构造（无现成基线，需自建）

- 滑窗 + 离线动作识别 + 逐窗 caption 的流水线（下界）；
- 视频流式理解方法（边界触发 + Video-LLM 式）迁移到雷达的跨界对比；
- τ_gap、K、层数、检测器配置、记忆层级数、合并规则的完整消融。

# 十三、创新点与论文定位

## 13.1 核心 Claim（一句话版本）

**一个统一表示（Event Semantic Tokens）同时承担四个角色：流式理解的状态、边界判决的基底、分层记忆的单元、LLM 推理的输入。** 现有工作中这四个角色分别由不同表示承担（检测器 logits、分割边界、KV cache、文本 caption），本方案以单一表示打通。

## 13.2 三个创新点

1. **Prompt-as-episodic-memory**：交叉注意力学到的语言对齐 token 直接作为情景记忆单元，存于 LLM 原生 embedding 空间，无需额外投影即可被 LLM 检索、推理、复述；
2. **面向雷达流的在线语义完备性判决**：Active/Candidate 双假设语义跟踪 + same/different 开放判决，把动作分割从信号层面提升到语义层面；
3. **多粒度分层事件记忆**：事件 token 按时序层级压缩合并（单事件 → 事件组 → 长期行为），Compressor 以 LLM 摘要损失端到端训练。

## 13.3 理论框架：事件分割理论（EST）的计算实现

认知科学 EST 认为：人脑维护受保护的当前事件模型，预测误差瞬增时释放旧模型、构建新模型，事件边界是该更新过程的副产品。本方案与之逐项同构：

| EST 概念 | 本方案模块 |
| --- | --- |
| Event model（受保护、持续预测） | Active Semantic Event State（门控更新防污染） |
| Prediction error 瞬增 | Local Change + Radar Transition |
| 释放旧模型、构建新模型 | Candidate 从干净 base 启动 |
| 边界是更新的副产品 | Transition Confirm |

注意划界：EST 的计算化实现已有先例（门控循环网络、自监督事件分割等），本文创新在于**事件模型首次以语言对齐的可学习 token 形式存在，使事件表示可直接被 LLM 推理、复述与分层压缩存储**。EST 对应关系写入 Introduction 以增强故事性。

## 13.4 相关工作区分（尽职调查结论）

截至本方案撰写时的检索结论：**在线、流式、带分层事件记忆的雷达-语言理解目前为空白**。最接近的工作均为离线或缺少关键组件：

- 雷达+LLM 离线理解（片段级 caption/QA，无流式、无分割、无记忆）；
- 雷达-语言驾驶场景模型（离线、非人体行为）；
- 传统连续雷达分割（CNN 两段式，无 LLM、无语言输出、无记忆）；
- 流式视频 LLM（视觉模态，帧级 KV 压缩记忆，非事件级语义 token）；
- HEM（query 驱动的事件记忆，无 LLM、无语言对齐）。

论文措辞采用 "To the best of our knowledge, this is the first..."，全部引用并逐一区分；**投稿前必须重新检索一次**（该交叉领域正在快速升温）。

## 13.5 隐私卖点（Introduction 素材）

毫米波不采集可识别图像；本方案更进一步——原始雷达特征在 commit 后即焚，长期保存的只有抽象语义 token 与文本。从感知到存储全链路无原始可识别信息，对养老监护、居家看护等落地场景是决定性优势。

# 十四、已知局限

1. **短事件盲区**：稳定性机制要求 Candidate 持续若干 chunk，持续过短（< 最小可检测时长）的快速动作会被吞掉。作为系统明确规格报告，不回避；
2. **单人假设**：当前限定单人室内；多人场景下 Active/Candidate 单事件假设不成立；
3. **重叠/复合动作**：单 Active 假设无法表达"边走边喝水"类并发事件，列为 future work；
4. **最多一个 Candidate**：快速连续动作（A→B→C 三连）召回受限，实验中如实报告；
5. **长事件漂移**：虽经 tanh 门控残差缓解，超长事件（分钟级）上的状态保真度需实测。
