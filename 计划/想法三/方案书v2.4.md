# 毫米波连续动作实时语义理解与分层事件记忆系统方案书
**版本：v2.4 正式修订版**

> 本版本基于 v2.3 主体方案进行收敛式修订，不新增主干网络，将 v2.4 核心决策替换融合至对应章节，保留连续事件形成、Streaming Event Former、Fork-and-Shadow、Hierarchical Memory 等核心设计，重点强化 Event Token 语义稳定性、物理可解释性与双视图训练收敛性。

---

## 版本修订核心变更
1.  **新增 Semantic-Evidence 双投影约束**：Event Token 内部统一表示，分别输出语义投影与证据投影，同时承载语言语义与雷达物理可解释性，从根源抑制语义漂移与生成幻觉。
2.  **Streaming/Commit 一致性改为蒸馏范式**：采用「Commit Teacher → Streaming Student」单向训练，先训练完整上下文的 Commit 模式作为金标准，再蒸馏约束流式模式，解决双向强制对齐的训练目标冲突问题。
3.  **明确事件转换的双假设验证定位**：将 Fork-and-Shadow 从工程级错误恢复机制，升级为语义层面的「新事件/旧事件」双假设并行验证机制，提升算法贡献度。
4.  **补充多维度探针实验体系**：围绕语义稳定性、证据可解释性、双视图一致性、长时记忆保留力设计专项探针，完善论证闭环。
5.  **收敛式约束**：所有修订均不新增主干网络，全部以轻量 Head、训练策略、规则机制的形式实现，保持「三个核心可学习模块 + 若干轻量 head/规则」的总体架构不变。

## 一、研究目标
本方案面向**单人室内连续毫米波人体感知任务**，目标是实现从连续毫米波信号到时间顺序事件描述的实时理解。系统不采用固定时间窗口切割动作，而是学习连续演化的事件状态，使事件边界由语义变化自然形成。

核心目标包括：
1.  连续毫米波流中的事件形成与边界检测；
2.  语言对齐的事件状态表示，兼具语义准确性与物理可解释性；
3.  长时序历史的分层记忆管理与语义检索；
4.  基于雷达物理证据的可靠自然语言生成。

---

## 二、核心问题
系统围绕三个核心问题展开设计：
1.  **什么时候可能发生动作变化？**
    通过物理层的 Radar Transition Detector 发现潜在变化区域，输出高召回的变化提议。
2.  **当前语义是否已经稳定转变为新事件？**
    通过 Candidate Event 与 Active Event 之间的语义验证完成确认，保证事件分割的语义纯度。
3.  **已经完成的事件如何长期保存？**
    通过 Hierarchical Event Memory 保存不同时间尺度的信息，在控制上下文成本的同时支撑 LLM 长时序推理。

> **核心思想**：Event Token 不是普通的雷达特征向量，而是持续更新的语言对齐事件状态。它同时承担：当前事件表示、语义变化判断基准、长期记忆单元、LLM 推理输入接口四种角色。

## 三、总体架构
### 3.1 系统视角
整体数据流与状态流转如下：
```text
Continuous mmWave
       │
       ↓
① Streaming Radar Encoder
       │
       ├────────→ ② Local Change Detector ───────┐
       ├────────→ ③ Radar Transition Detector ───┤
       └────────→ Idle / Presence Controller     │
                                                  ↓
                                      Physical Proposal
                                                  │
                                    Fork at t_p
                      ┌───────────────────┼───────────────────┐
                      ↓                   ↓                   ↓
              Frozen Active Ref.    Candidate State      Shadow Active
              （固定语义参照）      （P_base启动）       （Reject恢复用）
                      │                   │                   │
                      └──── Semantic Difference / Stability ──┘
                                          │
                                          ↓
                                  ④ Semantic Verify
                                  ┌────────┴────────┐
                                Reject           Confirm
                                  │                │
                         Shadow → Active     Candidate → Active
                                                   │
                                      Old Event Sealed at t_p
                                                   │
                                                   ↓
                                      Low-Priority Finalization Queue
                                      ┌────────────┴────────────┐
                                      ↓                         ↓
                               ⑤ Commit Refiner          Full LLM Caption
                                      │                         │
                                      └────────────┬────────────┘
                                                   ↓
                                  ⑥ Hierarchical Event Memory
                                                   │
                                                   ↓
                                        Full LLM Reasoning
```

### 3.2 学习视角：三个核心可学习模块
论文方法部分仅围绕三个核心网络展开，其余均为轻量检测头、投影头、验证头与规则状态机：
1.  **Radar Encoder**：流式雷达特征提取与时序建模
2.  **Streaming Semantic Event Former**：事件状态更新与跨模态语义对齐
3.  **Hierarchical Memory Compressor**：分层事件记忆压缩与检索

坚持三个不新增模型原则：
- Candidate 与 Active **完全共享** Event Former 参数；
- Commit Refiner **复用** Event Former 架构与参数；
- Memory Retrieval **复用** Semantic Projection 空间。

## 四、Event Token 设计：语义-证据双重可解释性
为避免 Event Token 退化为普通短时特征，v2.4 引入**语义-证据联合约束**。Event Token 内部保持统一向量表示，但通过两个独立投影头实现不同维度的可解释性：

### 4.1 Semantic Projection（语义投影）
- 功能：将 Event Token 映射到 128 维共享语义空间，用于学习事件语言语义，对接 LLM 语言空间。
- 用途：语义差异计算、记忆检索、文本对齐。

### 4.2 Evidence Projection（证据投影）
- 功能：将 Event Token 映射到雷达可观测属性空间，学习物理证据特征，包括人体运动状态、身体部位活动、速度变化、空间位置变化等。
- 用途：通过辅助监督保证 Event Token 始终绑定雷达真实物理测量，避免语义漂移与生成幻觉。

### 4.3 训练目标
总损失函数：
$$
L = L_{caption} + \lambda_1 L_{semantic\_align} + \lambda_2 L_{evidence}
$$
- $L_{caption}$：文本生成损失，驱动 Event Token 具备语言生成能力；
- $L_{semantic\_align}$：语义对齐损失，将 Event Token 语义空间与文本语义空间对齐；
- $L_{evidence}$：证据约束损失，利用同步骨架信息生成物理属性标签，监督 Event Token 保留雷达可观测证据。

## 五、时间粒度与在线更新规格
- 雷达默认帧率：$20 \ \text{fps}$
- 系统更新周期：每收到 4 个新帧更新一次，$\Delta t = 0.2\ \text{s}$，即 $5\ \text{Hz}$ 语义更新频率
- 时序建模：Causal TCN 保持 stateful hidden state，每次仅计算新增 4 帧，不重复计算历史

采用 5 Hz 的设计依据：
- Candidate 预热 1–2 次更新仅需 0.2–0.4 s；
- Verify 连续 2 次成立约需 0.4 s；
- 总体语义确认延迟可控制在 0.5–1.2 s；
- 相比 2.5 Hz 更适配短过渡动作场景。

> 2.5 Hz 作为效率消融项，不作为默认配置。

## 六、模块①：Streaming Radar Encoder
### 6.1 总体结构
```text
                         4 个新雷达帧
                              │
               ┌──────────────┴──────────────┐
               ↓                             ↓
           RD Frames                    Point Frames
               │                             │
         2D CNN Encoder                PointNet Encoder
               │                             │
       frame-level r_i ∈ R²⁵⁶        frame-level p_i ∈ R²⁵⁶
               │                             │
         Stateful Causal TCN          Stateful Causal TCN
         dilation 1/2/4/8             dilation 1/2/4/8
               │                             │
       2 learnable queries            2 learnable queries
       pool newest states             pool newest states
               │                             │
          2 RD tokens                    2 PC tokens
               └──────────────┬──────────────┘
                              │
                     modality embedding
                              │
                    Transformer × 2
                              │
                  F_t ∈ R^{4×256}
```

### 6.2 RD 分支
每帧 RD 图输入尺寸：$2\times64\times64$
- 编码器结构：4 个 ConvBlock 逐级下采样，每个 ConvBlock = `Conv 3×3 → BatchNorm → GELU → Downsample`
- 输出：单帧 256 维特征 $r_i$
- 时序建模：4 个 Block 的因果 TCN，膨胀系数 1/2/4/8，深度可分离卷积 + 残差连接
- 特征读出：2 个可学习 pooling query 从 TCN 状态中读出 2 个 RD tokens

### 6.3 Point Cloud 分支
每帧点云输入：$P_i\in \mathbb R^{N_i\times 6}$，每点特征为 $$(x,y,z,v,I,SNR)$$
- 编码器：共享 MLP（6→64→128→256）+ 最大池化，输出单帧 256 维特征 $p_i$
- 时序建模：与 RD 分支同结构的 Stateful Causal TCN
- 特征读出：2 个可学习 pooling query 得到 2 个 Point tokens

> 默认采用 PointNet 作为主干，Point Transformer Lite 仅作为升级/消融项保留。

### 6.4 特征融合
最终融合特征：
$$
F_t=[R_t^1,R_t^2,P_t^1,P_t^2]\in\mathbb R^{4\times256}
$$
加入模态嵌入与更新时间嵌入后，经过 2 层小型 Transformer 完成融合。
> **关键约束**：$F_t$ 始终停留在雷达特征空间，不预投影到 LLM 维度。

## 七、Stage 1：逐帧 Pose-Guided 雷达预训练
Stage 1 的目标不是训练姿态模型，而是让 Radar Encoder 学习人体结构与运动动力学先验。

- 监督信号：在两分支 TCN 的帧级隐藏状态融合后，对每个雷达帧预测 3D 骨架
  $$\hat S_i=\text{PoseHead}(h_i^{frame})$$
  PoseHead 结构：256 → 512 → J×3

- 损失函数：
  $$
  L_{pose}=L_{MPJPE}+\lambda_vL_{velocity}
  $$
  其中速度损失：
  $$
  L_{velocity}
  =
  \frac1{T-1}\sum_i
  \|
  (\hat S_i-\hat S_{i-1})-(S_i-S_{i-1})
  \|_1
  $$
  显式约束帧间人体运动的物理连续性。

- 推理阶段：Stage 1 完成后整体删除 Pose Head，仅使用毫米波特征。

## 八、变化检测前端
### 8.1 Local Change Detector
对短时突变高敏感、高召回、允许误报，仅负责提出「可能变化」。
1.  先对 $F_t$ 做 LayerNorm：$\bar F_t=LN(F_t)$
2.  逐 token 构造差异特征：
    $$
    D_t=\left[\bar F_t-\bar F_{t-1},\ |\bar F_t-\bar F_{t-1}|,\ \bar F_t\odot\bar F_{t-1}\right]\in\mathbb R^{4\times768}
    $$
3.  经过 MLP + 注意力池化 + 输出层，得到局部变化得分 $s_t^{local}$。

### 8.2 Radar Transition Detector
基于运动原型空间的长时变化检测，衡量整体运动模式的偏移。
1.  建立独立 Motion Prototype Space：
    $$
    r_t=\text{MLP}_{256\rightarrow128}(\text{Pool}(F_t))
    $$
    并做 L2 归一化。
2.  维护事件内慢统计量 $R_{slow}$（Welford 运行均值/方差）与快统计量 $R_{fast}$：
    $$
    R_{fast,t}
    =
    \alpha R_{fast,t-1}
    +
    (1-\alpha)r_t
    $$
    其中 $\alpha = \exp(-\Delta t/\tau_{fast})$，默认 $\tau_{fast}=2\ \text{s}$，5 Hz 下 $\alpha\approx0.905$。
3.  计算归一化偏移量 $\delta_t$，构造统计特征向量，经 MLP 输出雷达变化得分 $s_t^{radar}$。

### 8.3 Proposal 生成机制
仅由物理证据产生提议，采用噪声-OR 融合：
$$
p_t^{proposal}
=
1-(1-s_t^{local})(1-s_t^{radar})
$$
若 $p_t^{proposal}>\tau_p$ 且连续 1–2 次更新，则触发 Candidate，记录时刻 $t_p$ 并执行 Fork。
> 从 Candidate 建立开始，Local/Radar 不再参与 Confirm 判决。

## 九、Fork-and-Shadow 状态管理
Fork 的核心目标：
1.  语义参照冻结：Candidate 的语义差异始终与 proposal 时刻的旧 Active 比较，避免参照系漂移；
2.  无延迟恢复：Reject 时无需串行回放历史帧，实现 O(1) 状态切换，消除延迟尖峰。

Proposal 后同时维护三个逻辑状态，**三者完全共享同一套 Event Former 参数**：
```text
                      proposal at t_p
                            │
              ┌─────────────┼─────────────┐
              ↓             ↓             ↓
       Frozen Active     Candidate      Shadow Active
        Reference          State         Recovery State
              │             │             │
       不再更新，只作     P_base启动      从旧Active快照继续
       semantic reference  吸收新雷达     吸收相同F_t
```

### 9.1 Proposal 时刻执行操作
1.  冻结语义参照：$E_A^{ref}=E_A,\quad z_A^{ref}=g(E_A^{ref})$
2.  保存旧事件物理统计快照
3.  旧 Active 的事件 buffer 在 $t_p$ 处封口，时间范围固定为 $[t_0,t_p]$
4.  Candidate 初始化：$E_C=P_{base}$，独立吸收后续雷达特征
5.  Shadow Active 初始化：从旧 Active 快照继续更新，同步维护物理统计量
6.  Frozen Active Reference 不再运行 Event Former，仅保存参照状态

> Candidate 与 Shadow 复用同一个 Radar Encoder 输出 $F_t$，不重复计算雷达特征。

### 9.2 Candidate 跟踪期间
- 语义差异始终比较：$z_A^{ref}\ \text{vs.}\ z_C$
- 稳定性仅计算 Candidate 自身
- Local/Radar 不再参与 Confirm 判决
- Shadow 不参与语义验证，仅负责 Reject 时的无损恢复

### 9.3 Reject 状态恢复
若 Candidate 被判定为与旧 Active 语义相同：
- 直接将 Active 状态切换为 Shadow 的当前状态
- 接管 Shadow 的事件状态、物理统计量
- 丢弃 Candidate，无需串行回放历史帧

Reject 是近似 O(1) 的状态切换，彻底消除传统方案的回放延迟尖峰。

### 9.4 Confirm 事件提交
若 Candidate 被语义验证确认：
- 新 Active 状态 = Candidate 状态
- 新事件起始时间 = $t_p$
- 旧事件结束时间 = $t_p$
- 丢弃 Shadow 状态
- 旧事件封口，提交至异步语义定稿队列
- Streaming Path 立即继续处理新 Active，不等待定稿完成

> 系统区分两种提交：
> 1. **Online Control Commit**：Confirm 后立即完成状态切换，属于实时控制路径；
> 2. **Semantic Finalization**：Commit Refiner、记忆更新、文本生成属于异步低优先级路径。

## 十、模块②：Streaming Semantic Event Former
### 10.1 Event State 初始化
- 默认 Event Token 数量：$$K=8$$
- 向量维度：与 LLM 原生维度一致（如 Qwen2.5-7B 为 3584 维）
- 事件状态矩阵：$E_t\in\mathbb R^{8\times3584}$

### 10.2 固定 Event Prompt
Streaming Path 不接受任意用户问题，全程使用固定语义提示：
> Maintain a compact semantic representation of the current human motion event from radar observations.

该 Prompt 全程固定，前 4 层 K/V 可缓存，保证 Event Token 为 query-independent 的客观事件记忆。用户问题仅进入完整 LLM 推理路径。

### 10.3 Event Former 内部结构
#### 10.3.1 注意力掩码
- Instruction/Event Prompt 保持标准因果掩码
- 8 个 Event Token 之间为双向全连接（并列记忆槽，非自然语言序列）

#### 10.3.2 LLM 层 1–4 主干
- 主干权重冻结
- LoRA 插入 q/v，rank=16
- 每层结构：
  ```text
  Native Self-Attention
          ↓
  Bottleneck Radar Cross-Attention
          ↓
  Native FFN
  ```

#### 10.3.3 512 维瓶颈式交叉注意力
不在完整 LLM 维度执行跨模态注意力，通过瓶颈降参：
- 定义映射矩阵：
  $$
  W_Q:\mathbb R^{3584}\rightarrow\mathbb R^{512}, \quad W_K,W_V:\mathbb R^{256}\rightarrow\mathbb R^{512}
  $$
- 在 512 维执行多头注意力：$C_t=\text{MHA}(Q_{512},K_{512},V_{512})$
- 输出映射回原维度：$W_O:\mathbb R^{512}\rightarrow\mathbb R^{3584}$
- 层内更新：$H^l=H^l+\tanh(\alpha_l)W_OC_t$，$\alpha_l$ 初始化为 0

每层新增参数约 4M，4 层总计约 16M，远低于全维度交叉注意力的百 M 级参数。

### 10.4 跨 update Event State 更新机制
1.  第 4 层输出经 $W_{out}$ 映射得到预测状态 $\hat E_t$，$W_{out}$ 采用 identity-like 初始化
2.  构造状态增量：$\Delta E_t=\hat E_t-E_{t-1}$
3.  每个 Event Token 生成标量更新门：
    $$
    \lambda_{t,k}=\text{MLP}([\text{LN}(E_{t-1,k});\text{LN}(\Delta E_{t,k});maturity_t])\in\mathbb R
    $$
4.  最终更新：
    $$
    E_{t,k}=E_{t-1,k}+\tanh(\lambda_{t,k})\Delta E_{t,k}
    $$
    每个 token 独立决定更新幅度，而非逐维度门控。

> 训练与调试必须监控 $\|E_t\|$ 随时间曲线，防止状态范数漂移。

## 十一、语义投影与证据投影
### 11.1 Event Semantic Projection
输入 Event Tokens $E\in\mathbb R^{K\times3584}$：
1.  用可学习语义查询 $q_s$ 做注意力池化：$h_E=\text{Attention}(q_s,E,E)$
2.  经过投影层：3584 → 256 → 128 + L2 归一化
3.  输出 128 维语义向量 $z_E\in\mathbb R^{128}$

Active 与 Candidate 共享同一个投影头：$z_A=g(E_A),\quad z_C=g(E_C)$

### 11.2 Event Evidence Projection
输入 Event Tokens，通过独立的轻量投影头，映射到物理属性空间，输出：
- 人体姿态/高度变化估计
- 上下肢活动状态
- 平均速度与速度变化量
- 空间位置偏移量

用于计算证据约束损失，保证 Event Token 绑定雷达物理测量。

### 11.3 Text Semantic Projection
文本不再使用输入嵌入均值池化，而是：
```text
Text Tokens
    ↓
Frozen LLM Layers 1–4
    ↓
Hidden States
    ↓
同一个 Semantic Query Pooling + Projection g(·)
    ↓
z_text ∈ R¹²⁸
```
实现事件语义键、文本查询、记忆检索、语义对齐全部闭合在同一个 $z$ 空间。

## 十二、语义差异与验证机制
### 12.1 Semantic Difference
构造差异特征向量：
$$
D_t=[z_A,z_C,|z_A-z_C|,z_A\odot z_C,1-\cos(z_A,z_C),maturity]
$$
输入维度约 514 维，经过 3 层 MLP（514→256→64→1）+ GELU + Dropout，输出语义差异概率 $p_t^{diff}$。

训练采用 2×2 成熟度配对策略：
| Pair 组合 | 标签 |
| --- | --- |
| mature(A) vs nascent(A) | same |
| mature(A) vs mature(A') | same |
| mature(A) vs nascent(B) | different |
| mature(A) vs mature(B) | different |

目标是学习 **category-agnostic semantic difference**，而非特定动作分类。

### 12.2 Candidate 稳定性（无参数版本）
基于最近三个 Candidate 语义向量计算：
- 相邻余弦相似度：$c_1=\cos(z_t,z_{t-1}),\quad c_2=\cos(z_t,z_{t-2})$
- 语义方差：$v_t=\frac13\sum_{j=t-2}^{t}\|z_j-\bar z\|_2^2$
- 稳定性得分：
  $$
  s_t^{stable}=\frac{c_1+c_2}{2}\cdot\exp(-v_t/\tau_s)
  $$
  裁剪至 $$[0,1]$$ 区间。

仅衡量 Candidate 是否已形成稳定语义状态，无额外可学习参数。

### 12.3 Semantic Verify
Verify 输入：$u_t=[p_t^{diff},s_t^{stable},maturity_t]$

采用单调 Logistic Head：
$$
p_t^{verify}=\sigma(w_dp_t^{diff}+w_ss_t^{stable}+w_mmaturity_t+b)
$$
其中权重通过 softplus 约束为非负，保证语义差异越大、越稳定、越成熟，确认概率越高。

- **Confirm**：$p_t^{verify}>\tau_c$ 且连续 2 次更新
- **Reject**：Candidate 运行超过 1.5~2 s 且 $p_t^{diff}$ 持续低于阈值

## 十三、Commit Refiner 与双视图一致性
Commit Refiner 复用 Streaming Semantic Event Former 参数，不属于 200 ms 实时关键路径。

### 13.1 两种模式
- **Streaming 模式**：增量式，每次只读当前更新的 $F_t$，因果注意力
- **Commit 模式**：全量式，输入完整事件雷达 buffer，加入相对时间编码，允许非因果全局注意力

### 13.2 Commit Teacher → Streaming Student 蒸馏范式
不再强制双向对齐，改为单向蒸馏训练：
1.  **第一阶段**：单独训练 Commit 模式，利用完整事件上下文学习最优语义表示，作为固定教师模型；
2.  **第二阶段**：训练 Streaming 模式，除原有任务损失外，加入语义蒸馏损失，约束 Streaming 的语义投影向 Commit 的输出看齐。

> 仅约束 Semantic Projection 空间，不限制底层物理特征，尊重两种模式的信息边界。

总一致性损失：
$$
L_{cons}=1-\cos(z_{stream},z_{commit})
$$

### 13.3 临时记忆与异步定稿
1.  Confirm 时先写入 provisional memory unit，使新近历史立即可被查询；
2.  异步 Commit Refiner 完成后，原子替换为 refined 记忆单元并更新检索键；
3.  文本描述可更晚补写，文本生成不是实时状态切换的前置条件。

## 十四、Idle / Presence 控制器
采用非深度学习规则控制器，基于点数量、RD 能量、动态能量、跟踪置信度计算 presence score，使用双阈值迟滞机制：
- Idle → Active：score > $\tau_{enter}$
- Active → Idle：score < $\tau_{exit}$ 且持续 N 次更新

**关键约束**：静止站立 ≠ Idle，不能仅通过多普勒信号判断。

Idle 状态下：
- Active 暂停更新
- 不触发新的 Proposal
- 在途 Candidate 直接丢弃
- 短中断恢复窗口默认 2 s，超过则从 $P_{base}$ 开启新事件

## 十五、实时执行与异步调度
### 15.1 每 0.2s 关键路径算力预算
正常 Active 状态单次 update 执行路径：
```text
4 个新雷达帧
→ Radar Encoder
→ Local / Radar Proposal Heads
→ LLM Layer 1–4 + 512-d Bottleneck Cross-Attention
→ Event State Update
→ Semantic Projection
```
不执行 LLM 深层、记忆压缩、全量文本生成等任务。

以 Qwen2.5-7B、$K=8$ 为例的量级估算：
- 前 4 层 LLM：约 15 GFLOPs / update
- 4 层瓶颈交叉注意力：约 0.2~0.3 GFLOPs / update
- 雷达编码器 + 时序 + 融合 + 检测头：约 1~2 GFLOPs / update

正常路径总量约 16~18 GFLOPs/update，5 Hz 对应 80~90 GFLOPs/s。

### 15.2 Candidate 状态计算预算
Candidate 活跃期间：
- Radar Encoder 仍仅运行 1 次
- Frozen Active Reference 不运行网络
- Candidate + Shadow 各运行 1 次 Event Former

主要开销为 Event Former 的 2 倍前向计算，避免了传统方案 Reject 后串行回放的突发延迟。

**工程目标预算**：
| 路径 | P95 目标预算 |
| --- | ---: |
| Radar Encoder | < 10 ms |
| 单次 Event Former（LLM 1–4 + cross-attn） | < 50 ms |
| 检测头 / 投影 / 状态逻辑 | < 10 ms |
| 正常 Active 总路径 | **< 70 ms** |
| Candidate + Shadow 双路径 | **< 140 ms** |
| Streaming 周期 | **200 ms** |

若延迟超标，优先按顺序降级：
1.  交叉注意力瓶颈 512→256
2.  LLM 流式层数 4→2
3.  Event Token 数量 $K=8$→4
4.  更新频率 5 Hz→2.5 Hz

### 15.3 双队列调度机制
#### High-Priority Streaming Queue
每 200 ms 处理一次，包含雷达编码、状态更新、提议验证、存在检测，任何异步任务不得阻塞此队列。

#### Low-Priority Finalization / Reasoning Queue
处理 Commit Refiner、记忆压缩、文本生成、用户长历史查询。Confirm 时仅提交任务，不同步等待结果。

### 15.4 模型驻留约束
完整 LLM 权重必须在实时会话期间常驻目标推理设备，禁止每次 update 在 CPU/GPU 间搬运模型。Streaming Path 仅调用前 4 层，Commit 与查询时才调用深层。

### 15.5 异步队列过载保护
若 Finalization Queue 积压：
1.  优先延后 caption 生成
2.  Commit Refiner 优先级高于文本生成
3.  临时 Event Token 仍可用于近期查询
4.  队列长度、定稿延迟、文本滞后纳入系统监控指标

## 十六、模块③：Hierarchical Event Memory
### 16.1 Memory Unit 结构
$$
M_i=\{E_i,T_i,c_i,k_i,y_i,status_i\}
$$
- $E_i$：8×3584 Event Tokens
- $T_i$：start/end/confirm 时间戳
- $c_i$：事件置信度
- $k_i$：128 维语义检索键
- $y_i$：Commit 文本描述（可异步补写）
- $status_i$：`provisional / refined / captioned` 异步定稿状态标记

### 16.2 三级分层记忆架构
- **Level 0**：最近 8 个完整事件，保留完整 Event Tokens
- **Level 1**：中期事件摘要，通过 Compressor 压缩为 4 个 Summary Tokens
- **Level 2**：长期事件摘要，进一步压缩为高层语义表示

Level 0→1 与 Level 1→2 共享同一套 Compressor 参数。

### 16.3 Query Compressor 压缩器
内部维度固定为 1024：
1.  输入 Event Tokens 先从 3584 维投影到 1024 维
2.  加入事件位置嵌入、Token 位置嵌入、时间嵌入、层级嵌入
3.  2 层 Transformer Decoder 做摘要压缩
4.  输出 4 个 Summary Tokens，再投影回 3584 维

### 16.4 Memory Merge 事件合并
主判据为语义键相似度：
$$
\cos(k_{prev},k_{new})>\tau_{merge}
$$
同时满足时间间隔小于阈值、期间无其他确认事件，则合并。
文本仅用于可读性检查，不作为合并主控制信号。

合并后 Token 经 Compressor 融合，时间范围合并，置信度取 min，保留次数元数据。

### 16.5 Memory Retrieval 记忆检索
- Level 0：全部读取，不检索
- Level 1 / Level 2：每个摘要单元通过共享 Semantic Projection Head 生成检索键

查询文本经过相同的投影流程得到查询向量 $z_q$，排序得分：
$$
s_i=\cos(z_q,k_i)+\beta e^{-\Delta t_i/\tau}+\gamma c_i
$$
默认 Level 1 返回 Top-2，Level 2 返回 Top-1。

## 十七、完整 LLM 推理路径
Reasoning Path 输入按层级拼接：
```text
[Retrieved Level-2 Summary Tokens]
→ [Retrieved Level-1 Summary Tokens]
→ [All Level-0 Event Tokens]
→ [Current Event Tokens, optional]
→ [User Query]
```

完整 LLM 仅读取 Event/Memory Tokens，不读取原始雷达与低层雷达特征；临时状态事件可先使用 provisional 版本，异步定稿后自动替换。

## 十八、训练流程
### 18.1 Stage 1：Radar Motion Pretraining
- 训练对象：Radar Encoder + 临时 Pose Head
- 损失：$L_{pose}=L_{MPJPE}+\lambda_vL_{velocity}$
- 完成后删除 Pose Head

### 18.2 Stage 2：Radar→Language 语义事件对齐
- 训练对象：LLM 1–4 LoRA、瓶颈交叉注意力、$W_{out}$、标量状态门、语义投影头、证据投影头
- 冻结：LLM 主干参数
- 总损失：
  $$
  L_{stage2}=L_{text}+\lambda_aL_{align}+\lambda_eL_{evidence}+\lambda_cL_{cons}
  $$
- 同时训练 Streaming 视图与 Commit 视图，采用 Commit Teacher 蒸馏范式

### 18.3 Stage 3：Continuous Transition Learning
- 训练对象：Local Change Head、Radar Transition Head、Semantic Difference Head、Verify Logistic Head
- 损失：
  $$
  L_{stage3}=\lambda_1L_{local}+\lambda_2L_{radar}+\lambda_3L_{semantic}+\lambda_4L_{verify}
  $$
- 边界标签采用容差区间 → chunk-level 高斯软标签

### 18.4 Stage 4：Hierarchical Memory Compression
- 前端全部冻结
- 训练对象：1024 维 Query Compressor 与输入输出投影层
- 损失：
  $$
  L_{memory}=L_{summary}+\lambda_rL_{retain}
  $$
  其中保留损失：$L_{retain}=1-\cos(z_{summary},z_{source-group})$

### 18.5 Stage 5：可选 Joint Fine-tuning
仅在前四阶段稳定后进行，若无明显收益则不执行。

## 二十二、论文核心贡献与Claim
### 22.1 核心一句话Claim
> A continuously updated, language-aligned event representation simultaneously serves as the streaming semantic state, the basis for semantic transition verification, the long-term memory unit, and the direct input to LLM reasoning.

中文：
> 同一组语言对齐的 Event Semantic Tokens 同时承担流式事件状态、语义转换判决基底、长期记忆单元和 LLM 推理输入四种角色。

### 22.2 三个主要贡献
1.  **Continuous Semantic Event Formation**：Physical Proposal + Semantic Verify + Fork-and-Shadow 机制，使事件边界成为持续语义理解的副产品，同时消除 Reject 回放的实时延迟尖峰。
2.  **Semantic-Evidence Dual Constrained Event Tokens**：事件表示同时具备语言语义对齐与雷达物理可解释性，在低信息传感场景下有效抑制语义漂移与生成幻觉。
3.  **Hierarchical Token Memory for Long Streams**：共享压缩器对变旧事件逐级压缩，在保持语义的同时控制上下文成本，实现感知-事件-记忆-推理的统一接口。

### 22.3 措辞边界
- 默认使用 **category-agnostic semantic transition** 表述，仅在 unseen-action 实验验证后再使用 open-set / open-vocabulary 表述。
- 隐私表述：Event commit 后丢弃原始雷达与低层雷达特征，减少低层感知数据长期留存风险；不宣称 Event Token 天然不可用于身份恢复。
- Attention 仅作为诊断手段，不直接作为幻觉检测依据。
